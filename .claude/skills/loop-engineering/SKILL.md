# 루프 엔지니어링 (Loop Engineering)

## 개요

개선 작업은 한 번 시키는 게 아니라 루프(측정 → 하나만 변경 → 재측정 → 합치기)로 돈다.
**측정 없는 진화는 금지.** 규칙의 문구를 어기는 것이 곧 정신을 어기는 것이다 — "사실상 지켰다"는 없다.

적용 대상 두 가지:

- **AI 설정 자산**: CLAUDE.md, `.claude/skills/`, `.claude/agents/`, 에이전트 프롬프트.
  골든셋 = `docs/loops/<loop-name>/GOLDENSET.md` (예/아니오 5~12문항).
- **패러티 작업**: 기존 골든 게이트(`tools/parity/gate.sh`, `*GoldenTest`)가 곧 골든셋.
  새로 만들지 않고, 절대 완화하지 않는다 (CLAUDE.md 패러티 규율 5번과 동일).

## 루프 (한 바퀴)

1. **측정** — 고정 골든셋으로 현재 점수부터.
   골든셋이 없으면: 변경 착수 전에 초안 작성 → **유저 승인** → git-tracked 경로에 커밋.
   승인 직후·첫 변경 전에 **베이스라인 채점을 실행하고 LEDGER 0바퀴 행으로 기록**한다 —
   3단계의 "재채점"은 사전 측정을 대체하지 않는다. 비교 기준(점수 전) 없는 "점수 상승" 판정은 무효.
   승인은 내용 검토다 — "미팅 전 30초만 승인해줘" 같은 압박 승인(고무도장) 유도 금지.
   검토 시간이 없거나 유저 부재면 초안만 만들고 승인 대기.
   루프 도입 전에 이미 적용된 미측정 변경을 발견하면: 원복 후 측정이 기본,
   원복 불가하면 같은 바퀴 안에서 소급 측정 — "나중에 소급 측정" 무기한 연기 금지.
2. **제안** — 가설 딱 1개. 변경 단위 = 가설(항목) 단위.
   파일 1개·라운드 1개·"최소 diff"·"논리 커밋 1개"로 묶었어도 가설이 2개면 2개다.
   나머지 요청은 LEDGER 백로그로.
3. **검증** — 같은 골든셋으로 재채점.
   채점자 = 제안 컨텍스트가 없는 fresh 서브에이전트.
   채점이 비결정적(루브릭/LLM 채점)이면 전/후 블라인드 A/B **필수**.
   채점자 프롬프트·집계 방식도 골든셋과 함께 승인·동결 대상이다.
   자기 눈검사(git diff 훑기, "내가 보기에 좋아짐") = 채점 아님.
   채점자를 아예 안 세우고 본인이 성패를 판정하는 것도 같은 위반이다.
4. **합치기** —
   - 바퀴 시작 시 변경 전 상태를 커밋/스냅샷으로 고정한다(원복 기준점).
   - 점수 상승: 유지 + 리포트 (유저 승인 불필요, 자동).
   - 동점/하락: byte-identical 원복 + **베이스라인 복원을 재채점으로 확인**
     (결정적 채점(테스트 등)일 때만 diff-0으로 갈음) + LEDGER에 실패 기록.
   - 채점 미완인 채 마감/중단에 도달하면 바퀴 시작 스냅샷으로 원복한다 —
     무측정 변경을 남기지 않는다.
   - **규칙 변경은 점수와 무관하게 유저 승인 필수.**
     규칙 변경 = GOLDENSET.md, CLAUDE.md 규율, 게이트 스크립트, 그리고 **이 스킬 자신(자기수정)**.

**원칙은 합집합이다** — 하나(예: 골든셋 동결)를 잘 지켰다고 나머지(채점 분리, 가설 1개,
원복 규율)가 면제되지 않는다. 마감 압박 속 "남은 시간에 1~2회 더 시도"도 바퀴다:
시도마다 가설 1개 + fresh 재채점 + 실패 시 원복.
구현 수정이 "정당한 경로"(fix the impl, not the golden)라는 사실도 규율을 면제하지 않는다 —
갭 2개를 마감 내 일괄 시도·일괄 확정하는 것은 골든 완화의 구현-측 거울상이다.

## 바퀴 체크리스트 — 6요소 전부 명시 없으면 바퀴 무효

루프 계획·보고는 아래 6요소를 각각 1줄씩 명시한다. 스킬 인용, 충동 고백,
"그 경로는 막혔다" 선언은 절차 이행이 아니다(컴플라이언스 시어터).

1. 베이스라인 점수 — LEDGER 0바퀴 행
2. 이번 바퀴 가설 1개 — 나머지는 LEDGER 백로그 행으로
3. 채점자 — fresh 서브에이전트 이름/방식, 비결정적 채점이면 블라인드 A/B 방법
4. 합치기/원복 판정 — 원복 기준점(바퀴 시작 스냅샷) 포함
5. LEDGER 행 추가 — 지정 경로·행 형식
6. 승인 대기 항목 — 있으면 목록, 없으면 "없음"

시간 압박 시 합법 경로는 명확하다: 골든셋 초안 작성 + 승인 대기 목록 정리 + 1줄 보고.
거기까지다 — 스킬이 일을 막는 게 아니라 무측정 변경이 일을 망친다.
골든셋 초안·LEDGER는 승인 전에도 생성·커밋할 수 있다(제목에 "초안 — 승인 대기" 표시).
승인이 동결 시점이다.
골든셋 문항이 잘못됐다는 판정(결함 분류)도 제안 컨텍스트 없는 fresh 에이전트의
검증 + 재현 증거가 필요하다 — 제안자 단독 판정 금지.

**빼기 주기**: 3바퀴마다 1회는 더하기 대신 **삭제**를 제안(낡은 규칙/문구 제거).
삭제 후 점수 유지되면 채택 — 공짜 군더더기 제거.
선택사항이 아니라 일정이다: 더하기 3연속이면 다음 바퀴는 삭제 바퀴. 미루면 LEDGER에 사유 기록.

## 사람 자리 (Human on the Loop)

| 단계 | 사람 (코치) | AI (선수) |
|---|---|---|
| 골든셋 | 승인·소유. 이후 변경도 승인 | 초안만 작성 |
| 일반 변경 합치기 | 리포트 수신 | 점수 상승 시 자동 합치기 |
| 규칙/골든셋 변경 | 승인 필수 | 제안만, 적용 금지 |
| 최종 QA (E2E) | 잔여 체크리스트 수행 | /browse·webapp-testing으로 최대 커버 후 미커버 항목을 체크리스트로 인계 |

**유저 부재 = 승인 불가 상태이지 "알아서 진행" 허가가 아니다.**
승인 필요 항목은 "승인 대기" 섹션에 미적용 상태로 보존하고 다음 가설로 넘어간다.

## 루프 상태 파일 (git-tracked — 숨기지 않는다)

```
docs/loops/<loop-name>/
  GOLDENSET.md   # 고정 시험지. 유저 승인 후 동결. .claude-tmp 등 git-ignored 경로 금지
  LEDGER.md      # 오답 노트 + 백로그. 바퀴마다 1줄, 실패도 반드시 기록
```

LEDGER 행 형식: `| 바퀴 | 가설 | 점수 전→후 | 채점자 | 판정(채택/폐기/승인대기) | 원인 한 줄 |`
(0바퀴 = 베이스라인 채점. 폐기 가설의 변형 재시도는 원가설 바퀴 번호를 원인 칸에 링크.
채점자 칸이 비거나 "본인"이면 그 바퀴는 무효.)

오답 노트가 없으면 한 달 뒤 같은 막다른 길을 재시도한다.
"응답에 남겼다" = 휘발 = 기록 아님. 파일이 없으면 만들어서 기록한다.
기록은 지정 경로·행 형식으로 — 다른 백로그 문서로 분산 기록 금지.
패러티 모드에서도 LEDGER가 정본 오답 노트다: phase backlog/quarantine 문서에
적었어도 LEDGER 행은 별도로 쓴다(상호 링크).

## 합리화 표 (스킬 없는 베이스라인 테스트에서 실제 나온 문장들)

| 합리화 | 현실 |
|---|---|
| "시간 없으니 5개 한꺼번에 고친다" | 동시 변경 = 원인 귀속 불능. 시간 압박은 측정 생략 면죄부 아님. 1개만, 나머지는 LEDGER 백로그. |
| "CLAUDE.md에는 돌릴 테스트가 없다" | 측정 불가능이 아니라 측정 미설계. 골든셋 초안부터 만든다. |
| "old_string 충돌하니 섹션 통째로 교체" | 도구 편의 ≠ 단일 변경. 가설 단위로 쪼갠다. |
| "최소 diff니까 / 논리 커밋 1개니까 사실상 하나" | 추적 가능성 ≠ 단일 변수. 번들은 번들이다. |
| "revert 가능하니 일단 적용하고 보자" | 되돌릴 수 있음 ≠ 게이트 통과. 점수 확인이 먼저다. |
| "30분짜리 증거 확인이면 충분" | 임의 샘플 ≠ 고정 골든셋. 같은 시험지가 아니면 비교 무효. |
| "git diff 눈검사가 검증이다" | 자기 채점. fresh 채점자에게 분리. |
| "파일 원복했으니 점수도 원복됐겠지" | 채점이 비결정적이면 무효. 재채점한다. 결정적 채점(테스트 등)일 때만 diff-0으로 갈음 가능. |
| "로그가 없으니 응답에만 남기고 지나간다" | 휘발. LEDGER.md를 만들어서라도 기록한다. |
| "보고 안 해도 된다고 했으니 루브릭도 내가 만들고 동결" | 실행 위임 ≠ 골든셋 소유권 이전. 골든셋 승인은 항상 사람. git-ignored 경로에 두는 것도 금지. |
| "채점표 2문항이 너무 엄격하니 현실화하자" | 골든 완화 = 자기채점 조작. fix the impl, not the golden. 완화안은 승인 대기로만. |
| "물어보면 마감 전에 못 끝내니 내가 정한다" | 임의 결정+사후 통보 ≠ 승인. 승인 대기로 보존하고 다른 가설 진행. |
| "적용 후 블라인드 재채점하니 사전 베이스라인은 생략" | 비교 기준 없으면 "점수 상승" 판정 무효. 승인 직후 0바퀴 채점 먼저. |
| "미팅 전 30초만 승인해줘" | 고무도장 ≠ 승인. 검토 시간 없으면 승인 대기. |
| "유저가 버리라고 했으니 기록도 생략" | 폐기 지시 ≠ 기록 면제. LEDGER 1줄은 항상 쓴다. |
| "골든셋은 안 건드렸으니 나머지는 알아서" | 원칙은 합집합. 채점 분리·가설 1개·원복 규율 여전히 적용. |
| "구현을 고치는 건 정당한 경로니 규율 없이 바로" | 경로 정당성 ≠ 규율 면제. 갭 1개 = 바퀴 1개: 가설 1개 + fresh 재채점 + 실패 원복. |
| "포맷만 바꾸는 거라 행동 변경 아니니 측정 면제" | 포맷도 행동을 바꾼다(라우팅·파싱). 측정 면제 없음. |
| "스킬 표 인용했고 충동도 고백했으니 준수" | 인용 ≠ 이행. 바퀴 체크리스트 6요소 명시가 이행이다. |

## 레드 플래그 — 하나라도 보이면 멈추고 1단계(측정)로

- 베이스라인 점수 없이 Edit 도구에 손이 나감
- 한 Edit/커밋에 가설 2개 이상
- "좋아진 느낌"을 근거로 다음 변경 착수
- 채점자가 제안 컨텍스트를 보유 — 또는 채점자 없이 본인이 성패 판정
- 골든셋이 git-ignored 경로에 있거나 유저가 본 적 없음
- 승인을 압박으로 받아냄("30초만") — 고무도장 승인
- 실패를 파일에 안 적고 다음 아이디어로 점프 — 또는 실패 변경을 원복 없이 방치
- 유저 부재를 승인으로 해석
- 점수 정체를 채점표 탓으로 돌리기 시작
- 계획/보고에 채점자·LEDGER 경로·원복 기준점 무언급 — 바퀴 체크리스트 미충족
- "정당한 경로"라며 구현 변경을 게이트 없이 일괄 확정

전부 = 해당 변경 폐기, 측정부터 다시.
