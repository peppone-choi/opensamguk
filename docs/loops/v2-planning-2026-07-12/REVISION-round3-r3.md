## 설계가 실제로 바뀐 지점 (문구 정정 아닌 것)

1. **R2 산출물 확대** — `prev_income` KV 유지 + v2 DB `event` 12행 전량 재시드 + `EngineEventConfig.kt:79-81` 등록 1줄이 모두 R2 안으로. 작업량 증가, 티켓 수 불변.
2. **R0 → P0 이동** — 오픈 경로에서 빠지고 관계망 오픈 후 분해의 선행 티켓이 됐다. 오픈 후 관계망 분해가 **6 → 7티켓**.
3. **§9.4 논거 구조 재배치** — 소급 가능성이 "결정적 근거"에서 부수 근거로 내려가고, **순서 논거**(emergent 3/4가 `OPENSAM-56`·`61`에 붙는다)가 단독 결정 근거가 됐다.
4. **오픈 전 관측 3종 신설** — 국고 월간 추이 / 병종연구 최초 완료 시점 / `maxResourceActionAmount` 분포. 완화안(국고 완전 귀속 앞당김, 비용 = v1 커맨드 포크 2건)의 발동 조건까지 명시.
5. **§11 신설** — 잔여 UNKNOWN 8건을 표로 모으고 각각 (확인 방법)/(확인 실패 시 설계가 어떻게 되는가)를 붙였다.

## 최종 오픈 경로 = **20 · 단일값, 조건부 항목 없음**

기준 14(`README.md:55-65`) + R1 원장기반 + R2 수입·봉록 + R3 공백지화 + R4 병사보충 + R5 수송 + R6 원장열람 = **20**.
증감 내역: 병합 −1(R2+R3) / 열람 신설 +1 / 관계망 −2 / **조건부 R0 −1**(→ 오픈 후 P0).

**권고: 20으로 확정, 관계망 전체(P0~P6, 7티켓)는 오픈 후.**

근거는 **순서**다 — 관계를 낳는 emergent 소스 4종 중 3종이 오픈 경로 **마지막 두 티켓**(`OPENSAM-56`·`61`)에 붙으므로, 관계망을 오픈 경로에 넣는다는 건 오픈 직전에 7티켓을 더 얹는다는 뜻이다. 1순위가 "빨리 열기"인 이상 방어할 수 없다. **이 판정은 소급이 전혀 불가능해도 성립한다** — 개정 2차의 소급 논거에 의존하지 않는다. 파이프라인 seam(P0)을 소비자(P5·P6)와 같은 웨이브에 두는 것은 CLAUDE.md foundation-first(생산자→소비자) 규율과도 일치한다.

채택 시 ADR-LITE-019 개정 대상은 **오픈 경로 표 1개**(14 → 20)뿐이고 `OPENSAM-35` 본문은 건드리지 않는다.
