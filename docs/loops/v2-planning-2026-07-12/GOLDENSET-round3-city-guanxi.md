## 기준선 (측정 완료 2026-07-25)

**묘섭 (`docs/wiki/raw/myosam-help/`, 37페이지 전수)**

- 운영자가 묘섭을 **"City-oriented(도시지향) 삼모전"**으로 자기규정하고, 체섭 대비 최대 차이를 **"금·병량이 국가→도시로 이전, 도시마다 도시병사 상주"**로 명시한다 (`peq.md : Q2/Q5`, `myostart.md : 5.묘섭의 특징`).
- 도시 축 장치: 도시 단위 금·병량 / 도시병사 상주(0 → 공백지화) / 태수·군사 담당도시 효과 / 임원진 6종 체류 효과 / 도시 특색 9종 / 규모 5단계 게이트(건국=중·소, 아이템매매=특) / 지역 7종 병종 게이트 / 성벽 수치가 건설 가능 개수 결정 / 세율 5~35%·지급률 100~500% / 인접 제약(출병·교역).
- **인물 관계 축의 결정적 사실: 묘섭에도 장수↔장수 관계망이 없다.** 친밀도·의형제·사제·결의·혼인·개인 이벤트·일기토 전부 없음. 상성은 개인↔**국가**일 뿐 개인↔개인이 아니며, 장수→군주 충성도 스탯도 없다.
- 대신 묘섭의 사람-의존은 **인사권 · 배치효과 · 감시 · 자원분배** 4축으로 만들어진다: 관직 임명(인사부) / 임원진 주둔 효과 / 호기·파견·발령·집합 / 감찰부 / 포상·증여·헌납 / 부대장 이동 시 부대원 동반 / 지휘부 위계별 발령·추방 권한.

**opensamguk 현재**

- 도시: `City`(`logic/.../domain/LogicEntities.kt:67-92`)에 스탯·소속·level·region·trade·conflict는 있으나 **특산·지형·시설·건설물 0**. 인접은 정적 `CityConst.path` 위 BFS(`CalcCityDistance.kt`). 금·쌀은 **국가/장수 소유이며 도시 소유가 아니다.**
- 관직: `officer_level` 2~4(태수/군사/종사)가 이미 있고 `ProcessIncome`의 `officerCntByCity`가 **담당도시 관직자 수를 수입에 반영**한다(`ProcessIncome.kt:59-60,72-74`) — 묘섭 태수 효과와 동형 구조가 이미 존재한다.
- 인맥: 장수↔장수 관계 구조 **0 hits**(친밀/호감/은원/사제/의형제/연고/relationship/affinity망/intimacy/rivalry/sworn/평판 등 전수 검색). 유일한 관계형 신호는 `general.meta`의 affinity 스칼라(1~150)이며 **군주 상성과의 원형 거리**로만 소비된다(`CheRandomImgwan.kt:180-183`, `RulerSuccession.kt:16`).
- v2 스펙: 장수 관계망(사제·라이벌·원한·구명 → 명령 신뢰·협상 태도)은 product-spec `:388` + LEDGER 확장 콘텐츠에 있으나 **오픈 경로 밖**. 도시 4모델 분리는 G0이며 ADR-LITE-019로 **오픈 후**로 이동.

## 가설

> **묘섭의 "도시 중심"은 지도도 3D도 거점 수도 아니라 자원 소유권의 위치다.** 금·병량을 국가에서 도시로 내리고 도시병사를 상주시키면, "누가 어느 도시에 있는가"가 곧 도시 수치를 바꾸는 결정이 된다. 그리고 **그것이 묘섭의 인맥이기도 하다** — 묘섭에는 관계 수치가 아예 없고, 사람 사이의 의존은 인사권·배치효과·감시·자원분배로만 만들어진다.
>
> 따라서 도시 중심과 인맥 중심은 **두 시스템이 아니라 하나**이며, G0(2,000 거점·3D·도시 4모델) 없이 v2 오픈 경로 안에서 구현 가능하다.

## 시험지

1. "도시 중심"을 3D·거점 수가 아니라 **자원 소유 주체(국가→도시)**로 정의하고, 운영자 자기규정(`peq.md : Q2/Q5`, `myostart.md : 5`)을 근거로 명시한다.
2. 도시 소유 자원(금·병량)과 도시병사 상주를 v2 스키마·판정으로 정의하고, **도시병사 0 → 공백지화**를 포함한 상태 전이를 deterministic하게 규정한다.
3. 묘섭식 인맥을 **관계 수치 없이** 인사권·배치효과·감시·자원분배 4축으로 표현하고, 관직자 배치 효과를 담당도시 한정으로 규정하되 opensamguk에 **이미 있는** `officer_level` 2~4 + `ProcessIncome.officerCntByCity` 위에 얹는 경로를 밝힌다. 평행한 새 축을 신설하지 않는다.
4. 장수↔장수 관계망은 **묘섭에도 devsam PHP에도 없는 opensamguk 독자 추가**임을 명시한다(골든 오라클 없음). 관계는 명령 신뢰·협상 태도뿐 아니라 **능력치 보정에도 작용한다**(2026-07-25 사용자 결정 — product-spec `:388`의 "능력치 버프가 아니라"는 이 라운드에서 뒤집힌다). 게임 중 발생하는 emergent 관계와 **시나리오 시작 시점에 이미 존재하는 역사적 사전 관계**(유비·관우·장비 도원결의 등)를 구분해 정의하고, 각각의 생성·변화·소멸 조건을 deterministic하게 규정한다.
   - 능력치 보정은 **v2 world profile에서만 등록되는 `ActionPipeline` stat source**로 들어가야 한다. v1 오리지널의 source 목록·`getStatValue` 결과·RNG draw·한글 로그·PHP 골든은 **한 바이트도 바뀌지 않음**을 증명해야 한다(ADR-LITE-018로 v1은 동결).
   - 사전 관계 데이터의 출처(RTK 원본 / 사서 / 자체 편성)를 밝히고, 정치·매력 5스탯과 동일하게 **원본은 git-ignore·미커밋, 빌더만 버전 관리**한다.
5. 임원진 체류 효과 6종(사도·대사농·사공·표기장군·거기장군·위장군)의 도입 여부를 결정하고, 도입분은 각 효과의 판정 지점과 중첩 규칙을 명시한다.
6. 도시 특색 9종 · 규모 게이트(건국=중·소, 아이템매매=특) · 지역병종 7지역을 각각 채택/보류로 판정하고, 채택분은 **발현 조건**(예: 도시기술 900)과 수량을 명시한다.
7. 위 전부가 **v1 패러티를 건드리지 않음**을 증명한다 — v1 `City`·`ProcessIncome`·RNG draw·한글 로그·PHP 골든 불변, v2 전용 스키마·경로.
8. 각 신규 요소가 `결정 → deterministic 판정 → 다음 상태 변화 → replay/log`를 만족함을 항목별로 보인다 (LEDGER 판정 규칙 4).
9. **오픈 경로(ADR-LITE-019 14티켓)에 들어갈 최소 부분집합**과 오픈 후로 미룰 부분을 나누고, 오픈 경로 증분을 **티켓 수량**으로 밝힌다.
10. G0와의 관계를 명시한다 — 이 제안이 G0를 **대체하지 않고 선행**하며, GOLDENSET 4·8번 적용 유예(ADR-LITE-019)와 충돌하지 않음을 보인다.
