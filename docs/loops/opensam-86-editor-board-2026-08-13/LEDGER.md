## Environment notes

- The worktree intentionally has no `legacy/` checkout; PHP/hwe evidence was read from the primary repository's ignored legacy directory without modifying it.
- The git-ignored external frontend skill bodies are absent from this isolated worktree. Repository routing, the checked-in components, and the available `webapp-testing` workflow remain the operative sources.
- An early direct `pnpm test` / `pnpm vitest` lookup reported `vitest: command not found` despite the installed local executable. `scripts/agent/verify-changes.sh --run` later invoked the full `pnpm test` suite normally; direct `./node_modules/.bin/vitest` remains the reproducible focused runner with concrete pass/fail exits.
- Fablize repeatedly emitted generic tool-failure warnings during discovery, edits, and documentation reads despite direct commands succeeding. This is isolated as a tooling baseline, not test evidence; the wrapper will not be retried and all gate results will be recorded from direct command output.
- The first jsdom interaction attempt for the TipTap empty-body case hit ProseMirror geometry gaps (`elementFromPoint` and `getClientRects`). It was replaced with a pure page-level guard regression, while the actual input/delete interaction was verified in Playwright against the running Next page. A separate Node-environment Vitest attempt could not load this repository's jsdom-only `MouseEvent` setup; the SSR assertion instead stubs `document` inside the standard runner and passes.
- The full `web/game` Vitest run is baseline-red: `__tests__/live-noop-closures.test.tsx` misses `pollCommandResultResponse` in its select-pool mock. The exact focused test also fails in a clean detached `fe7127fd` worktree (7 passed, 1 failed), so it is outside this board diff.
- The external TypeScript no-excuse checker requires TypeScript 7 `typescript/unstable/*` subpaths, while this project has TypeScript 5.7.2. Its direct invocation exits 2 before analyzing files; the project `tsc --noEmit` gate remains the applicable type check. One typoed external-skill location probe and one GNU-only `find -printf` probe were no-op command errors, corrected with explicit existing paths and macOS-safe commands; neither changed project state.
