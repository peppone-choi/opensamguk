# 카드·공사 콘텐츠 계약

정본: [장수·휘하 캠페인 재설계](../superpowers/specs/2026-09-17-general-and-retinue-campaign-redesign.md) §6.1, §8.1–8.2, §9.

## 카드 공통 머리

`CardHeader`는 인물·부대·계책·보물에 공통인 ID, 이름, 종류, 유일/공용, 개별 출처, 명망 코스트, 비용 색, 태그를 담는다. 출처 배지는 인용마다 **책과 권을 함께** 표시하거나 `게임 용어`로 표시한다. 정사·연의를 월드 프로필로 갈라 활성화하지 않는다. 명망 코스트는 음수가 아니며, 종류별 실제 부과 규칙은 §6.6을 따른다. 현재 손패의 견벽·간파 두 종류는 이 머리에 연결된다. 기존 손패 인스턴스와 소모 순서는 그대로 둔다.

## 縣 상태와 공사

새 縣 상태 축은 호구·전답·시장·민심·방비·특산 여섯 가지다. 기존 입력 원장의 인구→호구, 농업→전답, 상업→시장, 치안/신뢰→민심, 수비/성벽→방비로 투영한다. 별도 `InfrastructureNetwork`는 두지 않는다. 도로와 역참은 공사 종류다. 현재 `hwiha-domestic-v1.json`의 수치와 효과는 잠정값이며, 이 계약은 그 수치를 확정하지 않는다.

## 특산·산지

특산은 縣의 비축 재고가 아닌 특성이다. 철·목재·말 산지에는 시대·근거 책/권·결속 범위를 보존한다. `resource-sites-v1.json`의 미결·불명 산지는 추정 縣에 강제로 붙이지 않는다. 郡 단위 산지를 생산 縣에 배정한 행은 `COMMANDERY_SEAT`라는 게임 설계 배정임을 남긴다. 소금은 특산이며 다섯 가지 비축 자원에 추가하지 않는다.

## 참조 검사

`CardContentValidator`는 콘텐츠·근거·주장·입력 소비·출력 생성의 ID 중복, 이중 소비, 부분 생성, dangling, claim→evidence를 검사한다. `tools/content/validate_card_content.py`는 현재 내정·산지·생산 원장을 읽어 같은 참조 원칙과 출처 책/권 일치를 검사한다. 어느 쪽도 전체 개수를 상수로 고정하지 않는다. 실행: `python3 tools/content/validate_card_content.py`, `python3 -m unittest discover -s tools/content/tests -v`.

이 계약은 새 카드 콘텐츠 표면이다. `content/v2`의 read-only 샌드박스 로더와 과거 프로필 계약을 신규 카드의 생명주기나 월드 분리로 재사용하지 않는다.
