# 3층 입력·권한·황실 통합 설계 초안

> 상태: 검토 초안. 이미 확정된 제품 불변식과 구현 기반, 아직 결정할 규칙을 구분한다. 후보 입력 ID·저장 필드·API는 등록되거나 제공되는 기능이 아니다. 이 문서가 입력 증거 단계나 공개 알파 관문을 승격하지 않는다.

## 정본과 현재 공백

[휘하 설계](../superpowers/specs/2026-09-17-general-and-retinue-campaign-redesign.md) §4·§11·§13.2·§15.1이 입력 여섯 종류와 3층 범위를 정한다. 07-13 설계의 개인턴·사령턴 명령 링, 정사/연의 월드 분리, 전 병종을 고정 개수로 구현하는 조건은 최신 제품 계약으로 사용하지 않는다. 기존 회귀 기준선은 유지한다.

| 범위 | 있는 설계·모델 | 런타임 통합에서 채울 것 |
|---|---|---|
| 추천·자칭·실권 | [추천·자칭·추인](office-nomination.md), `OfficeNomination`, `OfficeClaimHistoryCodec` | 추천자/심의자 권한, 접수·응답, 관찰자 읽기, 재임과 실효 관할 연결 |
| 황실·인장·조서 | [황통](imperial-succession.md), [조서](imperial-edict.md), [인장](imperial-regalia.md), [196 許](imperial-xu-196.md) | 실제 시드·궁정 인가·전달·응답·보관·제위 전이의 저장/권한/AI/replay |
| 세력 정체성 | [정체성 상세](../superpowers/specs/2026-07-13-v2-nation-identity-rework.md), `FactionIdentityCore`, `IdentityPresetSources` | 새 입력에 배선, 청중별 정통성·지역망 보존, 프리셋13종·중립/미성립의 현행 역할 |

모델이 있는 항목도 입력 카탈로그 등록·서버 실행·화면·AI·도움말·replay 증거가 없다면 완료가 아니다. `court.institution` 한 행으로 황실·추천·정체성·시설·편제 전체를 전달했다고 세지 않는다.

## 칭제 생산과 통일 소비의 최소 경계

확정된 통일 조건은 **천하의 모든 州와 郡을 같은 세력이 점유 AND 그 세력이 칭제한 상태**다. 戶口 문턱이나 유지 기간을 추가하지 않는다. 190 漢 郡國의 유효성·지도 핀·점유 판정은 통일 도메인이 맡는다.

황제, 국가 군주, 조정 보호 세력, 칭제한 세력은 서로 다른 역할이다. `ImperialHouse.holderGeneralId`나 `courtNationId`, 국가 등급·관직·인장 소유만으로 칭제를 추정하지 않는다. 제위 승계와 국가 주공 승계도 분리한다. 기존 `changeSovereign(FOUNDATION)`은 이미 있는 비활성 황통을 전이시키며 신규 황통을 생성하거나 같은 입력을 멱등으로 재처리하지 않는다.

### 내부 스냅숏 제안

황실 생산자는 통일 소비자에게 아래 **현재 유효 증거**만 준다. 궁정 상세 API나 공개 위치 배지를 통일 입력으로 재사용하지 않는다. 이 표의 이름은 인터페이스 제안이며 신규 DB 열이나 공개 API를 뜻하지 않는다.

| 값 | 뜻·검사 |
|---|---|
| `worldId` | 점유 스냅숏과 동일한 세계. 다른 세계의 칭제 증거는 거절 |
| `snapshotToken` | 생산자와 소비자가 같은 불변 세계 스냅숏을 사용했다는 토큰. 순 시각만으로 두 별도 조회가 같다고 추정하지 않음 |
| `status` | `VALID`, `NOT_SEEDED`, `STATE_UNAVAILABLE` 후보. 뒤 두 상태는 통일 false이며 판정 불가 사유를 보존 |
| `claims[]` | `VALID`일 때 현재 확인 가능한 칭제 증거 목록. 유효하나 칭제가 없으면 빈 목록 |
| 증거의 `factionId` | 칭제 입력 실행 때 명시적으로 결속한 세력 ID. 행위자의 현재 소속에서 과거의 칭제 세력을 복원하지 않음 |
| `lineCode`, `foundationTransitionId` | 실재 황통과 지속된 창설/활성화 전이를 가리키는 안정 ID. 누락·중복·끊어진 참조는 오류 |
| `holderGeneralId`, `effective` | 현재 황제와 해당 세력의 유효 칭제 여부. 황통 공위/종결·세력 멸망·소속/승계 변화 후 재평가 규칙은 아래 결정 묶음에서 확정 |

칭제 입력 결과와 황통·전이 이력·증거의 세력 결속은 같은 `ChangeRecorder` 변경과 JDBC flush 트랜잭션으로 지속한다. 재시도는 같은 requestId의 이전 결과를 돌려주고, 다른 payload로 같은 requestId를 재사용하면 거절한다. 조회는 새 황통이나 증거를 만들지 않는다. 시드된 역사 황통의 활성 상태만으로 런타임 칭제 입력이 있었다고 판단하지 않는다. 역사 시드가 어느 세력의 칭제 증거를 제공할지는 시나리오 계약에서 명시해야 한다.

통일 소비자는 같은 `worldId/snapshotToken`의 점유와 `VALID` 증거에서 **후보 세력과 factionId가 같고 effective=true**인 것을 AND로 결합한다. 자료 누락·손상·다른 세계/토큰은 false다. 점유 판정, 승자 결정, `isunited` 동결, 연감·시즌 종료와 중복 방지는 통일/시즌 생산자가 맡는다. 황실 생산자는 그 종료 기록을 다시 쓰지 않는다.

### 순환 선행 제거와 구현 순서

1. 이 최소 경계와 미결정 규칙을 검토한다. 황실 설계·순수 판정·codec 테스트를 시즌 하니스 완료와 독립적으로 진행한다.
2. 황실 생산자는 단일 선언/재시도/소속 변화/사망·공위의 증거를 구현한다. 통일 소비자는 명시적 칭제 fixture로 점유·false/true·종료 멱등성을 독립 검증한다.
3. 동일 세계 스냅숏의 생산·소비를 실제 엔진에서 연결한다. 황실 상세·인장·제도 구현 전체를 통일 경계의 선행조건으로 걸지 않는다. 필수 칭제 증거가 없는 런타임 통일은 차단한다.
4. 실제3190 무인 시즌과 사람 참가 시즌에서 선언→점유→종료·저장/복구·replay를 검증한다. 독립 fixture나 초록 CI를 실제 시즌 완료로 세지 않는다.
5. 황실/통일 화면을 데스크톱·모바일에서 검증하고 운영 승격 뒤 다시 확인해야 관문 DONE이다.

## 입력 후보 목록과 권한

아래 ID는 **등록 전 후보**다. 공유 카탈로그 차례와 관직 경계 합의 후 최종 ID/payload/failureReasons를 고정하고 `PLANNED`부터 등록한다. 종류별 실행 시점은 휘하 §4를 따른다. 조정 결정은 결정권자의 턴, 직접 행동은 본인 턴, 공사는 순 경계, 배치/방침은 해당 카드의 다음 턴부터다. 물리적 이송을 입력 접수 시 즉시 완료로 처리하지 않는다.

| 후보 입력·종류 | 예약/실행에서 함께 검사할 권한·조건 | 결과와 공개 경계 |
|---|---|---|
| `court.officeNominate` · 조정 결정 | 추천 관할·추천자 자격·공석/후보 현재 상태. 자격 상세는 결정 필요 | 추천 ID. 추천만으로 tenure/실효 권한 생성 금지 |
| `court.officeNominationReview` · 조정 결정 | 해당 궁정의 현재 인가 심의자, 제출된 동일 추천 revision | 원안/하위/대행/보류/기각/경쟁 후보. 타 궁정 심의 금지 |
| `court.officeNominationReply` · 조정 결정 | 제안받은 candidate 본인 동의, OFFERED 상태 | 수락/사양; 실제 임명은 2층 임명 계약을 다시 검사 |
| `court.officeClaim` · 조정 결정 | 본인/위임 범위와 관직·관할의 유효성. 자칭 자격 상세 결정 필요 | 법적 주장·이력; 실효 관할이나 제삼자 인정 자동 부여 금지 |
| `court.officeRecognize` · 조정 결정 | 인정 주체 권한, 중앙 추인이면 수락된 유효 조서 증거 | append-only 인정/추인. 기존 SELF_STYLED/tenure.origin 보존 |

| `court.edictRegister` / `court.edictSeal` · 조정 결정 | 상서 인가, 활성 황제·같은 조정·실제 인가 보관자·인장 진위/공간 | 등록/봉인 증거; 인장 소유만으로 권한 없음 |
| `assignment.edictMessenger` · 배치 | 실제 직속 카드, 봉인된 전달 의무·대상·지도 경로 | 실제 이동/전달; 밀지 사자에게 전문 공개 금지 |
| `court.edictReply` · 조정 결정 | 실제 수신 권한자, 전달 완료·동일 조서 revision | 수락/부분수락/지연/거부/공개비난. 효과는 한 번만 적용 |
| `court.settlementPolicy` · 조정 결정 | 실제 황제 안전·조정 城·경비·군량·상서·인장 행정 | 봉대/보정/협제 이력. 城 점령만으로 보호국 생성 금지 |
| `action.regaliaTransfer` · 직접 행동 | 현재 실제 보관자와 같은 공간·수신 동의/유효성 | 보관 이력. 소유·진위·관직/제위 권한은 별개; 소유 이전/탈취·위조 입력 상세는 후속 설계 |

| `court.identityAdopt` · 조정 결정 | 세력 결정권과 현재 정체성/지역망 revision, 다른 조직망에 대한 시야 | 청중별 정통성·통치형태·전통/정책 전이. 선언 하나로 모든 효과 지급 금지 |
| `court.institution` · 조정 결정(기존 PLANNED) | 채택 권한, 제도별 실제 선행 조건과 지역 대상 | 郡縣별 채택/확산 의무. 즉시 전국 연구 완료 아님 |
| `construction.identityFacility` · 공사 | 해당 縣 실제 공사 권한·정체성/제도 능력·창고/공간 | 학교/方/산채 등 분기 진척. 전환/훼손/승계는 조직망 보존 규칙과 연결 |
| `court.unitTraditionAdopt` · 조정 결정 | 해당 세력 결정권·모집원/지휘/의종·항중 결속·명망/실명 유일성 | 실제 부대 카드 능력. 명칭 선택만으로 부대/병력 생성 금지 |

정체성 지역망의 운영·탄압·수용·전환, 제위 선양·폐위·시해·찬탈, 인장 탈취/소유권·진위 주장은 이 목록에서 삭제한 범위가 아니다. 기존 설계의 각 전이를 직접 행동/조정 결정/계책에 매핑하는 상세 슬라이스가 필요하다. 효과·비용·인가 범위가 비어 있는 항목을 가짜 handler나 VERIFIED 행으로 만들지 않는다.

인증 principal에서 현재 월드의 행위자를 해석하고 payload의 generalId를 신원으로 신뢰하지 않는다. 실제 실행 직전에 권한·존속·관할·위치·revision·동의를 다시 검사한다. 사람과 NPC가 동일 판정을 쓰며 NPC는 자기 시야로 알려진 값만 공급한다. 조건 불충족은 비용 없이 무효·사유 기록이다. 후보 failureReasons는 입력 정본에 등록할 때 기존 공통 코드와 도메인 회복 조언을 대조한다.

## 관직 공유·읽기 API 경계

2층은 `OfficeDefinition/OfficeTenure/OperationalAssignment/OfficeCapabilityResolver.actualJurisdiction`과 임명·실효 지배를 소유한다. 3층은 `OfficeNomination/OfficeClaim`과 인정·추인 이력을 소유한다. 3층이 tenure를 독자 생성하지 않는다. 임명/추인 결과로 생성할 credential·tenure ID, 원자적 recorder 저장 주체와 오류 롤백을 먼저 합의한다.

읽기 API는 현재 계약 초안인 `GET /api/court/office-claims?generalId=`, `GET /api/imperial/court?generalId=`와 정체성/제도/시설/편제 투영을 각각 갖는다. generalId는 **관찰 대상**이지 인증 신원이 아니다. 조서 투영은 `ImperialEdictProjection`을 사용해 밀지 존재·전문·대상·사자 정보를 관찰자별로 제한한다. 임의 빈 목록을 미시드/손상 대신 정상 완료로 반환하지 않는다. 정확 DTO와 상태/HTTP는 각 API 슬라이스가 소비 화면과 합의한다.

[공개 황제 소재지](imperial-presence-api.md)는 위치·공개 이름만 제공하는 독립 읽기 계약이다. 내부 칭제 유효성이나 비공개 궁정 상태를 추가로 노출하지 않는다. 부 이름 `buName/offices`는 관직/소속 읽기의 별도 계약이며 황제 이름과 결합하지 않는다.

## 결정 묶음

아래는 아직 채택되지 않은 제품 선택이다. 확정된 통일 AND 조건이나 공개 알파 전 세 층 완성 여부는 재질문하지 않는다.

| 선택 | 검토 권장안·확인할 영향 |
|---|---|

| 신규 황통·관계 | 기존 황통 자동 종료 없이 새 황통/경쟁 관계를 명시. 이름/코드·초기 정통성·조정 城·관계/명망 효과·NPC 선호 조건은 미확정 |
| 증거 유효성 | 사망/승계·선양·세력 멸망·소속 변경·공위/종결 시 어느 칭제 세력에 계속 귀속되는지 명시. 역사 seed의 칭제 자격도 별도 명시 |
| 관직 권한 | 추천/심의/자칭/인정의 주체와 관할, credential/tenure 생성 공유 경계. 현재 인장이 있거나 관직을 주장한다는 이유로 실권을 부여하지 않음 |

공유 `EventKind`·입력카탈로그·lint/결정론 기준선과 Flyway는 순서를 배정받은 뒤 수정한다. 이미 `world_state.meta`를 쓰는 황실/인장에 별도 표를 먼저 만들지 않는다. 새 저장 모델이 필요할 때에는 기존 codec·flush·콜드 재로드 계약과 대조하고 번호를 예약한다.

## 증거와 완료 조건

- 칭제: 미시드/손상/다른 세계·snapshot·세력/누락전이 false; 단일 유효 증거와 전체 점유만 true; 동일 requestId 재전달·다른 payload 재사용·동시 선언·사망/공위/승계·멸망의 결과와 저장/복구를 검증한다.
- 관직: 추천만으로 tenure/권한이 생기지 않고, 자칭의 실제 관할과 인정 주체를 분리하며, 추인은 원 주장과 tenure.origin을 보존한다. 임명·credential 경합 실패는 원자적으로 되돌린다.
- 황실: 같은 계통의 제위/주공 승계 순서·조서 전달/응답·인가 인장·보관 변경·밀지 제삼자/사자/원제안자 노출 차단·효과 중복0을 검증한다.
- 정체성/제도/시설/편제: 지역망 보존·훼손/전환 효과, 시야 밖 정보 사용0, 실명 부대 유일성·결속/명망/모집원, 다른 월드/세력·권한 변경·재시도·콜드 재로드를 검증한다. 기존 동결 회귀와 구분한다.
- 각 입력은 등록 뒤 `DOMAIN→HANDLER→UI→AI→HELP→TUTORIAL→REPLAY→VERIFIED`의 파일·앵커·실행 테스트 증거로만 승격한다. 튜토리얼은 첫걸음 설명/바로가기이며 연습 월드·진척·달성 API를 만들지 않는다.
- 실제3190 무인/사람 참가 시즌, 같은 입력/seed/replay, K8 데스크톱·모바일 e2e/API 시연·캡처와 승격 뒤 운영 실측이 있어야 3층·칭제·통일을 DONE으로 판정한다. 문서 존재·PR 병합·초록 CI만으로 판정하지 않는다.
