# 현별 사건 피드 읽기 계약 (K5-07)

`GET /api/events?section=PERSONAL|RETINUE_NATION|COURT|BATTLE&cityId={cityId}&before={cursor}&limit={n}`은 기존 인증 피드에 선택적인 양의 정수 `cityId` 조건을 더한다. `cityId`가 없으면 이전 응답과 v1 커서를 유지한다. `GET /api/world-events`는 이 변경의 대상이 아니다. K4의 한 현 최근 사건과 K5의 기록 화면은 이 경로의 같은 `GameEventPage {events,nextCursor}`를 사용한다. 총수 필드는 제공하지 않는다.

현별 피드는 먼저 기존 월드·섹션·SELF/RETINUE/NATION/COURT 권한으로 DB 후보를 제한한다. `refs.CITY` 조건은 정렬·커서·`LIMIT`보다 앞에서 적용한다. 그 뒤 각 후보에 기존 `EventFeedPolicy`를 다시 적용하고, **반환되는** `refs.CITY`가 요청한 현과 같은 사건만 페이지에 넣는다. 따라서 원본 행에 CITY가 있어도 현재 정책이 그 ref를 가린 BATTLE 사건은 현별 결과에 나타나지 않는다. 후속 K5-07 전투 refs 권한 투영이 별도로 검증되어 CITY가 반환되는 경우에만 자연스럽게 포함된다. 현 ID는 주체·시야·관객 권한을 넓히지 않는다.

현별 커서는 월드·섹션·현 ID와 위치를 묶는 v2 형식이다. 다른 현, 무필터 피드, 다른 월드·섹션에서 다시 쓰면 400이다. `cityId <= 0`, 잘못된 커서, `limit` 범위 밖도 400이다. 현별 응답의 `nextCursor`는 다음에 실제로 반환 가능한 사건이 확인된 경우에만 낸다. 스캔 상한에 도달해 숨겨진 후보만 남았을 때 그 행의 위치나 후보 수를 커서로 내보내지 않는다. 매우 희박한 피드는 상한 이후의 오래된 사건까지 도달하지 못할 수 있으므로, 이 제한은 후속 보안형 커서/DB 인덱스 설계에서 다룬다.

검증은 SQL의 현 조건이 `LIMIT` 전에 적용되는지, 다른 주체·세력·월드 사건이 섞이지 않는지, 투영에서 가린 BATTLE CITY가 필터로 드러나지 않는지, 현을 바꾼 커서 재사용이 거절되는지 확인한다. 기존 공개 사건 피드와 전투 ref 마스킹은 유지한다.
