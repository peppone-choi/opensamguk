## US-SUB1-04 발령 받기·응답

- **상태:** 구현됨(화면 있음). 원장 `court.dispatchReply` HANDLER_READY. NPC 군주→사람 방향은 `web/game/e2e/court-live.spec.ts`에 자동 시험이 있고, **사람 군주→사람 부하** 방향은 자동 시험이 없다
- **사용자 가치:** 부하는 받은 발령을 보고 수락하거나 거절하며, 거절의 대가를 안다.
- **정본:** 발령은 도착하면 보류 상태가 되고 장수는 접속 중 언제든 응답한다. 응답은 장수 행동을 소모하지 않는다(spec §2.4). 응답 기한 12순, 거절 시 충성 −5(`DispatchState.kt` 10–13행, `DispatchExecutor.kt`). 발령 거절의 명망 손실은 월단평 집계 −4 한 경로다(spec §2.8). spec은 응답 기한을 「미정」으로 두므로 12순은 현재 구현 값으로만 기록한다.
- **계정:** A-general1(수락), A-general2(거절). 발령은 [군주.md](군주.md) `US-LORD-06`으로 만든다

**조작**

1. A-lord가 A-general1에게 발령하고 A-lord의 다음 개인 턴이 지난다.
2. A-general1로 `/game/qa160/court`를 열고 「받은 요청」 영역(`data-testid="incoming-requests"`)에서 발령 카드를 찾는다.
3. 발령 대상 현·「응답 기한」을 확인하고 「수락」을 누른다(`web/game/components/requests/RequestCard.tsx` 78·91행).
4. 새로고침 뒤 같은 카드가 「수락 · 응답 기한」 상태로 보이는지 본다.
5. A-general2로 같은 절차를 하되 「거절」을 누른다.

**Given / When / Then**

- Given A-general1에게 `PENDING` 발령이 있다,
- When 「수락」을 누르면,
- Then `POST /api/game/api/commands/court/dispatchReply` 결과가 `RESOLVED`·`ok: true`이고 발령 상태가 `ACCEPTED`다.
- And 장수의 `countyAssignment`에 발령 ID·현·발령자가 기록되고, 현재 위치·예약 링·명망 정책은 응답 전과 같다(`court-live.spec.ts` 114–121행과 같은 항목).
- And 부임 이동은 수락 뒤 그 장수의 턴마다 진행된다(spec §2.4).
- Given A-general2에게 `PENDING` 발령이 있다, When 「거절」을 누르면, Then 상태가 거절로 바뀌고 충성이 응답 직후 5 줄어든다.

**검증**

| 축 | 기대 |
|---|---|
| 권한 | 남에게 온 발령에는 응답할 수 없다. 다른 계정 세션으로 같은 `dispatchId`에 응답하면 거절 |
| 비용 | 응답은 장수 행동을 쓰지 않는다. 예약 링 슬롯 수 변화 0. 거절만 충성 −5 |
| 턴 | 응답은 즉시 반영. 부임 이동은 이후 턴 |

| 기한 | 응답하지 않고 12순이 지나면 수락으로 처리되는지 관측(선택, 장시간) |

**증거:** 받은 요청 카드 전·후 캡처, 응답 결과 관측, DB readback(`meta.dispatch`·`meta.countyAssignment` 키만).

## US-SUB1-06 예약 취소와 중복 제출

3. 취소 버튼을 빠르게 두 번 누르는 경우를 따로 실행한다.
