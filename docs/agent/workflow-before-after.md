# Workflow Selection Policy

## Purpose

작업 특성에 따라 **사람-only / AI-assisted / AI-native** 중 어느 방식을 쓸지 결정하는 정책. 근거 없는 생산성 수치는 쓰지 않는다 — 비교축은 이 저장소에서 실제 관측된 운영 특성으로 기술한다.

## Decision Matrix

| 작업 유형 | 권장 방식 | 사람 역할 | AI 역할 | 승인 지점 |
|---|---|---|---|---|
| 패러티 갭 폐쇄(골든→포트→게이트→intake→FE) | AI-native (하니스) | 갭 선정, 격리 판정 승인 | 전 파이프라인 실행 | 커밋·main push |
| 병렬 갭 팬아웃 | AI-native (worktree) | disjoint 검증, fan-in 승인 | 샤드별 실행 | ship 전 게이트 |
| 라이브 버그(루프 바퀴) | Hybrid | 가설 채택/원복 판정 | 측정·재현·수정·재측정 | 채택, 배포 |
| v2 기획/스코프 | AI-assisted | 채택/보류 결정 | 자료 대조, 초안, 충돌 표 | LEDGER 채택 |
| 아키텍처 결정(비가역) | 사람-only + AI 자문 | 결정·책임 | 대안 비교, 영향 분석 | `.ai/decisions.md` |
| 배포/운영 | Hybrid | **go 결정, 위험 수용** | 게이트 실행, 배포 후 관측 | main push, DB 변경 |
| 문서 동기화/요약 | AI-native | 표본 검수 | 코드 기준 재생성 | 정책 문서만 승인 |

## Comparison

| 축 | 사람-only | AI-native | 운영상의 의미 |
|---|---|---|---|
| 시간 | 순차, 세션 길이에 묶임 | 병렬 팬아웃 가능(worktree 샤드) | 병렬화 이득은 **disjoint 분해가 선행**될 때만 실현 |
| 탐색폭 | 경험 기반 소수 경로 | 다수 대안·전수 감사 가능(예: 바퀴 8의 5축 병렬 리뷰) | 넓은 탐색은 오탐도 늘림 → 오케스트레이터 검증 필수(바퀴 8: 15건 중 14건 기각) |
| 검증 루프 | 사람이 직접 판정 | 게이트가 판정(골든/XML/typecheck) — 단 완료 주장은 검증 대상 | "green 아니면 done 아님"을 기계 게이트로 강제해야 AI-native가 성립 |
| 실패 패턴 | 누락·피로 | `failure-cases.md`의 5패턴(false-green, 위조, 범위 이탈, 배포 과신, 소유권 충돌) | AI 실패는 **빠르게 확산**됨 — 잘못된 전제가 자동화를 타면 6사이트 위조 로그처럼 증식(W-1) |

## Human-Only Required

비즈니스 우선순위 · 비가역 아키텍처 결정 · 운영 데이터 삭제/재시드 · 보안 승인 · 법률(Koei IP) 판단 · 주관적 UX 결정 · 비용·위험의 최종 수용 · main push(go).

## AI-Native Recommended

관련 파일 탐색 · 기존 패턴 조사 · 반복 이식(포팅) · 테스트 초안 · 정적 분석 · 문서 동기화 · 변경 요약 · 다수 대안 비교 · 골든 캡처 실행.

## Hybrid Required

배포(AI 실행 + 사람 go/검증 확인) · 루프 바퀴(AI 측정·수정 + 사람 채택 판정) · 격리(quarantine) 판정(AI 증거 수집 + 사람 승인).

## Escalation Rules

- 검증 실패가 같은 가설로 3회 반복 → 디버깅 절차로 전환하거나 사람에게.
- 요구사항 모호/충돌 발견 → 구현하지 말고 질문 목록과 함께 사람에게.
- 계약 밖 파일을 수정해야만 진행 가능 → 사람 승인 요청.
- 크로스 리뷰 `fix-required` 상태로 교착 → 리더(사람)가 증거로 재정.

## Stop Conditions

- `.ai/task.md` 부재/모호 상태에서의 기능 구현.
- 시각 검증 불가 상태에서의 UI "정상" 판정 (→ `채점대기`).
- 승인 없는 main push·prod 변경.
- 골든/테스트를 수정해야 green이 되는 모든 경로.
