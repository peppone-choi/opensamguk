## 3. 분류 차이와 필수 결정 체크포인트

Jira OPENSAM-215의 일곱 지형은 `SEA`, `PLAIN`, `HILL`, `BASIN`, `PLATEAU`, `DESERT`, `MOUNTAIN`이다. 커밋된 `_meta.terrainLegend`와 현재 `HanMapCanvas.tsx:49-58`은 여기에 `RIVER`, `LAKE`를 더한 9개 인덱스 색을 사용한다.

- 두 **수계 레이어**: RIVER, LAKE
- 코드 0-8과 배열 순서는 모두 불변

> **D1 제품 체크포인트:** 구현 전에 `RIVER`/`LAKE`를 수계로 별도 노출할지 확정해야 한다. 일곱 지형으로 흡수하거나 코드를 재배치하는 안은 이 규격 밖이다. 결정 전에는 본 규격의 7+2 분류를 기본값으로 사용한다.

## 4. 검토한 시각 방향

### A. 저채도 역사 지도 + 반투명 소유 색상, 채택

지형은 낙엽·토양·수계 계열의 저채도 명도로 구분하고, 소유는 고정 인지 명도의 투명 색상을 얹는다. 지형과 정치 정보를 동시에 읽을 수 있고, 소유 레이어를 끄면 순수 지형 지도가 남는다.

### B. 세력 색 전면 채우기, 기각

세력을 가장 빨리 파악할 수 있지만 녹색·갈색 지형이 사라진다. 이동·방어 판단에 필요한 강, 산지, 분지 차이가 소유 정보에 압도된다.

### C. 소유 면 없이 국경만 표시, 기각

지형은 가장 잘 보이지만 영토 덕어리를 매번 경계로 추론해야 한다. 여러 세력이 밀집한 중원에서 스캔 속도가 떨어진다.

## 5. 일곱 지형 표면

색은 정확한 sRGB hex로 고정한다. 질감 패턴은 커밋된 `col,row`를 입력으로 사용하며 타일 종류, 좌표, 투영을 변경하지 않는다.

| 코드 | 지형 | 기본 색 | 질감 마스크 | 질감 강도 |
| --- | --- | --- | --- | --- |
| 0 | SEA 바다 | `#193648` | `(col + 2*row) mod 17 = 0` 수평 파문 | 기본색 +9 RGB, 1 소스 셀 |
| 1 | PLAIN 평야 | `#64794B` | `(13*col + 7*row) mod 43 = 0` 희소 입자 | +9 RGB, 1 소스 셀 |
| 8 | HILL 구릉 | `#7C7650` | `(2*col + row) mod 9 = 0` 짧은 점선 | +9 RGB, 1 소스 셀 |
| 7 | BASIN 분지 | `#81705B` | `col,row mod 19 ∈ {0,1}` 컨투어 모서리 | +9 RGB, 1 소스 셀 |
| 6 | PLATEAU 고원 | `#8B7951` | `(col + row) mod 13 = 0` 대각 해칭 | +9 RGB, 1 소스 셀 |
| 5 | DESERT 사막 | `#B69A62` | `(5*col + 11*row) mod 31 = 0` 모래 스티플 | +9 RGB, 1 소스 셀 |
| 2 | MOUNTAIN 산지 | `#625C54` | `(col - row) mod 11 = 0` 능선 해칭 | +9 RGB, 1 소스 셀 |

질감은 다음 목적을 갖는다.

1. 투명 소유 색이 얹히더라도 지형을 구분한다.
2. 적녹 색각이상에서도 바다·평야·산지를 같은 색면으로 오인하지 않는다.
3. 확대 시 셀 다이아몬드와 정렬되어 투영 어긋남이 없다.

## 6. 세력 소유 색상과 명도 분리

### 6.1 정규화

런타임 국가 색의 hue는 보존하되 표시 색은 OKLCH `L=0.62`, `C≤0.14`로 정규화한다. 회색 국가와 중립은 면 표시를 생략하고 `#EFE1BB` 중립 마커를 사용한다.

- 소유 면: 정규화 색 `alpha 0.20`
- 선택 세력: 소유 면 `alpha 0.30`, 국경 강조
- 타 세력 디밍: 지형을 어둡게 하지 말고 소유 면만 `alpha 0.12`
- 라벨: `#FFF9EA` 전경 + `#0B0C0D` 75% 3 CSS px 할로

목업의 `#C65B4B`, `#4E8A70`, `#596CB0`은 명도 분리를 보여 주는 표본이며 실제 세력 목록이 아니다.

### 6.2 데이터 경계

`han-tiles.json` 단독으로는 현재 국가 소유를 알 수 없다. 제품 구현은 반드시 런타임 도시/郡 소유 read model을 결합해야 한다. `seatOwner` 인덱스를 국가 id로 간주하거나 인덱스 modulo로 세력 색을 만드는 것은 성공 위조다.

## 7. 계단형 다이아몬드 郡 경계

郡 경계는 `seatOwner` RLE를 768×669 row-major 격자로 풀고, 오른쪽 또는 아래 이웃의 소유 인덱스가 다른 셀에서만 공유 다이아몬드 변을 그린다.

- 선형: 곡선 보정 없음, 현재 셀 모서리 그대로 계단형
- 기본 색: `#E1D2A3` 66%
- 선 폭: L0 0.75 CSS px, L1/L2 1 CSS px, L3 1.5 CSS px
- 조인: bevel, cap: butt
- 해안: `seatOwner = -1`과의 경계는 郡 경계로 그리지 않음

국경은 인접한 두 郡의 런타임 국가 id가 다를 때 같은 셀 변에 추가한다.

- 하단: `#111315` 78%, 3 CSS px
- 상단: 정규화한 국가 색 82%, 1.5 CSS px
- 적대 국경: 6 CSS px 주기의 단선 패턴. 애니메이션 없음

이 규칙은 새 폴리곤, 스플라인, 보간 좌표를 만들지 않는다.

## 8. 도시 마커 4단계

4단계는 커밋된 level 5-8을 그대로 사용한다. 마커의 크기·링이 중요도를, 채움 색이 소유를 나타낸다.

| 단계 | 데이터 | 형태 | CSS 크기 | 라벨 우선순위 |
| --- | --- | --- | --- | --- |
| T1 | level 5 COUNTY | 원 | 지름 6 px | 선택/호버 또는 L3 |
| T2 | level 6 COMMANDERY | 다이아몬드 | 반지름 5 px | L2 이상 |
| T3 | level 7 PROVINCE | 다이아몬드 + 2 px 외링 | 반지름 7 px, 링 지름 20 px | L1 이상 |
| T4 | level 8 주요 도시 | 다이아몬드 + 이중링 | 반지름 9 px, 링 지름 24/30 px | 모든 LOD |

level 4 `EXTERNAL_PLACE` 37개는 4단계의 맨 아래가 아니라 **예외 유형**이다. `#D9705D` 다이아몬드에 수평 마이너스 기호를 쓰고 아이콘은 모든 LOD에서 노출한다. 라벨은 L1 이상이거나 선택/호버일 때만 노출한다.

추가 상태는 v1처럼 기본 형태를 바꾸지 않고 중첩한다.

- 수도: 오른쪽 위에 `#D5B85A` 5 px 왕관 점
- 내 도시: 애니메이션 대신 `#FFFFFF` 2 px 끊긴 선택 링
- 전쟁/위험: 왼쪽 위에 붉은 5 px 삼각형. 마커 전체를 붉게 변경하지 않음
- 중립: `#EFE1BB` 채움 + `#242019` 1 px 외곽선

## 9. 줌 LOD

현재 `HanMapCanvas.tsx:61-65`의 `1.4`, `2.2`, `5.5` 문턱을 변경하지 않고 4개 표현 단계로 명시한다. `s`는 현재 `IsoView.scale`의 의미를 그대로 사용한다.

| LOD | `s` 범위 | 지형/경계 | 마커 | 라벨 |
| --- | --- | --- | --- | --- |
| L0 천하 조망 | `fitScale ≤ s < 1.4` | 지형, 수계, 소유 면, 국경, 郡 경계 0.75 px | T4, T3, 이민족 | 대권역 + T4, 선택 세력명 |
| L1 주·군 조망 | `1.4 ≤ s < 2.2` | 위와 같음, 郡 경계 1 px | T4, T3, T2, 이민족 | 대권역, 충돌 없는 郡, T4/T3, 이민족 |
| L2 군 전략 | `2.2 ≤ s < 5.5` | 郡·국경 모두 | T4-T1 치소, 이민족 | 충돌 없는 郡, T4-T2. T1은 선택/호버 |
| L3 현 지역 | `s ≥ 5.5` | 郡 경계 1.5 px, 셀 질감 선명 | 모든 노드 | 모든 현 후보, 충돌 배제 후 노출 |

라벨 충돌 순서는 매 프레임 다르게 바뀌지 않아야 한다.

1. 선택 도시/세력
2. T4
3. T3
4. `EXTERNAL_PLACE`
5. 郡 라벨. 치소와의 거리 오름차순, 같은 거리면 `juns[]` 삽입 순서
6. T2
7. T1

라벨 상자는 스크린 공간에서 4 CSS px 패딩하여 교차를 배제한다. 호버/선택 라벨은 충돌 규칙을 이기고 다른 라벨을 숨길 수 있다.

- 4행: 4단계 도시 마커 + 이민족 예외

v1의 `도시명 표기` 토글을 `지명`으로 확장하며, 사용자 선택은 서버가 아닌 로컬 표현 상태로 기억한다.

- 첫 방문 데스크톱: L0/L1에서 확장, L2/L3에서 축소
- 다시 방문: 직전 상태 유지
- 폭 768 px 미만: 기본 축소, `범례` 버튼으로 88vw 다이얼로 열기
- 키보드: 토글에 `aria-pressed`, 축소/확장 버튼에 명시적 한글 접근성 이름

## 11. 축소 지도

데스크톱 축소 지도는 지도 오른쪽 위, 228×156 CSS px이다. 축소 지도는 본문 지도의 픽셀을 스케일하지 않고 같은 `terrain`, `seatOwner`, 런타임 소유 결합을 낮은 해상도로 다시 그린다.

- 표시: 지형, 소유 면 12%, 국경 1 px, 현재 뷰포트 `#F6E8B8` 2 px
- 숨김: 라벨, 郡 경계, 도시 마커, 질감
- 조작: 클릭으로 중심 이동, 뷰포트 상자 드래그로 팬. 휘 줌은 없음
- 좌표: 현재 `cellToScreen`/`screenToCell` 계약 재사용. 별도 위경도, 투영, 보정 수식 금지
- 768 px 미만: 152×104 px
- 640 px 미만: 40×40 `축소 지도` 버튼로 접고 탭 시 오버레이 열기

뷰포트를 축소 지도 경계 밖으로 드래그하면 현재 `clampView`와 같은 범위로 클램프한다.

## 12. 반응형 레이아웃과 접근성

- 지도 자체의 가로:세로 화면 비율은 현재 다이아몬드 배치를 유지한다.
- 범례·축소 지도·줌 버튼은 서로 겹치지 않도록 왼쪽 아래, 오른쪽 위, 오른쪽 아래에 고정한다.
- 업 프레임 지도는 범례 패널 크기만큼 라벨 배치 안전 영역을 제외한다.
- 지형은 색만으로 구분하지 않고 질감을 같이 사용한다.
- 소유는 색 면만으로 구분하지 않고 국경, 세력 라벨, 도시 마커 색을 같이 사용한다.
- 포커스된 도시는 최소 24×24 CSS px 히트 영역을 갖고, 포커스 링은 2 px 흰색 + 2 px 암색 외곽으로 표시한다.
- 툴팁은 `도시명 / 郡 / 세력 / 레벨 / 현재 상태`를 텍스트로 제공한다.
- `prefers-reduced-motion` 여부와 무관하게 지도 핵심 상태 표시는 애니메이션에 의존하지 않는다.

### 12.1 캔버스 상호작용 계약

현재 캔버스의 `aria-label`만으로는 도시를 키보드로 선택하거나 툴팁을 읽을 수 없다. 구현은 캔버스 위에 같은 크기의 DOM 상호작용 레이어를 두고, 현재 LOD에서 노출된 마커만 다음 계약으로 영상화한다.

- 캔버스: `role="img"`, 전체 지도 요약을 `aria-label`로 제공
- 도시: 투명 `button` 1개, 최소 24×24 CSS px. 시각 중심은 기존 `cellToScreen`의 결과와 정확히 같음
- DOM 레이어 위치: 캔버스와 같은 `left/top/width/height`; 별도 투영·좌표 보정 금지
- 포커스: roving `tabindex`. 선택 또는 가장 가까운 주요 도시 1개만 `tabindex=0`, 나머지는 `-1`
- 키 이동: 방향키는 현재 화면 좌표에서 같은 방향 반평면의 가장 가까운 도시로 이동. 거리가 같으면 `cities[]` 삽입 순서
- 활성화: `Enter`/공백은 포인터 클릭과 같은 도시 선택 동작
- 이름: `aria-label="<도시>, <郡>, <세력 또는 중립>, <레벨>, <상태>"`
- 툴팁: 포인터 호버와 키보드 포커스가 같은 `role="tooltip"` DOM을 열고, 도시 버튼이 `aria-describedby`로 연결
- LOD 변경: 포커스한 도시는 새 LOD에서 숨겨지더라도 선택 마커와 DOM 버튼을 유지. 포커스 소실 금지
- 화면 밖: 팬으로 뷰포트에서 벗어난 비선택 도시 버튼은 DOM에서 제거. 선택 도시는 다음 포커스 이동 전까지 유지

포인터 히트 테스트와 키보드 버튼은 같은 도시 id를 반환해야 한다. 이 계약은 새 지리 좌표계를 만드는 것이 아니라 현재 화면 좌표의 접근 가능한 투영이다.

## 14. 구현 수용 기준

이 규격이 이후 구현 티켓의 입력이 되려면 다음을 모두 충족해야 한다.

1. `_meta.terrainLegend` 0-8을 재배치하지 않고 7 지형 + 2 수계로 범례에 표시한다.
2. 색상 레이어를 꺼도 7 지형을 명도·질감으로 구분할 수 있다.
3. 국가 소유는 런타임 read model을 결합하며 `owner`/`seatOwner` 인덱스를 국가 id로 오인하지 않는다.
4. 郡 경계는 셀 다이아몬드 변을 따르고 곡선/보간 좌표를 새로 만들지 않는다.
5. level 5-8을 4단계로 표시하고 level 4 `EXTERNAL_PLACE`를 예외 유형으로 유지한다.
6. `s=1.4`, `2.2`, `5.5` 경계 전후에서 라벨/마커 세트가 표의 LOD와 일치한다.
7. 범례과 축소 지도는 키보드로 열·닫기 가능하고 640/768 px 반응형 규칙을 따른다.
8. 현재 투영, `cellToScreen`/`screenToCell`, `fitScale`, `clampView`, 좌표 원본을 변경하지 않는다.
9. 데스크톱 1440×900, 1280×900과 모바일 390×844에서 도시 라벨이 범례/축소 지도/줌 버튼과 겹치지 않는다.
10. 텍스트 없이 색만 보여 주는 테스트에서도 마커 크기·형태·링으로 4단계를 순서대로 구분할 수 있다.
