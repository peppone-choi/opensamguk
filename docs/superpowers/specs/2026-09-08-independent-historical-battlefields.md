# 역사 전장 이동·조우·전투

2026-09-08 사용자 결정: 역사 지명을 별도 장식 표시로 끝내지 않고 독립 전장으로 이동·조우·전투하도록 구현한다.

## 제품 계약

- 전장은 도시와 별개인 위치다. 현재 장수의 병력이 이동·주둔·교전하며, 새 군단 편제를 날조하지 않는다.
- 이동은 개인 예약 턴을 소비한다. 도달 가능한 연결을 서버에서 검증하고, 전장의 실제 위치와 소속 부대를 읽기 API 및 승인된 지도 UI에 반영한다.
- 같은 전장에 도착한 교전 관계의 적 부대와 결정론적으로 조우한다. 비적대 국가와의 동시 주둔은 자동 선전포고를 발생시키지 않는다.
- 전장 전투는 실제 병력·군량·부상 변화를 저장한다. 도시 수비·성벽·점령·세입은 전장 승패로 변경하지 않는다.
- 전장에 있는 장수는 이전 도시의 수비와 도시 내정에 동시에 참여할 수 없다. 이전 도시 식별자는 호환용 귀환 기준으로만 보존한다.
- 패퇴는 검증된 귀환 위치로 이동하며, 해당 위치의 소유·존재가 변한 경우도 명시적인 규칙으로 처리한다. 재시작 후 전장 위치·귀환 기준·전투 결과를 복원한다.
- 지리 출처의 좌표와 게임 경로 복원을 구분한다. 사건 연도는 건설 연도가 아니다. 수치 보너스를 사료 좌표에서 추론하지 않는다.

## 구현 순서와 완료 경계

1. 사료 원장: 적벽·관도·장판·백제성의 APPROXIMATE 대표 좌표와 호뢰관의 WITHHELD 판정을 저장하고 검증한다.
2. 도시 없는 전투 커널: 기존 피해·트리거 흐름을 재사용하되 빈 전장과 수비군 소진은 공성으로 진행하지 않는다.
3. 독립 위치·이동·조우: 우선 위치와 육상 접근을 확인한 장판의 실제 왕복·적대 조우를 끝까지 연결한다. 저장·재시작·도시 행동 배제를 함께 통과시킨다.
4. 읽기 API·지도·명령·전투 기록: 실제 엔진 결과만 표시하고, 관도 접근 검증과 함께 확장한다.
5. 적벽 수역 접근·수전, 백제성 방어 거점 및 호뢰관 근거 보강을 별도 기작으로 이어간다. 일반 육상 전투를 수전으로 재명명하지 않는다.

위 순서는 구현 단위이며 1·2 완료만으로 독립 전장 기능 전체를 완료로 보고하지 않는다. 기존 2026-09-06 봉인 리플레이 절편의 제외 범위는 해당 절편에 한정되며, 이번 사용자 결정으로 독립 전장 확장을 진행한다.

## 불변식과 검증

- 변경은 ChangeRecorder → JdbcFlushExecutor 경로만 사용한다.
- 같은 입력·seed·정렬 순서의 전투·이동 결과는 동일하다.
- 기존 도시 전투 회귀, 런타임 도시 305/548, 행정 소유 격자, 보급 전용 70개 간선은 보존한다.
- 빈 전장에서는 전투 난수·피해·부상이 없다. 수비군 소진 뒤 가상 도시를 만들지 않는다.
- 오래된 위치 revision·카탈로그 버전·허용되지 않은 연결은 이동 전에 거부한다.
- 승인된 야전사령부 디자인과 지도 시각 계층을 따른다.
- 출시 게이트는 도시→전장→조우→패퇴/주둔→귀환 및 재시작 복원까지 포함한다.

## 첫 적용 장소의 전투 기록

장판 절편은 실제 개인 전투 로그(장소·상대·병력 손실·결과·seed 지문)를 저장한다. 기존 도시 대상 battle_replay 행에 가상 도시를 넣지 않는다. 전장 전용 단계 재생 화면은 이 절편의 완료 조건이 아니며, 실제 로그·병력 정산·재시작 복원은 완료 조건이다.
