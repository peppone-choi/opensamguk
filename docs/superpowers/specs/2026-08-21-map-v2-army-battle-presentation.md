# v2 han 맵 — 부대·전투 지도 표현 스펙

- 작성 2026-08-21
- 상태: **SUPERSEDED 2026-08-22 — 현행 모델 감사만 참고**
- 선행 조건: 이 스펙의 §5 Phase A 가 닫히기 전에는 v2 han 맵을 기본 지도로 승격하지 않는다.
- 관련: ADR-LITE-042(패러티 해제) · ADR-LITE-043(han 건국 밸런스) · `docs/superpowers/plans/2026-06-02-frontend-parity-and-scenario-seed-plan.md` (F4)

> 아이소 셀과 현재 `HanMap`을 전제로 한 표현 단계는 폐기한다. §2의 현행 데이터 감사와
> 결정론·접근성 원칙은 유효하지만, 새 표현은 `2026-08-22-han-route-network-and-command-design.md`의
> 다턴 이동·작전·replay 상태와 승인된 corridor geometry가 준비된 뒤 구현한다.

---

## 1. 왜 이 스펙이 필요한가

v2 han 맵은 지형 타일·도시 아이콘·부대 스프라이트를 새로 갖췄다. 그런데 현재
`web/game/components/game/HanMap.tsx` 가 그리는 것은 **도시 마커와 그 위의 상태 아이콘 한 장**뿐이다.
부대도, 전투도, 진격도 지도에 없다.

부대 스프라이트 133종을 만들어 놓고 지도에 안 세우면, 그 자산은 전투 로그 삽화로만 쓰인다.
그리고 지도는 "누가 어디서 싸우고 있는가" 라는, 이 게임에서 사람이 가장 보고 싶어 하는 정보를
못 보여준다. **표현을 배지 하나로 끝내면 지도가 표가 된다.**

이 스펙은 그 표현을 정의하되, **없는 데이터를 지어내지 않는다** — §2 가 그 경계다.

## 2. 지금 모델이 실제로 가진 것 (근거 있는 사실만)

| 사실 | 근거 |
| --- | --- |
| **장수 = 부대.** 별도의 부대 엔티티가 없다 | `logic/…/domain/General`, 전투 단위는 `war/WarUnitGeneral.kt` |
| **부대 위치 = `general.cityId`.** 좌표가 아니라 도시 소속 | `IdentityDto.kt:190` `val cityId: Int` |
| **부대 병종·병력이 이미 API 에 있다** | `IdentityDto.kt:189` `crew`, `:202` `crewTypeId`, `:225` `crewTypeName` |
| **이동 = 인접 도시로 한 턴에 즉시.** 중간 좌표가 없다 | `actions/military/CheIdong.kt` — `NearCity(1)`, `setVar('city', destCityID)` |
| **출병 = 진격+전투+결과가 한 턴 안에 끝난다** | `actions/war/CheChulbyeong.kt` — `rng.choice(candidateCities)` → `processWar()` 1회 |
| **출병당한 도시에 3턴짜리 흔적이 남는다** | 같은 파일 — `city.state=43 / term=3`; 감쇠 `43→42→41→0` (`world/PreUpdateMonthly.kt:155`) |
| **교전 지분이 국가별 %로 이미 노출된다** | `city.conflict` jsonb → `GET /api/diplomacy/conflict` = `[[cityId,{nationId:pct}]]` (`DiplomacyController.kt:165`) |
| **전사자 수가 도시에 쌓인다** | `city.dead`; `world/ProcessWarIncome.kt:46` 이 매달 `pop += dead*0.2` 로 부상병 회복 |
| **턴 종료를 프론트가 실시간으로 받는다** | SSE `turnCompleted` (`app/game-api/…/sse/RealtimeRelay*`) |
| **부대는 소멸하지 않는다** | 병력은 `dead` 로 빠질 뿐, 부대 삭제 이벤트가 없다. 장수만 죽는다(`ai/GeneralAI.kt:161` reason `'사망'`) |

### 2.1 없는 것 (지어내면 거짓말이 되는 것)

- **부대의 지도 좌표.** `WorldMapDto.kt:12` cityList tuple = `[city, level, state, nation, region, supply]`.
  부대 위치 필드가 없다.
- **다턴 행군.** 이동은 인접 1칸 즉시다. "3턴 걸려 이동 중인 부대" 는 모델에 없다.
- **전투의 시간적 전개.** `processWarNG` 는 페이즈 루프를 한 번에 돌고 최종 결과만 남긴다.
  페이즈별 중간 상태는 **로그로만** 존재하고 DB 에 남지 않는다.

> 따라서 "지도 위를 행군하는 부대" 를 실시간으로 그리는 것은 **불가능이 아니라 신규 도메인**이다.
> 이 스펙은 그것을 §6 에 별도 트랙으로 분리하고, Phase A/B 는 기존 데이터만으로 세운다.

## 3. 설계 원칙

1. **연출은 데이터의 함수다.** 화면에 나타나는 모든 것은 §2 표의 어느 행에서 온 값이어야 한다.
   근거 없는 연출은 넣지 않는다.
2. **턴 결과의 재생(replay)이지 시뮬레이션이 아니다.** 프론트는 자체 전투 계산을 하지 않는다.
   엔진이 확정한 결과를 시간축에 펴서 보여줄 뿐이다. (v2 space 계약과 동일 — 별도 simulation 금지)
3. **결정론.** 같은 턴 데이터를 같은 순서로 재생하면 같은 화면이 나온다. 연출용 난수를 쓰지 않는다.
4. **연출은 건너뛸 수 있어야 한다.** 애니메이션이 정보 접근의 전제가 되면 안 된다.
   모든 상태는 정지 화면에서도 읽을 수 있어야 한다(접근성 · `prefers-reduced-motion` 준수).
5. **머리공간을 쓴다.** iso 셀 256×320 중 위쪽 y 0–127 은 지형 기복 외에는 비어 있다.
   부대·배지·수치는 이 공간에 올린다. 다이아(y 128–255)는 지형이 소유한다.

## 4. 표현 정의

### 4.1 주둔 — 도시에 서 있는 부대

각 도시에 그 도시 소속 장수들이 보인다.

- **대표 부대 스프라이트 최대 3기**를 도시 아이콘 뒤/옆에 배치. 선정 규칙(결정론):
  `crew` 내림차순 → 동률이면 `generalId` 오름차순.
- 4기 이상이면 `+N` 칩. 부대가 0이면 아무것도 그리지 않는다(빈 도시가 명확해진다).
- 스프라이트는 `crewTypeId` → 통일 유닛 스프라이트. che id 는 `units.json.equivalents` 로 han id 에 사상해
  **같은 그림**을 쓴다(§ 통일 유닛 체계).
- 부대 아래 얇은 **병력 바** — `crew / 최대치`. 색은 소속국 색.
- 줌 아웃 시 스프라이트를 끄고 국가색 점 + 총 병력 수로 떨어진다(LOD).

**소유 정보:** `cityId` 로 묶은 `crew` / `crewTypeId` / `nationId`. 전부 기존 필드.

### 4.2 교전 — 지금 싸우고 있는 도시

`city.conflict` 항목이 2개 이상 = 다국 교전 중.

- 도시 마커 상단(머리공간)에 **교차 검 배지**.
- 배지를 감싸는 **원호 링을 참전국 지분 %로 분할**하고 각 호를 그 국가 색으로 칠한다.
  지분은 `GET /api/diplomacy/conflict` 가 주는 `pct` 그대로. **프론트가 재계산하지 않는다.**
- 호버 시 참전국·지분 목록.

### 4.3 전장의 열기 — 최근 전투 흔적

`city.state` 43→42→41→0 감쇠(월 1단계, `PreUpdateMonthly` P7)는 **"몇 턴 전에 공격받았는가"** 를
그대로 담고 있는 무료 데이터다. 지금은 정적 아이콘 한 장으로만 쓰인다.

- `state` 43/42/41 → 다이아 위에 **붉은 열기 오버레이**를 3→2→1 단계 알파로. 시간이 지나면 식는다.
- 도시 34(탈취)/32 등 비전투 상태는 기존 `state-N.png` 유지 — 열기와 별개 축.
- 이것만으로 지도에 **전선(front)** 이 저절로 드러난다. 추가 데이터 0.

### 4.4 진격 — 턴 재생

SSE `turnCompleted` 를 받으면 그 턴의 전투를 **순서대로 재생**한다.

- 출병 1건 = 출발 도시 → 목표 도시로 **부대 스프라이트가 활강**(2:1 iso 경로, 0.6s).
- 도착 시 교전 이펙트 → 결과 배지(승/패/함락).
- 함락이면 도시 깃발·색이 교체되는 전환.
- 여러 건이면 엔진이 확정한 처리 순서대로 직렬 재생, 전체 상한 8초. 상한 초과분은 즉시 반영.
- 스킵 버튼 · `prefers-reduced-motion` 이면 재생 없이 최종 상태로 점프.

**필요한 것:** 그 턴에 어떤 출병이 있었는지 (출발/목표/결과)의 목록. 지금 SSE 페이로드에 없다 →
**§5 Phase B 의 유일한 신규 API.** 엔진은 이미 `lastBattleResult` / `lastConquerCity` 를 들고 있으므로
새 계산이 아니라 **노출**이다.

### 4.5 죽음

부대 소멸 표현은 만들지 않는다 — 모델에 없다. 대신:

- **병력 감소** = 병력 바가 줄어드는 것. 스프라이트 인원 수를 병력에 맞춰 바꾸지 않는다
  (133종 × N단계 = 자산 폭발). `ponytail:` 상한 — 온전/반/궤멸 3단계 변형이 정말 필요해지면 그때 3배만.
- **장수 사망** = 지도 사건이 아니라 로그·명예전당 사건. 지도에서는 그 부대가 다음 턴에 사라질 뿐이다.
- **전사자 누적** = `city.dead` 는 지도에 안 그린다(도시 상세에서 읽는다). 4.3 열기와 정보가 겹친다.

## 5. 단계와 게이트

### Phase A — v2 han 맵 승격의 **선행 조건** (신규 API 0)

전부 기존 응답 필드만 쓴다. 이것이 닫히기 전에 v2 맵을 기본으로 올리지 않는다.

- [ ] A1 주둔 부대 스프라이트 + 병력 바 + LOD (§4.1)
- [ ] A2 교전 배지 + 지분 링 (§4.2) — `GET /api/diplomacy/conflict` 소비
- [ ] A3 전장 열기 오버레이 (§4.3) — `city.state` 43/42/41
- [ ] A4 통일 유닛 스프라이트 해석기: `crewTypeId` → 스프라이트 키, che→han `equivalents` 사상 포함
- [ ] A5 `prefers-reduced-motion` / 정지 화면 가독성 확인

**게이트:** `web/game` 빌드 통과 + A1–A4 각각의 렌더 테스트 + 스프라이트 키 해석의 전수 테스트
(모든 `crewTypeId` 가 스프라이트로 해석되고, 미해석이 조용한 공백이 아니라 요란한 실패가 될 것).

### Phase B — 턴 재생 (신규 API 1개)

- [ ] B1 턴 전투 요약 노출: 그 턴의 출병 목록 `[{fromCityId, toCityId, attackerNationId, defenderNationId, result, conquered}]`.
      엔진이 이미 가진 `lastBattleResult`/`lastConquerCity` 의 노출이지 신규 계산이 아니다.
      **one-daemon-write-rule 무비위반** — 읽기 경로다.
- [ ] B2 진격 애니메이션 + 결과 배지 + 함락 전환 (§4.4)
- [ ] B3 스킵 / 재생 상한 / reduced-motion

### Phase C — 선택 (후순위)

- [ ] C1 부대 호버 상세(장수·병종·훈련·사기)
- [ ] C2 전선 히트맵 토글
- [ ] C3 전투 화면에서의 병종 대치 삽화(133종 스프라이트의 두 번째 쓰임)

## 6. 별도 트랙 — 다턴 행군 (이 스펙 밖)

"지도 위를 여러 턴에 걸쳐 행군하는 부대" 는 §2.1 대로 **신규 도메인**이다. 필요한 것:

- 부대의 지도상 위치(도시가 아닌 경로상 위치)
- 다턴 이동 명령과 중간 턴의 부대 상태
- 행군 중 요격 규칙

이는 전투 밸런스·명령 체계·AI 를 모두 건드리므로 별도 스펙과 ADR 이 필요하다.
**이 스펙은 그것을 전제하지도, 배제하지도 않는다** — Phase A/B 의 표현은 다턴 행군이 나중에
들어와도 그대로 유효하다(주둔·교전·열기는 그때도 같은 데이터에서 온다).

## 7. 열린 질문

- Q1 주둔 부대 대표 3기 상한이 큰 도시에서 충분한가, 아니면 5기인가 — 실측 후 결정.
- Q2 4.3 열기 오버레이가 지형 타일 가독성을 해치는 임계 알파 — 실측 필요.
- Q3 Phase B 재생을 기본 on 으로 둘지 opt-in 으로 둘지.
- Q4 관전자/미소속 유저에게 부대 병력을 어디까지 보여줄지 (정보 은닉 규칙 확인 필요 — `showSecret`).

## 8. 하지 않는 것

- 프론트에서의 전투 재계산 (원칙 2 위반)
- 연출용 난수 (원칙 3 위반)
- 부대 소멸 스프라이트 (모델에 없음)
- 병력 단계별 스프라이트 변형 (자산 폭발, 지금은 병력 바로 충분)
- 지도에 `city.dead` 수치 표기 (4.3 과 정보 중복)

## 9. 유닛 표현 — 아이콘으로 간다 (2026-08-22, ADR-LITE-044)
