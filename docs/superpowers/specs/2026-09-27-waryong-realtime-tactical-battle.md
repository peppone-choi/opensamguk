# 와룡전식 실시간 전술 전투 계약

- Date: 2026-09-27
- Status: 사용자 D1–D5 확정, 2026-09-28 NPC 전용 가속 결정 반영, 구현 계약
- Scope: 군단 조우, 성새 강공, 부곡 없는 개인 조우
- Basis: ADR-LITE-025의 권위 세션·권한·재접속·리플레이 경계. 이 문서는 ADR-LITE-061의 무조작 조우와 2026-09-17 군단 명세 §5.1.1의 선계획 자동 해결을 대체한다.

## 결정과 이전 계약의 차이

전투는 항상 같은 서버 권위 고정 틱 세션으로 해결한다. 참가 자격자 중 사람 소유 장수가 한 명이라도 있으면 60초 참가 대기 후 10Hz로 최대 5분 진행한다. 사람 소유 장수가 0명이면 참가 대기와 벽시계 페이싱 없이 같은 엔진·AI·입력 로그로 끝까지 계산한다(2026-09-28 사용자 결정). 입장하지 않은 측과 이탈한 측은 AI가 맡는다. 사전 계획을 계산해 자동 종결하는 별도 제품 경로, 전술 정지, 자동전투 fallback은 사용하지 않는다. 권위 액터, epoch fence, 승인 명령 receipt, 진영별 투영, durable snapshot, 손상 시 격리, 결과 outbox와 단일 캠페인 flush는 7월 계약을 유지한다. 7월의 12–15분·200ms 틱·진영당 16편제·수전 출시 범위는 이 군단 조우/성새/일기토 계약에 적용하지 않는다. 수전의 별도 기존 제품 결정은 이 문서에서 폐기하지 않는다.

한쪽은 선봉·중앙·좌익·좌비·우익·우비 여섯 자리다. 주장과 해당 군단에 함께 있는 부(府) 소속 장수가 실제 부곡을 이끌고 각각 한 자리만 맡는다. 부곡 없는 장수는 제외하고 빈 자리는 남긴다. 기본값은 주장 중앙, 나머지를 무력 내림차순·장수 ID 오름차순으로 정렬한 첫 장수를 선봉, 남은 장수는 통솔 내림차순·장수 ID 오름차순으로 좌익→우익→좌비→우비에 둔다. 주장에게 부곡이 없으면 중앙은 빈다. 참가 대기 중 합법적인 자기 측 배치를 바꿀 수 있다. 부곡의 실제 병력은 보존하고 원작의 1,000명 정원을 적용하지 않는다. 개인 조우는 부곡 없이 일기토 세션을 연다.

## 원작 사실과 게임 결정값

원작 확인 사실은 6분대 개별 조작, 돌격·공격·대형·수비·성벽·후퇴와 3위치 집결점, 원작 214개 64×64 전장, 성벽·성문·사다리, 사기 100 문턱과 유사 무력의 일기토 제안이다. 근거는 사용자 제공 원작 조사와 로컬 원본 `~/.cache/waryongjeon/README.md` 「전투 화면 해독」·「전투 유닛」·「전투 지도 산출」이다. 원작의 피해식·속도·사거리·성문/사다리 공략 시간·일기토 진행 방식·시간 제한은 **UNKNOWN**이다. `KI.EXE` 정적 분석과 플레이 영상을 각각 별도의 증거로 기록한 뒤에만 원작 확인값으로 승격한다. 그전 실행 수치는 `data/battle/waryong-tactical-rules-v1.json`의 게임 결정값을 쓴다. 이 파일의 `CONFIRMED`는 원작 재현 확인이 아니라 제품 수치의 결정 상태다.

## 세션과 월드 경계

참가 자격자는 해당 전투의 군단 주장, 같은 군단의 부(府) 소속 장수, 城 수비 책임자, 개인 조우 당사자다. 티켓을 만들 때 이 집합의 소유권을 동결해 사람 소유 장수 수를 판정한다. 접속 여부나 실제 배치 인원으로 모드를 바꾸지 않는다. 불변 티켓과 결과에는 `pacingMode=REALTIME|ACCELERATED_NPC`를 기록하고 리플레이에도 같은 값을 보존한다. `REALTIME`은 사람 소유 참가 자격자가 한 명 이상인 경우다. `ACCELERATED_NPC`는 0명인 경우이며 참가 대기 없이 AI 명령을 같은 승인·이벤트 경로에 남기면서 논리 틱을 가능한 한 빨리 진행한다. 100ms는 두 모드 모두 논리 틱 길이지만 가속 모드에서 `sleep`이나 벽시계 타이머를 요구하지 않는다. 가속 모드의 제한 시간은 3,000 논리 틱으로만 판정하고 DB `deadlineAt` 만료로 승패를 정하지 않는다. DB 시각은 lease·감사 기록에만 쓰고 가속 전술 틱의 대기 조건으로 쓰지 않는다. 모드는 세션 중 소유권·접속이 바뀌어도 다시 계산하지 않는다.

1. 조우/강공/개인 조우를 만난 턴 단계에서 결과를 즉석 계산하지 않고 `battleId`·`worldId`·원인 사건·참가자·고정 상태·규칙/전장 해시·시드·entity revision·`pacingMode`를 담은 불변 티켓을 만든다. 관련 군단·장수와 공성 城에 battle lock을 두고 알림을 기록한다. 같은 원인 사건의 재시도는 같은 티켓만 얻는다.
2. 다른 장수와 군단의 월드 턴은 계속 처리한다. 잠긴 당사자의 새 이동·개인 턴 입력은 사유와 함께 거절한다. 턴 러너는 전투 완료를 기다리지 않는다. lock generation과 잠금 대상 revision을 결과 적용 때 재검사한다.
3. `REALTIME`은 알림 뒤 60초 동안 배치·접속을 기다리고, 기한 내 입장하지 않은 쪽은 AI가 조작한다. 진행 중 사람 입장은 다음 안전 틱에서 자기 권한을 인계받고, 이탈은 다음 안전 틱부터 AI가 이어받는다. 이 전이는 event seq·tick·DB deadline을 가진 durable 입력이다. 재접속은 단기 JoinTicket·session epoch·마지막 event seq로 수행한다. `ACCELERATED_NPC`는 60초 참가 대기를 건너뛰고 모든 참가 자리를 AI가 맡아 즉시 개전한다.
4. 클라이언트는 분대 또는 측 전체의 6명령, 3위치 집결점, 합법 목표, 성문 조작, 일기토 신청/응답, 계책 카드를 전술 의도로 보낸다. 위치·피해·난수·도착 틱은 보내지 않는다. 같은 명령 ID/내용은 최초 ACK를 재현하고 같은 ID/다른 내용은 거절한다. 전투는 서버 100ms 정수 틱으로만 전진한다.
5. 3,000틱 전에 섬멸/후퇴/목표 달성으로 종료할 수 있다. 시간 초과 시 생존 병력×사기의 합계를 비교하고 동률이면 수비 측을 지킨 것으로 처리한다. 종결 뒤 입력은 거절한다.
6. `BattleResolved`와 결과 outbox가 durable해진 뒤 game-engine이 `(battleId,resultRevision)` 멱등성·lock generation·entity revision을 검사하고 `ChangeRecorder -> JdbcFlushExecutor` 단일 flush로 사상자·사기·퇴로·포로/부상/사망·점령·성벽/성문/공성 상태를 반영한다. 불일치면 결과를 추측해 적용하지 않고 blocked 사건을 남긴다. 결과 적용 확인 뒤 전체 관전 리플레이를 공개한다.

### actor 배포와 클라이언트 통신

첫 수직 절편의 actor 조정 코드는 인증·티켓 발급·battle 저장소를 이미 가진 `app/game-api` 아래에 둔다. 이 소스 위치는 연결 부위를 먼저 검증하기 위한 것이며, ADR-LITE-025의 전용 `battle-engine` 런타임을 대체하는 배포 결정은 아니다. 제품 가동 전 전투 actor와 DB 재발견을 요청 스레드/월드 턴 실행기에서 떼어 전용 프로세스·배포 단위로 분리하고 CPU·메모리·연결 수 한도와 100ms 틱 지연을 부하 시험한다. battle 런타임은 `battle_*`만 쓰고, 캠페인 변경은 game-engine의 단일 flush에만 맡긴다. 재시작·다중 인스턴스에서 `(worldId,battleId)`의 한 actor만 원자적 `sessionEpoch` claim과 lease 갱신으로 쓰게 하며, 이전 epoch의 명령·체크포인트·결과는 거부한다. 분리 전 co-location은 개발/검증 상태이며 운영 수용 기준을 충족하지 않는다.

클라이언트 실시간 전송은 **WebSocket**으로 고정한다. 인증된 game-api HTTP join 요청은 계정과 현재 전투 권한을 확인한 뒤 60초 이내 만료하는 서명 JoinTicket을 발급한다. 브라우저/모바일은 `JoinTicket`, `lastSeenEventSeq`로 전투 WebSocket에 접속하며 장기 gateway access token을 전투 런타임에 넘기지 않는다. 서버는 토큰의 계정·참가자·진영·authority revision·`sessionEpoch`을 저장된 티켓 및 현재 권한과 다시 대조한다. HTTPS POST+SSE는 이 계약의 대체 전송이 아니다.

| 방향 | 메시지 계약 |
| --- | --- |
| 서버→클라이언트 | `SNAPSHOT(worldId,battleId,sessionEpoch,tick,eventSeq,sideProjection)` 뒤 증가하는 `DELTA(eventSeq,tick,sideProjection)`; 상대의 비공개 카드·안개 속 좌표/ID는 제외한다. |
| 클라이언트→서버 | `COMMAND(clientCommandId,expectedEpoch,expectedAuthorityRevision,issuedTick,scope,intentType,intentPayload)`; 서버가 계정·seat·진영을 JoinTicket과 현재 상태에서 결정한다. 클라이언트는 위치·피해·난수·효력 틱을 지정하지 않는다. |
| 서버→클라이언트 | `ACK(clientCommandId,ACCEPTED|REJECTED,serverTick,acceptedTick?,effectiveTick?,eventSeq?,reasonCode?,currentAuthorityRevision)`; 같은 ID와 같은 정규화 입력은 최초 ACK를 되돌리고 같은 ID의 다른 입력은 `IDEMPOTENCY_CONFLICT`로 거절한다. |

재접속에는 새 JoinTicket과 마지막으로 **적용한** `eventSeq`를 사용한다. 같은 epoch에서 누락분을 안전하게 이어줄 수 있으면 진영별 delta를 순서대로 보낸다. epoch가 바뀌었거나 gap/투영 검증에 실패하면 해당 진영 snapshot과 그 이후 delta를 보낸다. 클라이언트는 snapshot 기준보다 오래된 delta를 버리고 seq 누락 시 재동기화를 요청한다. 단절 중인 편제는 기록된 DB deadline 뒤 AI로 인계되며 재접속은 다음 안전 틱에서 사람에게 권한을 돌려준다. 재접속 이전 epoch의 미확인 명령은 새 권한 revision으로 재검증하며, 명령 ID 중복 응답은 저장된 영수증을 쓴다. 전체 replay는 결과 적용 ACK 뒤에만 공개한다.

## 전장과 판정

`BATTLE.MAP`의 앞 512바이트는 판별 타일셋 표, 뒤는 214×4096바이트다. 원작 바이트는 어느 Git 저장소에도 넣지 않는다. `opensamguk-images`의 owner-accepted 파생 export와 타일 번호·지형 분류 목록만 배포한다. 성새/야전 구분은 파생 카탈로그의 검증된 분류를 쓰며, 단순 벽 타일 번호 존재 여부로 재분류하지 않는다. 판마다 평지·숲·산·강·성벽 구성비와 통행 가능 칸을 사전 계산한다. 전투 省의 고정된 han-tiles 판본에서 같은 범주의 지형 구성비를 계산하고, 일치도가 가장 높은 상위 후보 중 `battleId` 시드로 하나를 선택한다. 공성은 성새판, 조우는 야전판으로 한정한다. 전장 ID·타일셋·분류 목록 해시·지형 입력 해시를 티켓과 결과·리플레이에 핀한다. #995 지형 변경은 새 티켓에만 적용한다. #984의 지도 설계 층이 규칙 입력으로 배선되면 그 뒤 생성하는 티켓부터 해당 판본과 해시를 지형 입력으로 사용한다. 이미 발행한 티켓은 기존 han-tiles 핀을 유지한다.

### 전장과 화면 좌표

2026-09-30 K0가 전달한 사용자 직접 답 「원작처럼 아이소」에 따라 64×64 전술 전투는 원작처럼 아이소 화면으로 그린다. 전략 지도는 탑다운이다(ADR-LITE-057). 추출 전장 214판과 유닛 그림 `BATTLE.MAP`·`BATTLE.MDL`·`BATTLE.SCH`를 AI/새 그림으로 대체하지 않는다. 전투 화면은 K2가 소유한 `opensamguk-images`의 owner-accepted 파생 export를 쓴다. 원본 바이너리는 Git 저장소에 커밋하지 않는다. export의 판·자산 ID, 버전, SHA를 K2와 C2가 맞추고 티켓·replay에 핀한다. 자산이 빠졌을 때 다른 그림으로 조용히 대체하지 않으며 이전 replay의 핀을 보존한다. 아직 확인되지 않은 실제 SHA·추출 결과를 추정하지 않는다. 이 화면 결정은 전술 엔진의 지형·시야·이동·거리·충돌·피해식, 결정론, 진영별 비공개 정보 투영을 변경하지 않는다.

서버 권위 위치는 `row`·`col` 정수 각각 **0..63**인 64×64 격자 칸이다. 현재 `TacticalUnit.row/col`, `Battlefield.at(row,col)`과 티켓의 `battlefieldId`가 이 정본을 사용한다. `SNAPSHOT`·`DELTA`·결과·replay의 위치도 `(row,col)`을 같은 순서와 범위로 표현한다. `COMMAND`는 6명령·3위치 집결점과 합법 목표 등의 전술 의도만 보내며 목표 칸 좌표를 지정하지 않는다. 서버는 픽셀 `(x,y)`를 위치 입력으로 받거나 권위 상태로 저장하지 않는다. 화면에서 부르는 `battleMapId`는 티켓의 핀된 `battlefieldId`와 수치상 같은 0..213 판 번호다. 새 메시지 필드 이름은 C2/K6 계약판에서 확정하며 기존 티켓 필드를 조용히 개명하지 않는다.

K6/K5 렌더러는 논리 칸 `(r,c)`를 화면 투영의 기준점 `x=(r+c)×16`, `y=(r−c)×8`로 계산한다. 원점 이동·배율·디바이스 픽셀비·히트 테스트 역변환은 화면 몫이다. 역변환한 칸은 화면에서 분대·성문 같은 합법 목표를 선택하는 데만 사용하고 서버에는 분대 slot·목표 ID 등의 전술 의도만 보낸다. 역변환한 `(row,col)`이나 픽셀 `(x,y)`를 명령의 위치 입력으로 보내지 않는다. 픽셀값을 반올림해 서버가 칸을 추측하거나 row/col 축을 교환하지 않는다. 현재 WS 본문은 아직 구현되지 않았고 기존 `x/y` 위치 필드는 없으므로 변환 대상도 없다. 이후 x/y 호환 입력이 발견되면 축 정의·격자 대응·범위·정밀도·핀된 판 번호를 계약판에 기록한 다음 별도 마이그레이션으로 처리한다.

칸 점유는 분대 하나에 한 칸이다. 매 틱 시작의 점유 스냅숏으로 이동 요청을 판정하며 점유 칸 교환·꼬리물기는 허용하지 않는다. 같은 빈 칸 경합은 고정 우선도 뒤 분대 ID로 푼다. 지형의 이동/방어 보정은 원장에 둔다. 병력·사기·훈련·피로·군량과 통솔·무력·지력·정치·매력은 티켓에 고정한다. 시작 사기 계산값이 100 미만이면 개전 첫 틱부터 후퇴 AI가 우선하며 사람 명령으로 취소할 수 없다. 이는 사기가 이미 낮은 부곡의 전투 이탈을 표현하는 게임 결정값이다. 그 상태에서 패배하면 괴멸한다. 실명 부대 고유 능력과 병종 상성도 버전된 원장만 읽는다. 날씨·계절·밤, 계책 카드, 목표, 극적 사건은 티켓에 기록한 시드와 순서로 결정한다. v1 원장의 날씨는 효과가 정의된 맑음·비만 포함하며, 안개·눈·강풍 및 바람 방향/불 확산은 V8 규칙 버전에서 효과와 함께 추가한다. `SUPPLY_CONVOY`(호위·습격)·`RIVER_CROSSING`·`PASS_BREAKTHROUGH`·`PURSUIT`·`AMBUSH` 목표는 각각 이동·요격·관문·보급 상황에서 파생하고 목표별 승리 조건을 V10 연결 때 구현한다. 장수 컷인·대사·전장 효과는 결과 상태/사건을 읽는 연출이다. 개막 연출·실황 자막·소리·사료 명장면은 이 버전에 넣지 않는다.

성새전은 城의 `wall`·`defence`에서 벽/성문 내구도를 만들고 주둔 `garrison`과 수비 책임자의 부곡을 참가시킨다. 수비가 성문을 열 수 있다. 공격은 성문 파괴 또는 사다리 통과 전에 성벽 뒤 칸을 공격할 수 없다. 한 강공은 한 세션이며 남은 내구도·사기·포위 상태를 다음 강공까지 보존한다. 야전에서는 무력 높은 장수가 일기토를 신청할 수 있고 사람은 수락/거절, AI는 원장 유사 무력 기준으로 응답한다. 개인 조우는 일기토로 곧바로 시작한다. 일기토는 원작 진행 방식 확인 전 서버 결정론 판정과 읽기 전용 연출로 처리한다.

## 결정론과 수용 증거

입력 로그에는 초기 티켓의 `pacingMode`, 양측 사람/AI 명령, 승인/효력 틱, 전이, 시드, 결과 및 버전별 checkpoint state hash를 남긴다. 결과에도 `pacingMode`를 기록한다. 두 모드 모두 같은 핀과 입력 로그를 재생하면 마지막 해시와 결과 바이트가 일치해야 한다. 기존 P-4 `ReplayEnvelope`는 작전 단위이므로 `battleId`와 battle replay hash를 연결하되 작전 hash를 대체하지 않는다. 한쪽의 미공개 정보는 상대 스트림에 보내지 않고 전체 리플레이는 캠페인 적용 후 공개한다.

수용 검증은 (a) 입력 순서를 바꾼 적색 결정론/리플레이 프로브, (b) 사람 소유 자격자가 있는 전투의 60초 부재·중도 입장·이탈 AI 인계, (c) 전투 중 무관 월드 턴 진행 및 당사자 잠금, (d) 재시작·중복 결과 PG 통합 테스트, (e) 야전·공성·일기토 웹/모바일 명령과 관전/다시 보기 실제 조작, (f) 사람 소유 자격자 0명인 전투가 대기·`sleep` 없이 끝나고 같은 AI 입력 로그로 재현되며 티켓·결과 모드가 일치하는지다. 원본 조사와 기능 검증의 통과 상태는 별도로 보고한다.
