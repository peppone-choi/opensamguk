## What the diff changes

- `_glob_pattern_to_regex()` (`check.py:274-291`) translates each entry of `PRODUCT_AUTHORITY_SOURCE_GLOBS` into a compiled regex over posix relative paths; `PRODUCT_AUTHORITY_SOURCE_REGEXES` (`:293`) precomputes them at import.
- `scannable_repo_files()` (`check.py:298-309`) replaces the per-pattern filesystem walk with one `git ls-files --cached --others --exclude-standard -z`, NUL-split and `surrogateescape`-decoded, raising `RuntimeError` through the existing `run_git_bytes()` contract when git fails.
- `check_product_authority_policy()` (`check.py:997-1002`) now matches the precompiled regexes against that single in-memory list.
- Two new test modules, and five `.gitignore` entries closing a local-only-exclude gap.

## Verification performed

1. **Glob/regex equivalence, independently fuzzed.** Rather than re-running the author's test, I built a separate hostile fixture (327 files: dotfiles, near-misses `xsrc/`, `src/mains/`, `webx/`, `toolsx/`, hidden dirs, spaces, Hangul path segments, a literal `**` directory, a bracket-containing directory, plus 300 randomly generated paths) and diffed `root.glob(pattern)` against `_glob_pattern_to_regex(pattern)` for all 24 patterns. **0 mismatches.** The first run reported one mismatch on `**/src/main/**/*.kt`; I traced it to a macOS case-insensitive-filesystem artifact in my own fixture (`A.KT` and `A.kt` collapse to one inode), not to the code — removing the colliding entry gives a clean run.
2. **Read the translation logic rather than trusting the test.** The three tricky cases hold: leading `**` → `(?:.*/)?` (matches zero directories, so `src/main/A.kt` at top level is caught); mid-pattern `**` → `/(?:.*/)?` with the following segment deliberately not re-prefixed by `/` (so `web/x.ts` matches `web/**/*.ts` with zero intervening dirs); bare `*` → `[^/]*`, which cannot cross a separator, so `settings.gradle.kts` stays root-only while `sub/settings.gradle.kts` is correctly rejected. Greediness is not exploitable: `(?:.*/)?` must end in `/`, so `xsrc/main/A.kt` cannot satisfy `^(?:.*/)?src/main/…`.

## Findings

- [LOW, confidence HIGH] `tools/agent-system/tests/test_check_glob_pattern_equivalence.py:62-73` — **the equivalence test can pass vacuously for a newly added pattern**, which contradicts its own docstring claim that "a newly added pattern is covered automatically". `expected` and `got` are both derived from `FIXTURE_FILES`, so a pattern whose file type is absent from the fixture yields `expected == got == set()` and passes regardless of whether the translation is correct. Demonstrated: appending `"**/*.[tc]oml"` to `PRODUCT_AUTHORITY_SOURCE_GLOBS` leaves the test **OK**, even though `_glob_pattern_to_regex` mistranslates it (`re.escape` makes `[`/`]` literal, so the regex rejects `.codex/agents/x.toml` while `pathlib` accepts it). By contrast, appending `"web/**/*.[jt]s"` — an extension the fixture does cover — correctly **fails** the test, so the guard works whenever a fixture file exists. One-line fix: assert per pattern that `expected` is non-empty, turning "no fixture coverage" into a loud failure instead of a silent pass.
- [LOW, confidence HIGH] Glob character classes (`[abc]`, `[!a]`) and `**` used as a partial segment (`a**b`) are silently mistranslated by `_glob_pattern_to_regex` (`check.py:281-284`). No current pattern uses either, so this is latent, not live. Combined with the finding above it is the realistic path to a future silent regression. A one-line `raise ValueError` on an unsupported metacharacter would make the constraint explicit at import time rather than at some future debugging session.
- [LOW, confidence HIGH] Comment/docstring arithmetic is off by one: `check.py:279`, `tests/test_check_glob_pattern_equivalence.py:5`, and `tests/test_check_product_authority_scan.py:4,14` all say "23 patterns"/"23 walks", but `len(PRODUCT_AUTHORITY_SOURCE_GLOBS) == 24`. The "9 of them full-tree-recursive" count is correct. Cosmetic, but the number is quoted four times and in the commit messages.
- [LOW, confidence HIGH] The guard's coverage is now sensitive to machine-local ignore configuration, because `--exclude-standard` honours `.git/info/exclude` and `core.excludesFile` in addition to committed `.gitignore` files. A developer whose local excludes hide an untracked source file gets a local pass that CI (fresh clone, no `info/exclude`, no global excludes) would not give. This fails in the safe direction — CI is strictly stricter, and per verification 9 no tracked file can ever be hidden — so it is a caveat rather than a defect. Checked concretely: the entries still present only in this worktree's `.git/info/exclude` after commit `60836eaf` are `.context/`, `/legacy`, `.conductor/settings.local.*`, `/.claude/RESUME.md`; of these only `.context/` could plausibly hold matchable source, and it currently contributes **0** files that match a source glob and pass `is_active_product_authority_source()`. No action needed today.
- [LOW, confidence MEDIUM] Pre-existing, not introduced here, noted only because this diff establishes the better pattern two hundred lines away: `check.py:577` still does `run_git(["ls-files", "--others", "--exclude-standard"]).splitlines()` without `-z`, so it is exposed to git's path quoting and to filenames containing newlines. The new `scannable_repo_files()` gets this right. Worth aligning in a separate change.

No CRITICAL or HIGH findings at any confidence level.

## Security surface

Clean. `run_git_bytes(["ls-files", …])` passes a fixed argument list to `subprocess.run` with no `shell=True` and no interpolated data, so there is no injection surface — nothing user- or repo-controlled reaches the argv. `-z` output framing removes git's `core.quotepath` escaping entirely, so adversarial filenames (embedded newlines, quotes, non-UTF-8 bytes) cannot forge or split an entry; `surrogateescape` decoding round-trips them losslessly back through `ROOT / rel`. Paths are used only for `is_file()` and reads under `ROOT`; `git ls-files` never emits absolute or `..`-relative paths, so no traversal outside `ROOT` is reachable. The `RuntimeError` on a non-git checkout is the correct choice over an empty-list fallback: an empty list would render this policy check a silent no-op, which is precisely the failure mode a security-adjacent guard must not have.

## Positive observations

- Enumerating once at the git layer instead of filtering after a filesystem walk is the correct shape of fix: the pathological tree is never *touched*, not merely discarded afterwards. A name-based `.omo/` skip-list would have passed the same tests and rotted at the next tool that creates a scratch directory.
- `test_check_product_authority_scan.py` deliberately uses `totally-unrelated-scratch-dir/` and `scratch-tree/` rather than `.omo`, and says why in a comment. That is the difference between testing the property and testing today's symptom, and it is the reason the `.omx/` case in commit `60836eaf` is already covered.
- `test_non_git_directory_raises_instead_of_silently_returning_empty` pins the fail-loud contract explicitly, which is the assertion most likely to be quietly "helpfully" relaxed later.
- Keeping `--others` (rather than the simpler `--cached`-only) preserves pre-commit detection of violations in not-yet-added files, and there is a dedicated test for exactly that distinction — my mutation run confirms it is the only thing holding that behaviour in place.
- Precompiling the regexes at module scope rather than per call avoids reintroducing per-pattern work inside the loop.
- The `.gitignore` commit message cites `git check-ignore -v` evidence per entry; every claim reproduced exactly when I re-ran it.

## Assessment

The three tricky glob cases the author flagged are correct under independent fuzzing, the mutation claims reproduce, the fail-loud path is genuinely unswallowed, the `.gitignore` additions are justified and cannot hide tracked source, and no sibling unbounded walk survives in `check.py`. The findings above are all LOW and none blocks merge; the first two are worth a short follow-up because together they are the plausible route to a future silent mistranslation.

Verdict: cleared
