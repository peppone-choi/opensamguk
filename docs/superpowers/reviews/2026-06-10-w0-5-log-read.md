## 공격 벡터별 판정

### A1. PHP 경계 시멘틱 위조 여부 — `id >` vs `id >=`
GetFrontInfo.php:65-103 세 피드 전부 `id >= %i`(GTE, 경계 포함). Since 3메서드 모두
`id >= :sinceId`로 미러, IT가 경계 자신 포함을 행 단위로 증명
(`findGlobalHistorySince(5,…)` → id 5 포함). **무혐의.**

### A2. 글로벌 액션 SUMMARY+ACTION 합집합 — 과포섭/누락 검증
writer 전수 그렙(2026-06-10, 엔진 LogEntryDraft 전 call site):
- common `ActionLogger.kt:17` pushGlobalActionLog → SYSTEM/**SUMMARY**
- engine "global"/"action" → SYSTEM/**ACTION**: `WorldActionContext.kt:571-573`,
  `ReservedTurnHandler.kt:831`, `MakeGeneralHandler.kt:133,138,149`, `ClaimNpcHandler.kt:93`
  — 전부 PHP `pushGlobalActionLog`(general_record general_id=0 log_type='history') 등가 스트림.
- common ActionLogger의 LogCategory.ACTION 방출은 GENERAL 스코프 한정(generalDraft) →
  SYSTEM∩ACTION = 글로벌 액션 전용. **합집합은 정확히 한 논리 스트림 — 과포섭 0, 누락 0.**

### A3. NATION/HISTORY 매핑 — 엔진측 writer 존재 확인
common `ActionLogger.kt:12-15`(NATION/HISTORY + nation_id, 0/null 가드) 외에 엔진
`ProcessNationCommand.kt:205,223`도 scope "nation"/category "history"/nationId 세팅 →
`scopeLiteral` 경유 동일 NATION/HISTORY 영속화. 두 계열 모두 read 필터에 포섭. **무혐의.**

### A4. P1-009 경매 — fabrication 의혹
현재 엔진 auction/betting 핸들러는 scope `"action"`(+category `"auction"`/`"betting"`) —
`log_scope`/`log_category` enum에 없는 리터럴(P6 flush 버그, DatabaseHooks.kt scopeLiteral
NOTE에 기추적; AuctionBidHandler:209, AuctionFinalizeHandler:118,162,219,230,
AuctionExpiryDaemon:62, PlaceBetHandler:71). 해당 행은 INSERT 시 enum 캐스트로 실패하므로
**오늘 DB에 category=auction 행은 존재할 수 없다.** 파운데이션은 카테고리 리터럴을
하드코딩하지 않고 `findRecentByScopeAndCategory(scope, category, limit)` 범용 피드로 제공 —
정본 리터럴은 enum 버그 수정 오너가 확정하고 호출부가 주입한다. 값 발명 없음. **무혐의.**
(legacy `getAuctionLogRecent`의 `array_reverse` 표시 순서는 소비자 소관으로 KDoc 명시.)

### A5. P1-059 map 히스토리 — 기존 `/api/world-log` 재사용 주장과의 충돌
