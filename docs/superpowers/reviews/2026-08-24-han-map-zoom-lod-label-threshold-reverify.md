# han-map-zoom-lod 라벨 문턱 재분리 독립 재검증 (5차, 작성 레인 외부)

Scope: 4차 리뷰가 잡은 B1(넓은 고DPI 화면에서 縣 라벨 도달 불가) 의 수정 — `TIER2_LABEL_ZOOM` 절대 복귀(5.5), 마커 문턱은 `tierZoom(table, kind, fit) = K·fit`(K=2.19) 유지, 신규 `labelZoomFor(kind, fit) = min(MAX_SCALE-0.5, max(절대문턱, 마커문턱))`, `draw()` 라벨 루프 두 호출부, `initialView` 의 `INITIAL_SCALE_MARGIN=0.9`. 대상 파일 `web/game/components/game/HanMapCanvas.tsx`·`web/game/lib/isoMap.ts`·`web/game/__tests__/HanMapCanvas.test.ts`·`data/map/han-tiles.json`. 커밋 전 워킹트리 상태.
Verdict: cleared

작성자 산문은 근거로 치지 않고 `isoMap.ts` 의 실제 `fitScale`·`MAX_SCALE` 과
`data/map/han-tiles.json` 의 실제 격자(`_meta.cols=768`, `rows=669` → spanX=1435,
spanY=717.5)로 전부 재계산했다. 아래 수치는 이 세션에서 재현한 값이다.

## 1. B1 해소 — 확인됨

`h = round(cssW·0.53)`, 백버퍼 = css × dpr, `fit = min(W/1435, H/717.5)`
(항상 W/1435 가 최소). 마커 = `2.19·fit`, 라벨 = `min(13.5, max(5.5, 마커))`.

| 800@1x | 800×424 | 0.5575 | 1.2209 | 5.5000 | 예 | 예 | 예 | 1.099 |

4차에서 깨졌던 1920css@2x 가 이번엔 라벨 문턱 5.8603 < MAX_SCALE(14) 로 **도달 가능**하다.
`min(MAX_SCALE-0.5, …)` 클램프 덕에 어떤 `fit` 에서도 라벨 문턱 ≤ 13.5 < 14 라 "라벨이
영원히 안 뜨는 화면" 은 수학적으로 존재하지 않는다. B1 은 해소됐다.

기준 뷰포트(1440css@1x, fit=1.0035)에서 라벨 문턱은 정확히 절대 5.5 — 밀도 기준
체감이 그대로 돌아왔다. 마커 문턱은 2.1976 로 구 절대 2.2 대비 0.1% 미만 오차.

## 2. 마커 측 수정 유지 — 확인됨

`TIER2_MARKER_ZOOM = {COUNTY: 2.19, MARQUISATE: 2.19}` 는 그대로고
`tierZoom(table, kind, fit)` 3인자 시그니처(`k === undefined ? undefined : k*fit`)도
유지된다. `draw()` 마커 루프(`HanMapCanvas.tsx:217`)가 3인자로 호출한다. K=2.19 > 1
이므로 `2.19·fit > fit` 이 모든 `fit > 0` 에서 성립 — "완전 줌아웃(s=fit)이면 1급만" 보장은
되돌려지지 않았다. 위 표의 `마커>fit` 열 전부 예. 되돌림 없음.

`initialView` 도 같은 좌표계에서 `MIN_TIER2_MARKER_ZOOM * fitScale(w,h,g)` 를 재계산해
0.9 를 곱하므로 8개 뷰포트 전부 `init < 마커문턱` 이다(표 마지막 열). 리사이즈당 1회라
비용 문제 없음.

## 3. 라벨 ≥ 마커 불변식 — 실사용 전 구간 성립

`max(5.5, 2.19·fit)` 이므로 클램프가 걸리기 전엔 정의상 라벨 ≥ 마커다. 클램프가 실제로
값을 깎기 시작하는 지점은 `2.19·fit > 13.5 ⇔ fit > 6.1644 ⇔ 백버퍼 폭 > 8846px`
(예: 1440css 컨테이너에 dpr ≈ 6.2). 그 위에서는 라벨 13.5 < 마커 13.63… 이라 불변식이
깨진다 — 다만 같은 구간에서 마커 문턱 자체가 곧 `MAX_SCALE` 을 넘어(`fit ≥ 6.3927`,
백버퍼 폭 ≥ 9174px) 마커도 못 뜬다. 8846~9174px 백버퍼라는 좁은 창에서만 "마커 없이
라벨만" 이 이론적으로 가능하다. 현행 하드웨어 범위를 한참 벗어나고, 테스트 주석
(`HanMapCanvas.test.ts:62-64`)이 이 극단을 별개 케이스로 명시해 인지된 상태다.
**LOW, 비차단.**

## 4. 조기 탈출 가드 — 회귀 없음

- `HanMapCanvas.tsx:189` 에서 `const fit = fitScale(w, h, {cols, rows})` 를 `draw()`
  진입부에 **한 번만** 계산하고 마커 루프·라벨 가드·라벨 내부 검사가 모두 재사용한다.
- 라벨 루프 가드(`:256-257`)는 살아 있다: `minLabelZoom` 을 루프 **밖에서** 한 번 구하고
  `s >= minLabelZoom` 일 때만 ctx 세팅 + 1144개 순회에 들어간다. 프레임당 무조건 전면
  순회로 되돌아가지 않았다.
- `minLabelZoom` 계산이 `Object.keys(...).map(...)` 로 프레임당 길이 2 배열 두 개를
  할당한다. 상수 폴딩 못 하는 건 `fit` 의존이라 어쩔 수 없고, O(2)라 무시 가능. **LOW, 비차단.**
- 삭제된 `MIN_TIER2_LABEL_ZOOM` 의 잔존 참조는 `web/game` 전체 grep 결과 0건.

## 5. 테스트 검토 — 도장 찍기 아님

`web/game/__tests__/HanMapCanvas.test.ts` 신규/변경 5건:

- "마커 문턱은 fitScale 의 배수(K>1)…" — `fit ∈ {0.01, 0.5575, 1.0035, 2.676, 100}` 에서
  `tierZoom(...) > fit` 단언. K 를 1 이하로 되돌리면 깨진다. 실효 있음.
- "라벨 문턱은 … MAX_SCALE 아래에 머문다" — `fit ∈ {0.5575, 1.0035, 2.676, 5}` 에서
  `labelZoomFor < MAX_SCALE` **그리고** `labelZoomFor >= tierZoom(마커)` 를 함께 단언한다.
  **4차의 B1(1920@2x, fit≈2.676)을 정확히 커버한다** — 라벨 문턱을 다시 `5.48·fit` 로
  되돌리면 이 테스트가 fit=2.676 에서 즉시 깨진다. 순서 불변식도 같은 루프에서 검증한다.
  구현식 재기술이 아니라 독립 성질 단언이다.
- "좁은 화면에서 절대 밀도값을 그대로 쓴다"(fit=0.01) — `max()` 의 절대값 가지 커버.
- `undefined` 전파는 `tierZoom` 3곳 + `labelZoomFor('KINGDOM', 1)` 로 유지.
- 첫 테스트(`toBeCloseTo(TIER2_MARKER_ZOOM.COUNTY * fit)`)는 여전히 구현식 동어반복이라
  회귀 탐지력이 없다 — 4차와 같은 지적, 차단 아님.

## 7. 이월된 비차단 항목 (N1, 변동 없음)

컨테이너 폭 0(숨김 탭·초기 마운트)이면 `fit = 0` → 마커 문턱 0 → 도시 루프를 다 돈다.
라벨 쪽은 절대 하한 5.5 가 돌아온 덕에 오히려 4차보다 나아져 조기 탈출한다. 0px 캔버스라
시각 결과는 없고 프레임 1회 낭비뿐. `if (!(fit > 0)) return;` 한 줄로 막을 수 있으나
이번 라운드 스코프 밖이라 그대로 둔다. **LOW.**

## 결론

B1 은 실제로 해소됐고(1920css@2x 에서 라벨 문턱 5.8603 < 14), 마커 측 `K·fit` 보장은
되돌려지지 않았으며(전 뷰포트 `문턱 > fit`), 라벨/마커 순서 불변식은 실사용 전 구간에서
성립하고, 성능 조기 탈출 가드도 유지됐다. 새 테스트가 이번 회귀를 실제로 잡는다.
타입·테스트 전부 녹색. 남은 지적 3건은 전부 LOW·비차단(백버퍼 8846px 초과 극단,
프레임당 소형 배열 할당, fit=0 퇴화 입력). **cleared.**
