## 3. 시도한 공격과 결과

1. **재기동 유실(P0-36 본체)**: `WorldSnapshotLoader.loadCities` SELECT에 state 누락 시
   in-memory 0 → 다음 flush가 `state=0` UPDATE로 직전 달 재해 표시를 지움.
   → SELECT/매핑 포함 확인 + `ScenarioBootIT`에 rehydrate 왕복 테스트(state=4 → buildSnapshot → 4) 존재. **방어됨.**
2. **state-only 변경 유실**: RaiseDisaster의 리셋/기록은 state 단독 변경일 수 있다 —
   `diffCity`가 state를 비교하지 않으면 dirty 마킹이 안 서고 recorder-flush에서 탈락.
   → `diffCol("state", ...)` 추가 + `ChangeRecorderTest` state-only dirty 테스트. **방어됨.**
3. **applyDisaster 이중 기록(리셋→기록 같은 도시)**: 루프2의 preLogic은 루프1 `world.updateCity` 후
   재독해 — 최종 상태 일관. flush는 어차피 in-memory 전체 행(`updatedCities`) UPDATE라 패치 병합 의미론 무관. **무해.**
4. **betting upsert 정합**: ON CONFLICT 타깃 = V7 UNIQUE(general_id,betting_id,betting_type)와 일치.
   `BettingUpsertFlushIT` — 단일 행 + amount 100+200=300 누적 + 충돌 시 user_id 기존 행 유지 + verb=UPSERT 검증. **방어됨.**
   (PlaceBetHandler 검증 체인 9종은 지시대로 **건드리지 않음** — W1-C 소관.)
5. **연감 UPSERT vs PHP plain INSERT**: PHP ng_history는 UNIQUE 없는 단순 INSERT.
   opensamguk은 재기동-재캡처 시 같은 (profile,year,month) 재실행 가능 → UNIQUE 위 UPSERT가 멱등 정본.
   read 결과는 동일(월당 1스냅샷). 저장 계층 한정의 의도적 divergence로 기록. RNG/로그 영향 0.
6. **dirty 신호 누락**: 기록만 있고 `isDirty`가 안 서면 flush 트리거 자체가 안 선다 —
   statistic/yearbook을 `isDirty` 식에 포함(statistic은 기존 누락 보강). `ChangeRecorderTest`에
   yearbook 단독-dirty + emit 순서 + clear 테스트 추가. **방어됨.**
7. **FlushPayloadConvergenceTest/DatabaseHooksOrderTest 회귀**: 두 테스트 모두 statistic/yearbook
   채널 동등성을 단언하지 않음 — 비대칭(아래 §5-2)이 게이트를 깨지 않음을 사전 확인. **무해.**
8. **one-daemon-write**: 전 채널 ChangeRecorder→JdbcFlushExecutor JDBC 배치 경로.
   EntityManager 0 — `DaemonNoEntityManagerTest`/`InfraNoEntityManagerTest`가 게이트에 포함. **준수.**
9. **삽입 순서**: yearbook/betting columns는 LinkedHashMap 운반 + SQL 컬럼 리스트 고정 바인딩.
   `yearbookInserts()` emit 순서 보존 테스트 추가. **준수.**
10. **하드코딩/위조**: 골든 수치 없음(DDL+운반체 작업). 모든 상수는 PHP 스키마/라이터 인용 기반. **준수.**
