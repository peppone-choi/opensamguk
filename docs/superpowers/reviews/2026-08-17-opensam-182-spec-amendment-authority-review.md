# OPENSAM-182 [H6] product-spec 개정 권한 규칙 — 자체 리뷰

Scope: docs v2 백로그 README의 "정본 개정 규칙" 신규 절과 .ai/decisions.md ADR-LITE-036. 코드 변경 없음.
Verdict: cleared

## 1. 무엇을 정했나

`docs/superpowers/plans/2026-07-17-v2-ticket-backlog/README.md`의 **"정본 판정" 절 바로 뒤**에
"정본 개정 규칙" 절(한 페이지 이하)을 넣었다. 네 조항 = 티켓 범위 1~4와 1:1 대응이다.

1. 개정 시점 — 값·키·불변식·산출물이 달라지면 개정.
2. 승인자·기록 — 사람 승인 필수, ADR-LITE 기록 의무, 수정 커밋이 ADR 번호 인용.
3. supersede **명시 열거 의무** — 열거 안 된 절은 살아 있는 것으로 간주.
4. 후속 계획의 traceability 표에 product-spec 행 요구.

## 2. 티켓 수용 기준 대조

- AC1 "충돌 시 개정/비개정 중 하나가 명시되고 '언급하지 않음'이 유효한 상태가 아니게 된다" —
  **충족**. 3번 조항이 그 문장을 그대로 규범으로 적었다("개정하거나, 비개정임을 한 줄로 적거나,
  둘 중 하나다").
- AC2 "이번 사고에 소급 대입하면 ADR-LITE-025 시점에 §6·§10에 대한 명시적 판단이 요구됐음을 규칙이
  설명한다" — **충족**. "소급 대입" 문단이 3번(025의 열거 누락)과 4번(07-30 계획의 0행 표) 두 조항으로
  사고를 설명한다.

## 3. 스스로 공격해 본 것

- **비범위를 넘었나?** product-spec 본문은 **한 글자도** 고치지 않았다. 07-28 2.5D 문서 `:70`도
  건드리지 않았다(변경 금지 대상). 바꾼 파일은 백로그 README와 `.ai/decisions.md` 둘뿐이다.
- **규칙이 이미 있는 것과 충돌하나?** 정본 판정(README:19 계열)과 라벨 분리(중복 제거 규칙)는
  "무엇이 이기는가"를 정하고, 새 절은 "그것을 어떻게 고치는가"를 정한다. 두 절 사이에 끼워 넣어
  읽는 순서가 자연스럽다. CLAUDE.md의 하드 규칙(사람 승인 없이 merge/deploy 금지 등)과도 같은 방향이다.
- **소급 감사를 유발하나?** 하지 않는다 — ADR Consequences에 "소급 적용은 하지 않는다"를 명시했다.
  기존 문서 일괄 재감사는 이 티켓이 요구한 적 없고 비용만 크다.
- **규칙이 자기 자신을 승인하나?** 아니다. ADR-LITE-036은 `proposed`/`Approved by: NONE`이며 규칙의
  발효 자체가 사람 비준을 전제한다고 적었다.
- **4번 조항이 과한가?** "0행이면 미판단"이라는 판정 기준만 준다. 이번 사고에서 07-30 계획이
  product-spec을 0회 참조한 것이 실제 관측 증상이므로 근거가 있는 요구다.
