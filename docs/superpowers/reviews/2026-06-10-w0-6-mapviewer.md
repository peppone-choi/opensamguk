## 2. 두 맵뷰어 불변식 검증

- prop 표면 동일: 양쪽 모두 `mapData / disallowClick / currentCityId / live / showMe / refreshKey`.
- 동작 분기는 **데이터 가용성 차이만**(불변식이 허용하는 "데이터만 차이"):
  - gateway는 클릭 인터랙션이 원래 없음(기존 설계 — `MapPreview.tsx` 헤더 주석) → `disallowClick`은 타입 미러(no-op), 두번-탭 토글 버튼 미노출. 동작 날조 없음.
  - gateway 프록시(`/api/server-map/[id]`)는 캐시 preview만 노출 → `live/showMe` 타입 미러, 미배선 주석 명기. 라이브 머지를 흉내내는 가짜 동작 없음.
- 시각 패러티 동시 적용: 계절 공식, state 캡 해제, `.my-city` blink CSS, `.map-btn-stack`/`.hide-cityname` CSS 블록이 양쪽 globals.css에 동일 삽입.
- 양쪽 tsc green(§4).

## 3. 공격 시도와 결론

- **"mapData 주입 기본 클릭-비활성이 레거시 위조 아닌가?"** — 레거시 Vue 뷰어엔 self-fetch가 없어 '주입' 자체가 기본 경로다. 감사 P0-22가 "주입 시 self-fetch 생략, 클릭 비활성"을 명시했고, 레거시 주입 소비자(PageHistory/PageCachedMap)는 전부 disallow-click=true, 클릭이 필요한 PageFront는 명시적으로 false를 준다 — 명시 prop 우선 규칙으로 두 패턴 모두 재현됨.
- **"live 머지가 날조 아닌가?"** — `/api/map`(WorldMapController, W9)·`api.worldMap`은 기존 코드이며, `lib/api.ts:267-269` 주석("MapPreview와 id로 머지해 렌더한다")의 설계를 그대로 구현. 좌표는 PHP도 클라(cityConst)에서 머지한다.
- **"live 실패 시?"** — preview 폴백(graceful), 테스트의 graceful 패스 유지. 빈 세계/실패 placeholder 기존 동작 불변.
- **"기존 호출부 깨짐?"** — 모든 prop optional + 기본값이 기존 동작과 동일(`<MapViewer />` = self-fetch + 클릭 활성). 호출부 7곳 무수정, 양쪽 tsc로 증명.
- **"두번 탭 토글 라벨/극성?"** — 레거시 코드 기준: `toggleSingleTap=true`면 첫 탭 즉시 이동(`MapViewer.vue:450-452` `if (!toggleSingleTap) return`), active 클래스는 toggleSingleTap에 바인딩 — 라벨·극성 그대로 복제(개선 금지 원칙).
- **테스트 하네스 수정 정당성** — Node 25의 스텁 localStorage가 jsdom Storage를 가리는 환경 결함(+jsdom matchMedia 부재). 폴리필은 setup 전용이며 프로덕션 코드 경로와 무관. 기존 65케이스 전부 green 유지로 회귀 없음 증명.
