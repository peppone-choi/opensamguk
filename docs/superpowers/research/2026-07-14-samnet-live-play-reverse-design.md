# 삼넷 실플레이 역기획과 오픈삼국 v2 3D 결정

> 관찰일: 2026-07-14
> 상태: adopted-for-v2-planning
> 범위: 인증 후 `status`, `map`, `gacha`, 임관 전후 상태, 국정·관직·등용·부대, 이동·전투 명령, 일괄등록, 프리셋, 정세, 전투 replay
> 원칙: 공개·인증 화면의 상호작용 구조만 분석한다. 계정 정보, 화면 자산, 문구, 수치는 복제하지 않는다.

## 1. 관찰 방법

- 실제 계정으로 로그인해 상태를 변경하지 않는 범위에서 화면을 조작했다.
- 이미 예약된 명령은 유지했다. 빈 슬롯 선택과 명령 모달 진입까지만 수행하고 제출하지 않았다.
- 지도는 WebGL canvas, 모드 전환 후 canvas 상태, 로드 자산과 네트워크 요청을 확인했다.
- 전투 기록은 저장된 공성 replay를 열어 자동 재생, 일시정지, 다음, 스킵, 처음 기능과 턴 로그를 확인했다.

## 2. 실플레이에서 확인한 제품 구조

### 상태 화면

- 첫 화면은 홍보 화면이 아니라 운영 작업대다. 장수 상태, 소속, 경험, 금·군량, 보호 턴, 세계 시각을 항상 노출한다.
- 지도·현재 도시·선택 장수·명령 큐·개인/전투/정세 로그가 한 화면에서 연결된다.
- 국가 미소속 기능은 숨기지 않고 비활성 사유를 툴팁으로 보여준다.
- 정세 로그는 게임 날짜, 사건 분류, 본문, 실제 시각을 함께 보존한다.

### 명령 큐

- 장수별 24개 슬롯을 사용하며, 슬롯 선택과 drag reorder를 지원한다.
- 남은 시간과 현재 명령 실행 시간을 큐 헤더에 함께 표시한다.
- `내정`, `군사`, `계략`, `이동·탐색`, `개인`으로 명령을 좁힌다.
- 일괄등록은 `명령 선택 → 적용 장수 선택 → 입력 턴 선택 → 적용`의 3단계 흐름이다.
- 프리셋은 현재 큐를 저장하고 다시 적용하는 별도 흐름이다.

### 이동과 지도

- 전체 지도와 이동 목적지 선택기가 같은 WebGL 지도 엔진을 사용한다.
- 전체 지도는 Three.js 계열의 GLB 도시·병사 asset과 terrain texture를 사용한다.
- 이동 모달은 현재 도시 주변과 이동 가능한 도시 목록을 함께 제공한다.
- 관찰한 이동 규칙은 현재 도시 기준 사방 8블록 안의 인접 도시이며, 실제 후보 4개가 국가·도시명·규모와 함께 노출됐다.
- `2D모드` 전환은 DOM 지도로 갈아끼우지 않는다. 같은 WebGL canvas를 유지하고 카메라·표현을 평면화하며, 다시 `3D모드`로 복귀한다.

### 장수 성장

- 뽑기 포인트, 활성 슬롯, 전체 보유 수를 한 화면에서 분리한다.
- 등급·능력·개별 능력치·이름 정렬, 교체, 분해, 합성, 강화, 승급, 특기 계승으로 이어진다.
- 희귀 획득을 전역 피드로 노출해 개인 성장과 서버 사건을 연결한다.

### 전투 기록

- 전투 목록은 게임 날짜, 전투 유형, 양측 국가·지휘관·병종, 승패, 실제 시각을 보여준다.
- replay는 공격자·수비자 카드, 현재 병력/HP, 장수 능력, 현재 턴, 피해 숫자와 누적 턴 로그를 동기화한다.
- 자동 재생, 일시정지, 다음, 스킵, 처음 기능이 있어 결과 확인과 원인 분석을 모두 지원한다.

### 임관 후 국가 운영면

- 230년 5월 중순 한에 임관한 상태를 다시 확인했다. 상태 헤더의 소속, 임관 정세, 개인 로그, 국가 봉록, 현재 주둔 도시가 같은 사건을 서로 다른 읽기 모델로 일치시켰다.
- 이후 230년 7월 상순에 재접속해도 소속 `한`, 현재 도시 `강주`, 시간당 국가 봉록, 임관 개인 로그가 유지됐다. 임관은 메뉴 하나를 여는 UI flag가 아니라 소속·도시·수입·로그·채널·명령 capability를 함께 바꾸는 원자적 도메인 사건이어야 한다.
- 임관 후 `국가 회의실`, `부대 막사`, `관직 설정`, `인재 등용`이 국정 메뉴에 열린다. 개인 명령 작업대와 국가 운영은 별도 앱이 아니라 같은 전역 shell과 현재 장수 문맥을 공유한다.
- 관직 화면은 군주·참모·승상과 군부·내각 직위를 재임자, 권한, 효과로 나눈다. 현재 일반 `장수` 역할은 전체 조직도를 읽지만 임명 입력은 받지 않으며, 군주 또는 참모만 임명·해임할 수 있다는 거부 사유를 같은 화면에 명시한다.
- 인재 등용은 자국을 제외한 재야·타국 후보를 탭으로 나누고 레벨·이름·소속·자원·보유 장수 정렬과 이름 검색을 제공한다. 일반 장수 계정에서도 타국 후보의 `등용장` 초안 모달까지 열렸고, 수신자·200자 제한·명시적 발송 단계를 확인했다. 실제 발송은 하지 않았다.
- 부대 막사는 국가 단위 부대를 보여주고 최대 인원, 부대장, 주둔 도시를 한 행에서 비교한다. 일반 장수에게도 부대 창설 입력은 보였지만 실제 제출은 하지 않았다.
- 임관 직후 한 소속 곽유지의 24턴 큐에서 슬롯을 선택하자 내정·군사·계략·이동 명령이 활성화됐다. 부대장 전용 집합은 현재 역할에 따라 비활성화되어 권한과 상태가 명령 가용성을 함께 결정한다.
- 슬롯을 선택하지 않은 동안 명령 버튼은 비활성이고, 1번 빈 슬롯을 선택한 뒤 같은 버튼들이 활성화됐다. 따라서 command capability와 command destination slot은 별도 조건이며, UI는 둘 중 어느 조건이 빠졌는지 구분해야 한다.
- 실제 활성 명령 집합은 내정 6개, 군사 8개, 계략 5개, 이동·탐색 3개, 개인 4개였다. 한 화면에 전부 늘어놓지 않고 슬롯 선택 뒤 범주를 전환하는 방식이라 24턴 큐의 세로 길이를 늘리지 않는다.
- 국가 회의실은 게시물이 없을 때도 새 글 진입점을 유지했고, 상태 작업대 하단 채팅은 `한국`, `강주성`, `개인` 채널을 같은 입력기에 연결했다. 장기 의사결정은 게시판, 즉시 조율은 채팅이라는 시간축 분리가 보인다.

관찰된 최소 capability 행렬:

| 상태/역할 | 허용 표면 | 제한 표면 |
|---|---|---|
| 국가 미소속 | 개인 성장, 기본 상태, 임관 탐색 | 국정·국가 채널·국가 봉록 |
| 일반 장수 | 회의실 읽기/글쓰기 진입, 부대 창설 진입, 등용장 초안, 내정·군사·계략·이동 명령 | 관직 임명·해임, 부대장 전용 집합 |
| 부대장 | 일반 장수 capability + 집합 | 관직에 종속된 국정 명령 |
| 군주/참모 | 조직도 읽기 + 관직 임명·해임 | 서버 외교·자원·상태 제약을 넘는 명령 |

### 임관 후 3D 전투 목적지 선택

- 강주성의 전투 명령은 서버가 허용한 인접 타국 도시인 촉 자동성 1곳만 후보로 노출했다. 지도 위 도시와 하단 후보 목록은 같은 선택 집합을 표현한다.
- 전투 모달은 처음에는 평면 표현을 열고 같은 지도에서 `3D모드`로 전환한다. 전환 후 지형 높이, 산맥, 수역, 도시 모형을 등각 격자로 읽으며 버튼은 다시 `2D모드`로 바뀐다.
- 재검증 시 3D 전환은 `1287x840` backing canvas를 `858x560` CSS 영역에 렌더했고, canvas는 비어 있지 않았으며 브라우저 warning/error가 없었다. 3D 합격 판정은 토글 문구가 아니라 canvas pixel, framing, picking 후보와 콘솔 상태를 함께 본다.
- 반면 전체 지도는 3D 상태로 열렸다. 전체 지도와 전투 모달이 모드 선호를 공유하지 않는 점은 전환 비용이므로, v2는 사용자 카메라 모드·방위·줌을 전략 지도와 명령 선택기 사이에서 보존한다.
- 이 3D는 자유 비행 카메라보다 명령 정확도를 우선한 2.5D 정사영 지휘면이다. 오픈삼국 v2는 이 가독성을 유지하되 도시 사이를 단순 정사각 칸으로 고정하지 않고 route corridor와 연속 좌표 formation으로 확장한다.
- 목적지 클릭은 명령 등록으로 이어질 수 있으므로 실제 후보는 선택하지 않았다. 분석상 필요한 계약은 `서버 허용 후보 → 3D picking → 명령 초안 → 명시적 등록`의 단계 분리다.

## 3. 묘삼과의 역할 분담

묘삼은 v2의 규칙·정보 문법을 제공한다.

- 예약턴, 도시 상태, 지도 marker, 부대 집합과 이동.
- 요격·야전·공성·농성·시가전의 전쟁 단계.
- 도시 예산, 주둔군, 수송, 건설물, 장애물과 역할 분담.

삼넷은 이 문법을 현대 브라우저에서 운용하는 상호작용 참고다.

- 상태 작업대, 즉시 피드백, 명령 큐, 일괄등록, 프리셋.
- 3D 공간에서 도시 탐색과 이동 목적지 선택.
- 기록에서 replay로 즉시 진입하는 분석 루프.
- 장수 성장과 서버 공개 사건의 연결.

따라서 묘삼의 규칙을 삼넷의 화면으로 복제하지 않는다. 묘삼의 전략 문법을 오픈삼국의 서버 권위·deterministic replay·3D 공간 모델로 다시 설계한다.

## 4. 채택 결정

### 채택

1. **3D가 v2의 기본 지도 surface다.** 전략 지도와 전술 전장 모두 같은 world coordinate 계약을 사용한다.
2. **정사영 지휘 카메라를 기본으로 한다.** 회전·틸트·줌은 허용하되, 병사 시점 자유 카메라와 cinematic은 MVP에서 제외한다.
3. **2D는 별도 제품 모드가 아니다.** WebGL 불가 환경의 정보 fallback과 접근성용 정사영 표현만 유지한다.
4. **지도 선택은 탐색과 명령을 연결한다.** 도시·관문·나루·route·formation을 picking하고, 선택 결과가 명령 초안과 작전 경로로 이어진다.
5. **명령 큐는 v1 문법을 확장한다.** drag reorder, 다중 슬롯, 일괄등록, 프리셋을 v2 대상 selector와 결합한다.
6. **전투는 replay-first다.** 실시간 화면과 replay가 동일한 event stream과 spatial snapshot을 소비한다.
7. **국가 권한은 화면 장식이 아니라 커맨드 capability다.** 관직·부대장·소속·현재 도시가 서버 허용 후보와 명령 가용성을 결정하고, 클라이언트는 그 결과를 설명한다.

### 채택하지 않음

- 삼넷의 asset, 문구, 뽑기 확률, 등급 체계, UI 배치를 복제하지 않는다.
- gacha를 v2 핵심 진척 구조로 삼지 않는다. 장수 성장은 관계·관직·전공·훈련과 연결한다.
- 클라이언트가 이동·충돌·피해를 판정하지 않는다.
- 3D를 배경 장식이나 별도 미니게임으로 만들지 않는다.

## 5. 3D 제품 계약

### 전략 지도

- 도시, 관문, 나루, 항구, 자원 거점, route corridor, 작전 경로, 보급선을 하나의 scene graph에 배치한다.
- 도시 선택은 inspect가 기본이며, 명령을 고르면 같은 선택이 목적지·작전 anchor가 된다.
- 목적지 후보는 클라이언트가 지형을 보고 추측하지 않는다. 서버가 권한·외교·인접성·보급을 평가해 반환한 후보만 scene과 대체 목록에 동시에 표시한다.
- `TemporalPlace.uncertaintyRadius`와 `terrainReconstructionStatus`를 화면에서 숨기지 않는다. 개연 생성 지형은 역사 확정 지형처럼 표현하지 않는다.

### 전술 전장

- 연속 좌표, elevation, slope, water, vegetation, road, wall, obstacle을 실제 판정과 렌더링이 공유한다.
- formation은 footprint, facing, 폭·깊이, 지휘 연결, 사기·피로·보급을 가진다.
- 전략 지도에서 선택한 교전 anchor와 route가 전술 전장 seed로 이어진다.

### replay

- replay body는 `geographyVersion`, `terrainTileVersion`, `projectionVersion`, `assetManifestVersion`을 기록한다.
- 카메라 이동은 승패 판정에 포함하지 않는다. 관전용 keyframe은 별도 presentation track으로 저장한다.
- 같은 world snapshot, 명령, seed, content version은 같은 spatial event와 결과 hash를 만든다.

## 6. 첫 구현 슬라이스

1. 실제 전체 지도가 아닌 도시 3개, route 2개, terrain patch 1개를 Three.js로 렌더한다.
2. 도시 picking, focus, hover, 명령 목적지 선택을 같은 selection contract로 연결한다.
3. formation 4개를 연속 좌표에 배치하고 이동·회전·대형 변경 명령을 서버 fixed tick으로 실행한다.
4. 작전 경로에서 전술 전장으로 진입하고 replay에서 같은 공간 상태를 재생한다.
5. 데스크톱과 모바일에서 canvas nonblank, selection 정확도, UI 겹침, camera framing을 Playwright screenshot과 pixel check로 검증한다.

## 7. 성능·접근성 gate

- 데스크톱 목표: 1080p, 60 FPS, p95 frame 20ms 이하.
- 모바일 목표: 지원 기기 30 FPS, p95 frame 40ms 이하.
- 첫 상호작용 가능한 frame: 캐시 warm 2초, cold 5초 이내.
- context loss 후 scene을 재생성하고 명령 초안·선택 상태를 복구한다.
- 키보드로 camera focus와 선택 대상 이동이 가능해야 한다.
- 저사양 fallback은 동일 read model의 정사영 정보 지도를 제공하되, simulation 규칙은 바뀌지 않는다.
