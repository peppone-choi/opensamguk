## Unit 1 — tick-pipeline (the two-level global loop + monthly orchestrator)

### Summary
The real tick entry is `TurnExecutionHelper::executeAllCommand` (`TurnExecutionHelper.php:393-517`), invoked from `proc.php:13`. It is a **TWO-LEVEL loop** that wraps what P2's `TurnRunService.runTick` ran for a single drain:
- **(A) `executeAllCommand`** = the GLOBAL turn loop + month-boundary orchestrator.
- **(B) `executeGeneralCommandUntil`** (`:233-368`) = the per-general execution pass (the P2 drain).

**Gating preamble** (`:399-436`): `now()<turntime` no-op; `tryLock()` fail; `isunited==2|3` (천통 freeze); `gameStor->cacheAll()`; `checkDelay()`; `updateOnline()`; `CheckOverhead()`; compute `prevTurn=cutTurn(turntime,turnterm)`, `nextTurn=addTurn(prevTurn,turnterm)`; compute `limitActionTime` from `max_execution_time*2/3`.

**The month-boundary `while` loop** (`:440-487`, runs while `nextTurn<=now`):
- L1. `[$over,$currentTurn] = executeGeneralCommandUntil($nextTurn,$limitActionTime,year,month)` — drains every general whose `turntime < nextTurn`.
- L2. `updateTraffic()`.
- L3. if `$over` (wall-clock budget hit): persist `turntime=currentTurn`, `unlock()`, **early-return** — THE WALL-CLOCK RESUMABILITY ESCAPE (partial month, resumed next cron).
- L4. build `$monthlyRng = RandUtil(LiteHashDRBG(hiddenSeed,'monthly',year,month))` — **MONTH-SCOPED SEED**.
- L5. `runEventHandler(PreMonth)` — fires PreMonth events (ProcessWarIncome priority 9000).
- L6. `preUpdateMonthly()` — throws `RuntimeException` after `unlock()` if returns false.
- L7. `turnDate($nextTurn)` — recompute & store year/month.
- L8. if `month==1`: `checkStatistic()` (annual snapshot BEFORE Month events).
- L9. `runEventHandler(Month)` — ALL monthly/semi-annual events, `priority DESC, id ASC`.
- L10. `postUpdateMonthly($monthlyRng)` — diplomacy/power/front/wander/emperor/tournament/auction.
- L11. advance: `prevTurn=nextTurn; nextTurn=addTurn(prevTurn,turnterm); turntime=prevTurn`.

**After loop** (`:490-516`): `turnDate(prevTurn)`; a FINAL `executeGeneralCommandUntil($date=now,...)` drains minute-granular generals past the last month boundary; `processTournament()`; `processAuction()`; `resetCache()`; `unlock()`; return turntime.

**§14 OQ RESOLVED — exact monthly side-effect ORDER:** `PreMonth events → preUpdateMonthly → turnDate → (month==1?checkStatistic) → Month events → postUpdateMonthly`. ## Unit 2 — income (ProcessIncome / ProcessWarIncome / ProcessSemiAnnual)

### Summary
**P2 ALREADY ported the income FORMULAS and the nation-type fold; P3 adds only the ORCHESTRATION (the three Action classes).** GREEN in `:logic` today: per-city + per-nation income math (`calcCityGoldIncome`/`calcCityRiceIncome`/`calcCityWallRiceIncome`, `getGoldIncome`/`getRiceIncome`/`getWallIncome`, `getOutcome`) in `IncomeTick.kt`; the `onCalcNationalIncome` hook on every `NationTypeModule` folded over the nation-type source via `nationIncomeFold`; `phpRound` (HALF_UP→Int); `getBill`/`getBillByLevel`. **P3 does NOT re-derive any formula — it WRAPS them in three sequential Event Actions.**

The THREE Actions to port (`sammo/Event/Action/`):
1. **ProcessIncome(gold|rice)** — per-nation loop over `SELECT FROM nation` (ascending id, preserve). income = `getGoldIncome(...)` (rice path ADDS `getWallIncome`); `originoutcome=getOutcome(100,generalRawList)`; `outcome=Util::round(bill/100*originoutcome)`. Then a 3-branch payout split vs `basegold(0)`/`baserice(2000)`: (a) res<base → realoutcome=0,ratio=0; (b) base ≤ res-base < outcome → realoutcome=res-base, res→base, ratio=realoutcome/originoutcome; (c) else realoutcome=outcome, res-=outcome, ratio=…. `valueFit` lower-clamps res. THEN `prev_income_gold`/`prev_income_rice = income` written to nation_env KV (history). THEN per-general payout: `gold/rice = Util::round(getBill(dedication)*ratio)`, officer_level>4 gets income log line, all get salary log line. Global history log + flush.
2. **ProcessWarIncome** — `getAllNationStaticInfo()` SKIP level<=0; income = `getWarGoldIncome` = sum of `calcCityWarGoldIncome = Util::round(onCalcNationalIncome('gold', dead/10))`; `nation.gold += income`. 3. **ProcessSemiAnnual(gold|rice)** — run(): -1% internal (agri/comm/secu/def/wall *0.99) on ALL cities + dead=0; `popIncrease()`; general upkeep `IF(res>10000,*0.97,*0.99) WHERE res>1000`; nation upkeep tiered `IF(res>100000,*0.95,IF(res>10000,*0.97,*0.99)) WHERE res>1000`. `popIncrease()` folds the POP branch: `popRatio=(30-taxRate)/200 → onCalcNationalIncome('pop',popRatio)`; pop grows secu-weighted (branches on sign of popRatio); agri/comm/secu/def/wall `*(1+(20-tax)/200)`; `trust=clamp(trust+(20-tax),0,100)`; neutral(nation=0) cities get `trust=50`.

**SCHEDULE / ORDER** (`GameConstBase.php:447-481`): pre_month → `[UpdateCitySupply][ProcessWarIncome]`. month==1 (spring) → MergeInheritPointRank, ProcessSemiAnnual gold, ProcessIncome gold, ResetOfficerLock, RaiseDisaster, RandomizeCityTradeRate, NewYear, AssignGeneralSpeciality. month==7 (autumn) → MergeInheritPointRank, ProcessSemiAnnual rice, ProcessIncome rice, ResetOfficerLock, RaiseDisaster, RandomizeCityTradeRate. **Gold income SPRING-ONLY, rice AUTUMN-ONLY, war income EVERY pre_month; SemiAnnual paired with its resource.**

## Unit 3 — city-supply-bfs (UpdateCitySupply)

### Summary
`UpdateCitySupply` is a **deterministic, NON-randomized multi-source BFS** over the static city graph that runs FIRST in the monthly tick (`GameConstBase.php:447-453`, very first action of pre_month/9000, BEFORE ProcessWarIncome). The same BFS body also lives as `checkSupply()` in `func_gamerule.php:104-172`, but `checkSupply()` STOPS at the supply-bit computation — the Event Action `UpdateCitySupply.php` is the full version that ALSO applies losses, neutralization, and the officer cascade.

**BFS algorithm** (`UpdateCitySupply.php:13-58`):
1. Build `$cities[id]={id,nation,supply=false}` from `SELECT city,nation FROM city WHERE nation!=0` (only owned cities tracked).
2. SEED queue from capitals: `SELECT capital,nation FROM nation WHERE level>0` (the **level>0 guard** — wandering forces have no supplied capital). Skip if capital absent from $cities or nation mismatch (captured); else supply=true + enqueue. **Multi-source BFS** — all valid capitals seeded before propagation; FIFO (SplQueue).
3. PROPAGATE: dequeue; resolve neighbors via `CityConst::byID(id)->path`; `foreach(array_keys($city->path) as $connCityID)`. Skip if neighbor not owned, nation mismatch (supply does not cross borders), or already supplied; else supply=true + enqueue.

**Neighbor iteration order (parity-critical):** `CityConst.path` is a name→id ordered map built in `_generate()` (`CityConstBase.php:206-210`) from the connected-city list (col 13 of each `$initCity` row, e.g. city 1 업 → ['남피','복양','호관','계교','관도']). PHP arrays preserve insertion order; `array_keys` yields ids in source-list order. **BFS neighbor order == the order cities appear in the legacy `$initCity` connection list** — already byte-faithful in P2 `CityConst.kt`.

**Persistence + loss rules** (`:60-102`): reset `supply=1 WHERE nation=0`, `supply=0 WHERE nation!=0`, then `supply=1 WHERE city IN (computed supplied)`. 10% city decay (`WHERE supply=0` multiply pop/trust/agri/comm/secu/def/wall by 0.9). 5% general decay (unsupplied cities grouped by nation: crew/atmos/train *0.95).

**Trust<30 neutralization + officer cascade** (`:104-131`): from `$unsuppliedCities` collect lostCities where trust<30; push global-history log `<R><b>【고립】</b></><G><b>{name}</b></>{josa} 보급이 끊겨 <R>미지배</> 도시가 되었습니다.`; officer reset `general SET officer_level=1, officer_city=0 WHERE officer_city IN (lostIds)`; city neutralize `city SET nation=0, officer_set=0, conflict='{}', term=0, front=0 WHERE city IN (lostIds)`.

**Front recalc is NOT inside UpdateCitySupply** — `SetNationFront($nationNo)` (`func_gamerule.php:45-102`) runs once per active nation in `postUpdateMonthly`. Supply sets front=0 on lost cities; SetNationFront re-derives (front 0/1/2/3 via diplomacy state/term + path adjacency).

## Unit 5 — trade-rate (RandomizeCityTradeRate)

### Summary
