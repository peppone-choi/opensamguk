## P5 Goal

P5 lifts the proven **per-general single-tick** framework of P0–P4 up to the **deterministic NPC AI** — the `GeneralAI` autorun that *replaces* a due general's reserved command with an AI-chosen `(actionCode, args)` BEFORE the existing `ReservedTurnHandler` executes it. The scope (design doc §11 P5 + lines 262-266):

- **AI command-selection parity.** *Which* `do<한글>` fires, *which* `che_*` command + args it emits, every RNG draw it makes (method + args + ORDER), every early-/null-return, every sort comparator. The AI mutates nothing — it CHOOSES; the existing handler resolve path (→ `ChangeRecorder` → `JdbcFlushExecutor`) executes. That isolation is the whole point.
- **The three dispatcher spines** (`chooseGeneralTurn`/`chooseNationTurn`/`chooseInstantNationTurn`) — ordered fallback chains over `do<한글>()` methods where **first non-null wins**, the `priority` array IS the dispatch order, and the dispatch order IS the log order IS the draw order.
- **Derived state** (`updateInstance` → `calcGenType`/`calcDiplomacyState`/`calcWarRoute`/`categorizeNationCities`/`categorizeNationGeneral`) — the per-AI-instance snapshot every `do<한글>` reads, with TWO distinct cache regimes.
- **~50 `do<한글>` command families** across nation (발령/포상/몰수/불가침제의/선전포고/천도) and general (내정/금쌀/징병/전투준비/출병/워프류/헌납/거병/건국/방랑군이동/해산/선양/국가선택/사망대비/중립) sides.
- **Rate/promotion helpers** (`chooseTexRate`/`chooseGoldBillRate`/`chooseRiceBillRate`/`choosePromotion`/`chooseNonLordPromotion`) — quarterly nation-turn side-effects.
- **Policy 4-layer merge** (aiOptions > nation_env KV > game_env/server > hardcoded defaults) producing the priority list + can-flags.
- **The constraint bridge** — the AI's accept/reject gate must be the *literally identical* `evaluateConstraints` call (FULL mode) that the daemon executor and the precheck UI already use.

> **DIPLOMACY RESULT IS DEFERRED TO P6 (design line 262-266).** P5 ports *whether* to emit and *which* `do<한글>` fires; P6 ports the `che_*` command-class `hasFullConditionMet()` precondition internals and the actual diplomacy/천도 state-mutation + logs. BUT the **boolean outcome** of `hasFullConditionMet()` is a P5 control-flow input (a `false` makes `do*` return null → next priority action fires → a *different* downstream draw stream), and the KV side-effects written *below* the gate (`resp_assist_try`, `last천도Trial`, `reqUpdateInstance`) only fire when it returns true. So P5 must call the gate and branch on it; the commands the AI actually emits need their FULL constraint pack ported *now*, not deferred (see GAP G5).

> **THE #1 PARITY RISK (the desync spine):** a whole AI turn runs on **ONE** `RandUtil(LiteHashDrbg(seed))` built once per general in the constructor from `simpleSerialize(hiddenSeed, 'GeneralAI', year, month, generalID)` and threaded by reference through `calcGenType` and every `do<한글>` — never re-seeded. Every draw funnels through this single stream, so byte-parity reduces to **did the Kotlin port pull draws off this stream in the identical ORDER, COUNT, and METHOD.** A single conditional draw that appears/disappears (the `calcGenType` near-balance `nextBool`, a `&&`-short-circuited `nextBool` whose left operand diverges, a `nextBool(prob)` where `prob` crosses the `>=1`/`<=0`/`===0.5` no-draw/bit boundary, a variable BFS `choice` count) shifts the entire downstream stream and silently desyncs the rest of the turn. **This is the same discipline as P4's `processWar_NG`, but the stream is per-general-per-turn instead of per-battle.**

P5 **extends, never reshapes, the proven P0–P4 framework.** Directly reused, not rebuilt:

- **`RandUtil` / `LiteHashDrbg` / `SeedSerializer`** (`RngKernelParityGateTest`, P0-B GREEN): `nextBool` PHP branch order (prob≥1 → true NO-draw, ===0.5 → `nextBit` 1-bit, ≤0 → false NO-draw, else `nextFloat1()<prob`); `choice(list)=items[keys[nextInt(size-1)]]`; `choiceUsingWeight(Map)` = one `nextFloat1()*sum` then insertion-order walk returning the KEY; `choiceUsingWeightPair(List<Pair>)` = same, returns the pair's item; `nextRangeInt(min,max)=nextInt(max-min)+min`. **No new RNG primitive is needed for P5** — every AI draw (`nextBool`, `choice`, `choiceUsingWeight`, `choiceUsingWeightPair`, `nextRangeInt`, `nextFloat1`) is an existing primitive. (`common/rng/RandUtil.kt` already exposes all of them.)
- **`serializeSeed(vararg)`** (`common/rng/SeedSerializer.kt`) — the `Util::simpleSerialize` byte-format `str(len,v)|int(v)`; the AI seed is `serializeSeed(hiddenSeed, "GeneralAI", year, month, generalId)`. The seam exists, just unwired.
- **`PhpRound`** (HALF_AWAY-from-zero) + `Util::valueFit`/`clamp` + `Util::toInt` (intval truncate-toward-zero) + `intdiv`. `maxResourceActionAmount = round(...,-2)`, `do징병` `round(crew-49,-2)`, bill `intval(income/outcome*90)`, `getDedLevel` `ceil`, `getOutcome` `round` ALL reuse these — **do NOT introduce `Math.round` (half-up) — the TS `aiUtils.roundTo` is half-up and is WRONG everywhere; PHP wins.**
- **`GeneralActionPipeline` / `getStatValue`** (P2/P3): the AI reads `leadership/strength/intel` (with-injury) AND `fullLeadership/fullStrength/fullIntel` (`getX(false)` = no-injury) via the existing fold; `onCalcDomestic('징집인구','score',100)` gates candidate membership in several 발령 methods. P5 only wires the call convention.
- **`evaluateConstraints` + `MemoryStateView`/`WorldStateViewAdapter`** (P1/P2): the AI's `hasFullConditionMet()` analogue IS `evaluateConstraints(def.buildConstraints(ctx), ctx, view)` in FULL mode — the *identical* call `ReservedTurnHandler` and `CommandPrecheckService` already make.
- **`CommandRegistry` + `GeneralActionDefinition` + `NationCommand`** (P2/P4): ~45 commands wired; the AI picks `(actionCode, args)`, the registry resolves+constructs the def the daemon runs. AI never re-implements a command body.
- **`InMemoryTurnWorld` / `ChangeRecorder` / `ReservedTurnHandler` / `TurnDaemonLifecycle` / `TurnRunService`** (P1–P4): the AI is read-only over the world; the chosen command's resolve runs the EXISTING delta path. The interpose seam is `TurnDaemonLifecycle.reservedActionOf` (the `(generalId)->String` hook).
- **`ActionLogger` + ConvertLog/Josa** (P0-B): `reason` tags + deny logs reuse the color-tag + 조사 model.
- **`tools/php-golden`** Docker capture harness: generalize to capture the per-general AI **draw stream** (method + args + result, tagged by firing `do<한글>` reason) for draw-for-draw replay (the P5 gate).

**The AI is SEQUENTIAL / draw-order-preserving.** There is no parallelism inside a single general's turn: each `do<한글>`'s draws feed the next read; the priority loop short-circuits on first non-null; `categorizeNationGeneral` mutates `nationCities['important']`/`['generals']` by reference (cities MUST exist first). The only fan-out P5 admits is across *research/plan families* (nation-deploy vs nation-reward vs nation-diplo vs gen-domestic vs gen-war-move vs gen-found vs rates-promo), NOT across the per-general decision sequence.

## Architecture & per-turn lifecycle

### updateInstance → derived state → dispatchers

`GeneralAI` is constructed **per due general** (`__construct(General)`, GeneralAI.php:147-168), replaces the reserved command with an AI-chosen one, and is invoked from the turn loop. The lifecycle:

1. **`__construct`** (147-168): `env = gameStor.getAll(true)`; build the SOLE `rng` (seed §7 above); cache `leadership/strength/intel` (`getX()` WITH injury) + `fullLeadership/fullStrength/fullIntel` (`getX(false)` no-injury). **No rng draw in ctor.**
2. **`updateInstance()`** (86-145, guarded by `reqUpdateInstance` → runs once unless re-dirtied): `baseDevelCost`; city row; nation row (21-col explicit list ?? neutral-default `재야` nation=0/level=0); `nationStor` KV cache; `nationPolicy`/`generalPolicy`; `maxResourceActionAmount`; `nation.aux` JSON-decode in place; `calcDiplomacyState()` (NO draw, sets `dipState`/`attackable`/`warTargetNation`, MAY write `last_attackable` KV); `genType = calcGenType()` — **the FIRST rng draw site.**
3. **Dispatcher** (`chooseGeneralTurn` / `chooseNationTurn` / `chooseInstantNationTurn`): the ordered fallback chain in §3. Each `do<한글>` draws on the same `rng`; order across them = the priority foreach order.

`reqUpdateInstance` dirty triggers (re-run updateInstance next access): GeneralAI.php lines **1308, 1509, 1972, 1990, 2113** (긴급포상 ×2, 선전포고, 천도 ×2 — commands that change the general's resources/nation). `categorizeNationCities`/`categorizeNationGeneral`/`calcWarRoute` are NOT cleared by these.

### Two distinct cache regimes (parity-critical)
- **`reqUpdateInstance` boolean** gates the `updateInstance` block (city/nation/policy/genType/dipState/maxResource) — re-runs when a command set it dirty.
- **Per-field null-guards** gate `categorizeNationCities`/`categorizeNationGeneral`/`calcWarRoute` — computed once, never re-invalidated within an instance, even if `reqUpdateInstance` later flips. Do not couple them.

## Derived state

### genType — `calcGenType` (175-204) — the FIRST rng draw, conditional
Inputs (all `getX(false)` = no-injury, item/adjust/floor ON): `leadership`, `strength=valueFit(getStrength(false),1)`, `intel=valueFit(getIntel(false),1)`. Flags `t무장=1, t지장=2, t통솔장=4` (bitwise `|=`). Branch:
- `strength >= intel` → `genType=t무장`; **if `intel >= strength*0.8`** (near-balanced) → **DRAW `nextBool(intel/strength/2)`** → `|=t지장`.
- else → `genType=t지장`; **if `strength >= intel*0.8`** → **DRAW `nextBool(strength/intel/2)`** → `|=t무장`.
- then (NO draw) `if leadership >= minNPCWarLeadership → |=t통솔장`.

**Exactly 0 or 1 draw in the whole derived-state phase** (the single conditional `nextBool` in calcGenType, prob in [0.4,0.5) when the band holds). The danger is purely the *presence/absence* of that one draw (it shifts the shared stream for every later command) and its exact float arg. ⚠ Stat-flavor mapping is unresolved — see GAP G8.

### diplomacy state — `calcDiplomacyState` (206-281) — NO draws
