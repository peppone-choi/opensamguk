# OPENSAM-194 [R7] 1단계 설계 — v2 도시 원장 자재 자원(목재·석재·철재)

작성 2026-08-17 · 대상 티켓 `OPENSAM-194` 1단계(설계) · 정본 `docs/loops/v2-planning-2026-07-12/round3-proposal-city-guanxi.md` §2.1·§8

## 0. 결론 먼저

1. **석재(stone)는 넣지 않는다.** 어떤 정본에도 없다. 넣으면 값·생산원·소비처를 전부 지어내야 한다.
2. **목재(wood)·철(iron)은 정본이 있다** — v2 PRD §3.2 자원 4종 표(금·쌀·철·나무). 다만 그 표가
   지정한 생산원(벌목장·철광산·제철소)과 소비처(건설·공성병기·병기 제작·특수병종)는 **아직 하나도
   구현돼 있지 않다.** 콘텐츠 카탈로그(`OPENSAM-53` 시설 48)와 공성(`OPENSAM-171`)이 선행이다.
3. 따라서 **지금 컬럼만 추가하면 설계안 §8 LEDGER 규칙 4가 요구하는 "결정→판정→상태변화"가 없는
   죽은 숫자**가 된다. 원장의 기존 3값(금·병량·도시병사)은 전부 소비처가 있다.
4. **권고: OPENSAM-194 2단계(구현)를 "첫 소비처 티켓과 같은 웨이브"로 묶는다.** 컬럼·store·flush·
   read를 소비처 없이 먼저 넣는 것은 스키마 부채이고, 소비처가 정해질 때 컬럼 의미가 바뀔 수 있다.

## 2. PRD가 실제로 말하는 것 (§3.2 자원 시스템)

| 자원 | 주 생산원 | 주 소모처 | 부피 |
|---|---|---|---|
| 금 (gold) | 시장, 광산, 세금 | 병력 유지, 외교, 건설, 가신 | 1 |
| 쌀 (rice) | 농지, 축사, 벼농장, 어획항 | 병력 급식, 인구 | 1 |
| 철 (iron) | 철광산, 제철소 | 병기 제작, 특수병종 | 2 |
| 나무 (wood) | 벌목장 | 건설, 공성병기 | 2 |

부수 규정: 3계층 보유(도시/국고/장수 개인 창고), `warehouse_capacity` 기본 5000,
부피식 `gold*1 + rice*1 + iron*2 + wood*2 ≤ capacity`, 자원 이동 커맨드 8종(증여·헌납·포상·몰수·
물자조달·물자원조·탈취·군량매매).

→ **자재는 2종(철·나무)이고, 티켓 제목의 "3자원(목재·석재·철재)"은 유저 제안 표현이다.** 석재는
PRD에도 없다. 철재/목재라는 이름도 PRD는 "철/나무"로 쓴다 — 컬럼명은 PRD를 따라 `iron`/`wood`.

## 3. 현재 v2 원장이 어디까지 와 있나 (구현 실측)

- 표: `infra/src/main/resources/db/migration_v2/V901__v2_city_ledger.sql` —
  `(world_id, city_id)` PK + `gold bigint` / `rice bigint` / `garrison integer`.
- 메모리 보유자: `app/game-engine/.../v2/V2CityLedgerStore.kt` — `V2CityLedgerEntry(gold, rice, garrison)`,
  `adjust(...)`가 세 값 델타를 받고 `coerceAtLeast(0)` 후 **절대값 UPSERT 델타**를 `ChangeRecorder`에
  기록한다(직접 쓰기 없음 = one-daemon-write rule).
- 생산: `V2ProcessCityIncome.kt` (R2) · 소비: `V2GarrisonRecruitHandler.kt` (R4, 금 → 도시병사) ·
  이동: `V2CityTransportRules.kt`/`V2CityTransportHandler.kt` (R5) · 열람: `V2CityLedgerReadController.kt` (R6).

즉 기존 3값은 각각 **생산·소비·이동·열람**이 전부 붙어 있다. 자재 2종에는 그중 아무것도 없다.

## 4. 자재를 넣으려면 무엇이 선행돼야 하나

| PRD가 지정한 경로 | 지금 상태 | 선행 티켓 |
|---|---|---|
| 생산: 벌목장·철광산·제철소 (시설) | v2 시설 카탈로그 미구현 | `OPENSAM-53` (core 시설 48 [T-FAC]) |
| 소비: 건설 | v2 도시 건설(CityProject) 계약 동결 단계 | `OPENSAM-74` (P-9 CityProject) |
| 소비: 공성병기 | 공성 adapter 미착수 | `OPENSAM-171` [V2-4B-SIEGE] |
| 소비: 병기 제작·특수병종 | 병종 72 엔트리 미구현 | `OPENSAM-52` [T-ENTRY] |
| 이동: 자원 이동 커맨드 8종 | R5는 금·병량·병사만 | `OPENSAM-154` 확장 |

**대체 경로를 억지로 만들지 않는다.** "지금 있는 것만으로 닫히는 최소 루프"를 찾아봤으나 없다 —
성벽·수비 개발은 v1 커맨드라 편집 금지(ADR-LITE-018), R4 병사보충은 PRD상 금 소비이고 자재를
끼워 넣을 근거가 없다. 도시 지역(`City.region` 7종)이나 크기로 산출을 나누는 안은 **수치가 전부
UNKNOWN**이라 §5 기준선("v1 수치를 입력으로 삼거나 값을 지어내면 보류")에 걸린다.

## 5. 그럼에도 지금 확정해 둘 수 있는 것 (구현 착수 시 그대로 쓰는 결정)

이 절은 **소비처 티켓이 붙는 순간 바로 쓰도록** 미리 못 박아 두는 것이며, 지금 코드를 넣자는 뜻이 아니다.

1. **자원 2종, 이름은 `wood`/`iron`** (PRD 표기). `stone`은 도입하지 않는다 — 필요해지면 그때
   출처를 만들어(오픈삼국 독자 divergence로 명시) 별도 티켓으로 연다.
2. **타입**: `wood bigint NOT NULL DEFAULT 0`, `iron bigint NOT NULL DEFAULT 0` — 금·병량과 같은
   `bigint`. 도시병사만 `integer`인 것은 병사 수의 물리 상한 때문이므로 자재는 금 쪽을 따른다.
3. **마이그레이션**: `V901` 수정 금지. `migration_v2/V9xx__v2_city_ledger_materials.sql` 신규,
   forward-only(롤백은 보상 마이그레이션) — `migration_v2/README.md` 규약 그대로.
4. **초기값 0.** 시드가 자재를 심지 않는다. 도시 원장 base는 이미 금·병량 모두 0으로 정해져 있다
   (설계안 §2.1 각주 1, "v2 도시별 base는 금·병량 모두 0 — 묘섭 미규정, 오픈삼국 결정").
5. **상한 없음(도시 원장 한정).** PRD의 `warehouse_capacity` 5000·부피 2는 **장수 개인 창고**
   규정이지 도시 원장 규정이 아니다. 도시 원장에 상한을 두려면 별도 근거가 필요하다 — UNKNOWN.
6. **음수 금지**는 기존 `adjust`의 `coerceAtLeast(0)`를 그대로 확장한다.
7. **수송(R5)은 소비처가 생긴 뒤에 연다.** 소비처 없는 자재를 옮기는 기능은 그 자체로 죽은 루프다.
8. **열람(R6)은 구현 웨이브에서 같이 붙인다** — 값이 도는 순간부터 화면에 보여야 한다
   (`V2CityLedgerReadController` + `web/game` v2 패널 컬럼 2개).

## 6. 불변(비범위)

v1 PHP 패러티 무변경 · `logic/`·골든·RNG·로그 무편집 · one-daemon-write rule 유지 ·
v2 격리 게이트 ②③⑤ green · 값 날조 금지(근거 없으면 UNKNOWN 표기).

## 7. 남긴 판단 (사람이 정할 것)

- **A안(권고)**: 2단계 구현을 첫 소비처 티켓(`OPENSAM-53`/`171`/`74` 중 먼저 오는 것)과 같은 웨이브로
  묶는다. OPENSAM-194는 그때까지 `blocked-by`로 둔다.
- **B안**: 지금 컬럼+store+flush만 넣고 값은 항상 0으로 둔다. 스키마가 미리 준비되지만 §8 규칙 4를
  어긴 죽은 숫자가 한동안 남고, 소비처 설계가 컬럼 의미를 바꾸면 다시 마이그레이션해야 한다.

A안을 권고한다. 자재는 "표시만 되는 숫자"로 시작하면 되돌리기가 더 비싸다.
