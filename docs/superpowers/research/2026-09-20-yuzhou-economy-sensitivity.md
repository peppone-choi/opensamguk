# 예주 월세입·모집·군량 정산 실험 — 2026-09-20

상태: **EXPLORATORY**. S2의 경제 수치 선택을 위한 계산이며 제품 규칙·S2 통과·런타임 구현이 아니다.

`tools/sim/county_economy.py`의 `settle_county`는 외부에서 지정한 월세입·수송 도착·모집 주문을 순별로 정산한다. 정수 인구·추상 군량 단위를 쓰며 호수 환산은 하지 않는다. 이 실험의 순서는 수송 도착 → ID순 모집 → 군량 소비 → 월 세입이다. 군량 소비 뒤 월 세입은 승인 spec §5.2의 단계1→4를 따른다. 모집의 경계 내 위치는 별도 실험 가정이며 월 녹봉·유지비는 계산하지 않는다. 모집할 인원이나 군량이 부족하면 둘 다 차감하지 않는다. 같은 주문 ID는 최초 거절도 포함해 한 번만 처리하며, 병력·비용을 바꿔 재전달하면 전체 입력을 거절한다. 군량 부족은 미충족 수요로 남고 사망·탈영·함락을 추론하지 않는다. 저장·재시작을 포함한 실제 엔진 멱등성 검증은 아직 아니다.

## 육상 경로 지연 수송과 성 안 군량의 합성

`tools/sim/convoy_schedule.py`는 초기 창고에서 1순에 보낼 군량을 예약하고 `1 + travelTurns`순에 목적지로 전달한다. 초기 재고 부족과 경로 없음은 출발 전에 거절한다. 이동 중 물자는 도착 전에 소비하거나 다시 발송할 수 없고, 관측기간 밖 도착도 이동 중 재고에 남긴다. 누적 도착량(`ledger.arrived`)과 해당 순 도착량(`arrivals[county][turn]`)은 구분한다. 이는 최초에 재원을 확보한 수송 실험이며 매순 자동 보급, 약탈·경로 변경·손실을 구현하지 않는다.

예주81縣 각각을 목적지로 삼는 독립 실험을 5가지 조건으로 수행했다. 각 사례는 81縣 전체 창고를 정산하지만 81개 동시 포위가 아니다. 대상 縣은 세입이 끊기고, 초기 재고로 모집 비용과 **18순분** 군량을 갖는다. 구원 물량은12순분이다. 그 외 縣은 앞의100호당25명·호당 월100단위 조건을 유지한다. 18순분을 설정해서19순에 부족해지는 것은 계산 구성의 결과이지 12–24순 함락 목표의 검증이 아니다.

### 월수입 처리 순서 정정

초기 실험의 `도착·세입 → 모집 → 군량` 순서는 승인 spec §5.2의 `순 보급·군량 소비 → 월수입`과 달랐다. 모델을 `수송 도착 → 모집 → 군량 → 월 세입`으로 수정했다. 빈 창고에 같은 경계의 세입이 도착해도 그 경계의 군량 부족이나 모집 거절을 소급 취소하지 않으며, 세입은 마감 재고에 보존되어 다음 순부터 사용할 수 있다. 월 경계의 별도 녹봉·유지비를 군량에 합치지는 않았다. 변경 전 두 적색 테스트로 선지출을 재현했고 수정 후 통과했다. 최초 기준 SHA의 결과는 당시 실험으로 보존하고 최종 재산출 SHA·해시는 메타 실행 기록과 evidence에서 확인한다.
