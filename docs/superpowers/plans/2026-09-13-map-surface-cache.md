# 2D 지도 정적 레이어 재사용

**Goal:** 드래그마다 지형·영토색·국경 전체를 다시 그리는 병목을 제거한다.

**Architecture:** 도시·깃발·선택 영역은 기존 프레임 루프에서 갱신한다. 지형·영토색·국경은 뷰포트 주변의 단일 제한 해상도 캔버스에 저장한다. 데이터/스타일/배율/픽셀 밀도 변경 또는 저장 영역 이탈 시 다시 그린다.

**Tech Stack:** React, TypeScript, Canvas 2D, Vitest, Chromium.

**Spec:** 사용자 승인 전체 목표 2항(지도 성능 및 모바일 조작 개선). 기존 정치·중립 관할 규칙은 변경하지 않는다.

## Constraints

- 캐시 한 개당 최대 4,194,304 픽셀(16 MiB RGBA), 한 변 최대 4096.
- 2026-09-20 갱신: 큰 뷰포트는 지형 캐시의 유효 DPR을 낮춰 예산 안에서 화면 가로·세로 1.5배의 패닝 여유 영역을 유지한다. 예산에 맞으면 장치 DPR을 그대로 사용한다. 축소된 캐시는 보간해 확대하고 도시·이름·클릭 좌표는 기존 장치 해상도 렌더 경로를 유지한다.
- 2D 컨텍스트 생성 실패 시 직접 렌더 fallback은 유지한다. 메모리 상한은 지형 캐시 한 장 기준이며 메인 캔버스·스프라이트·GPU 복사는 포함하지 않는다.
- 줌/핀치 개선이나 모바일 실기기 검증을 캐시 내 드래그 측정으로 대체하지 않는다.
- 캐시 재사용과 데이터 무효화가 도시 hit target 갱신을 막지 않아야 한다.

## 2026-09-20 청크 캐시 갱신

2D 렌더러는 단일 viewport surface 대신 512×512 청크 최대 16개를 사용한다(총 RGBA 16 MiB). 한 픽셀 gutter와 장치 픽셀 경계 clip으로 이음새를 막는다. 화면 안을 먼저 채우고 이웃 영역을 예열하며, 프레임당 한 청크만 생성한다. 줌 중에는 기존 청크를 변환해 표시하고 마지막 입력 120ms 뒤 정밀 청크를 갱신한다. 처음 방문한 미생성 영역은 배경으로 남았다가 점진적으로 채워진다. 구역 생성 자체의 시간 상한과 Windows 실기기 FPS는 별도 측정이 필요하다.

## 2026-09-20 데이터 재사용·정치 레이어 분리

지형 청크는 grid와 sprite 변경에만 무효화한다. 정치색·국경은 원래 그리기 순서로 합성 bitmap에 캐시하며, 세력색 변경 시 지형을 다시 그리지 않는다. 지형16MiB와 합성16MiB로 RGBA 상한은 합계32MiB다. 두 이미지는 함께 폐기한다. 메인 캔버스·sprite·GPU 복사본은 별도다.
