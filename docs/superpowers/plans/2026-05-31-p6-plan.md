# P6 Execution Plan — Foundation-First (diplomacy + messaging + auction + betting + inheritance + worldCommand/pools)

> Branch: `p6-diplomacy-economy` (off `p4-battle-engine`/`main`). One logical commit per task. Every commit ends with the Co-Authored-By trailer.
> Build verify: `JAVA_HOME=$(/usr/libexec/java_home -v 21) ./gradlew :<module>:test 2>&1 | tail -40` — grep `BUILD SUCCESSFUL` + counts (exit-0 unreliable).
> Companion research: `docs/superpowers/research/2026-05-31-p6-research.md`.
> Design ref: `docs/superpowers/specs/2026-05-29-devsam-opensamguk-kotlin-migration-design.md` §11 (P6).

**Decomposition rule (load-bearing).** Every shared extension point is built in the **Tier-0 foundation wave** (sequential, creator-then-consumer). Parallel leaf families never co-widen a shared file. The biggest missing seam is the **nation-command resolve path has no draft/log/delta plumbing** — Tier-0 builds it before any leaf.

## THE P6 GATE (per design doc §11)

A P6 sub-domain is **done** only when ALL hold (else gaps quarantined-with-proof + logged to the phase backlog):

1. **Draw-for-draw.** The 3 daemon-stream RNG sites (registerAuction order in the monthly tick, obfuscatedNamePool 6525-shuffle + DRBG cursor, startBetting per-NPC choice) byte-match PHP draw-for-draw. The api-ephemeral sites (ResetTurnTime/ResetStat/voteReward/builder) byte-match with pinned seeds. NoRNG paths **assert zero draws** (throw-on-draw).
2. **Number parity.** Diplomacy state/term transitions; auction escrow/swap/refund + `Util::round(-1)` nearest-10; betting tiered-halving float math + `Util::round` half-away; inheritance derived-keys (dex /3 overflow, betting pow²) + `Util::toInt(Σ)` truncation — all exact.
3. **Byte parity.** Every Korean log + Message text (josa 이/와/을/로/라, 【선포】/【파기】/【종전】/【천도】/【보물수배】/【내기】/【설문조사】, color/tag markup) byte-identical; log ORDER = execution ORDER; jsonb key insertion order preserved (LinkedHashMap, never re-keyed).
4. **Restart-rehydrate lossless.** Daemon restart re-reads obfuscatedNamePool from KV (no re-shuffle), survivor inheritance_* intact, active auction/betting/message pools rehydrated; a flush→reload cycle reconstructs polymorphic Messages via buildFromArray.
5. **CQRS double-spend safe.** Accept-flow + spend APIs hold a per-user advisory lock (PHP GAME_LOGIN-lock parity); all daemon writes flow through `ChangeRecorder → JdbcFlushExecutor` (the ONE-daemon-write rule — architecture-test-enforced); bidirectional diplomacy updates BOTH keys; ng_betting upsert amount+= (no double-insert); inheritance survivor tables never truncated.
6. **No collision.** The per-command diplomacy UPDATE delta and the monthly bulk-SQL tick must not corrupt each other (flush-order regression test green).
