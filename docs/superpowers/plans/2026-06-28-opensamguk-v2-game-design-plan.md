# 오픈삼국 v2 게임 기획안

> 작성일: 2026-06-28
> 상태: draft
> 근거: `docs/superpowers/research/2026-06-27-v2-samnet-myosam-gap-design.md`, `docs/wiki/raw/myosam-help/`, `/Users/apple/Downloads/files/` raw copy
> 원칙: v1 패러티는 보존하고, v2는 별도 제품 방향으로 설계한다.

## 1. 한 줄 정의

오픈삼국 v2는 삼모전의 장수 턴 입력 감각을 유지하되, 전쟁을 전장 상태 머신으로 만들고, 플레이어 아래의 가신·추종·봉신이 제안과 이해관계로 움직이는 실시간 봉건 정치 전쟁 게임이다.

## 2. 기획 목표

1. **삼모의 익숙함을 잃지 않는다.** 장수, 세력, 도시, 턴 예약, 상/중/하순, 정세 로그, 회의실 같은 문법은 유지한다.
2. **전쟁을 결과표가 아니라 사건으로 만든다.** 출병은 접근, 정찰, 요격, 야전, 공성, 시가전, 전후 처리로 쪼개지고 리플레이로 남는다.
3. **NPC를 숫자 보조가 아니라 관계 주체로 만든다.** 가신은 조언하고, 반대하고, 편향되고, 임무를 수행하며, 때로는 플레이어 판단을 흐린다.
4. **세력 내부를 비운 칸으로 두지 않는다.** 국가는 도독부, 봉토, 봉신 계약, 중앙 명령과 지방 자율성으로 구성된다.
5. **런타임 LLM은 쓰지 않는다.** 제안, 회의 발언, 전쟁 서사는 deterministic rule score와 템플릿으로 만든다.

## 3. 입력 근거와 v2 흡수 방향

v2는 v1 패러티 작업을 대체하지 않는다. v1은 PHP `legacy/devsam-core`를 byte 단위로 따라가는 이식선이고, v2는 samnet 공개 표면, myosam 도움말, 다운로드된 v2 PRD/ROADMAP에서 얻은 좋은 개념을 별도 제품 방향으로 흡수하는 확장선이다.

| 입력 | 관측/요구 | v2에 넣을 것 | v1과 분리할 것 |
|---|---|---|---|
| samnet 현재 공개 화면 | 첫 화면에서 날짜/순, 2D 지도 토글, 최근 정세, 최근 전쟁 로그가 바로 보인다. | 랜딩 대신 게임 현황 대시보드, 지도 모드, 정세/전쟁 타임라인을 첫 화면에 배치. | v1 PHP 화면 byte 패러티 요구로 보지 않는다. |
| myosam 도움말 37페이지 | 예약턴, 관직, 지휘부, 부대, 요격/농성/공성, 건설물/장애물, NPC 관리가 상세하다. | 전쟁 phase, 부대 전술, 관직/권한, NPC/위임 플레이를 v2 시스템의 근거로 사용. | 원문 UI/자산/명칭을 그대로 복제하지 않는다. |
| 다운로드 PRD/ROADMAP | 실시간 tick, 3D 지도, 추종+가신 2트랙, 창고/건설/황제제/명령 코드젠이 제안되어 있다. | 추종/가신, replay-first 전쟁, 실시간 이벤트, 3D 지도는 v2 방향으로 채택. | 첫 MVP에서 3D 지도와 전체 명령 70개를 선행하지 않는다. |
| 사용자 추가 요구 | 가신 상호작용, 명령/제안, 편견/어전회의, 부세력/봉건제, 동적 전쟁. | v2 핵심 차별점으로 승격. 기획과 schema 첫 스파이크의 중심으로 둔다. | 단순 버프, 단순 추천 UI, 깡대깡 전투로 축소하지 않는다. |

## 4. 플레이어 판타지

플레이어는 한 명의 장수로 시작한다. 처음에는 자기 턴에 내정, 이동, 전투 명령을 넣는 익숙한 삼모 플레이를 한다. 시간이 지나면 추종 장수와 가신을 얻고, 작은 부대를 운영하고, 도시를 맡고, 봉토를 받거나 도독부를 이끌게 된다.

후반에는 플레이어가 군주가 되거나 강력한 봉신이 된다. 이때 게임의 재미는 "내가 클릭한 명령 하나가 바로 실행된다"가 아니라 "내 명령이 가신, 도독부, 봉신, 보급, 전장 정보, 관계 편향을 통과하면서 실제 세계에서 어떤 결과로 굴절되는가"가 된다.

## 5. 핵심 차별점

### 5.1 동적 전쟁

기존 전투가 병력과 능력치의 일회성 충돌처럼 보였다면, v2 전쟁은 여러 단계의 전장 절차다.

전쟁 한 건의 기본 흐름:

1. **전쟁 의도**: 공격 목표, 동원 부대, 지휘관, 보급 출처, 전술 방침을 정한다.
2. **접근/기동**: 이동 경로, 지형, 기상, 정찰 수준, 차단 가능성을 계산한다.
3. **조우/요격**: 수비 측 정찰과 요격 방침에 따라 야전, 기습, 회피, 공성 진입을 결정한다.
4. **야전**: 병종 상성, 진형, 장수 전술, 사기, 지형이 개입한다.
5. **공성/농성**: 성벽, 요새, 공성병기, 도시 병사, 방어 시설이 작동한다.
6. **시가전**: 성내 돌입 후 치안, 민심, 창고, 건물 피해, 약탈/보호 선택이 발생한다.
7. **전후 처리**: 포로, 부상, 전공, 보급 손실, 도시 소유권, 정세 로그, battle replay를 확정한다.

기획상 중요한 점은 첫 버전부터 수식을 복잡하게 만드는 것이 아니다. 중요한 것은 **전쟁을 단계별 replay로 남기는 구조**를 먼저 고정하는 것이다. 수치 모델은 점진적으로 깊어져도 replay schema는 흔들리면 안 된다.

### 5.2 가신과 추종

부하 시스템은 두 트랙이다.

| 구분 | 정의 | 플레이 감각 |
|---|---|---|
| 추종 | 기존 장수/NPC/재야가 플레이어에게 서약한 독립 행동 주체 | 같이 이동, 동시 침공, 집결, 임무 수행 |
| 가신 | 플레이어 개인 휘하의 비독립 NPC 보좌관 | 조언, 보정, 대행, 탐색, 외교 보조, 편향된 제안 |

가신 유형:

| 유형 | 주 역할 | 대표 제안 | 대표 편향 |
|---|---|---|---|
| 참모 | 전략 판단 | "지금은 공성보다 보급로 차단이 낫습니다" | 장기 효율 과대평가 |
| 호위 | 생존/위험 관리 | "이 이동은 매복 위험이 큽니다" | 군주 신변 위험 과대평가 |
| 군수관 | 자원/보급 | "서부 전선 쌀이 2순 뒤 고갈됩니다" | 보급 부족 시 공격 강하게 반대 |
| 정찰 | 정보/탐색 | "적 요격 장수가 빠져 있습니다" | 불확실한 정보도 기회로 볼 수 있음 |
| 사신 | 외교/교섭 | "A세력과 3개월 휴전이 가능합니다" | 외교 해법 과대평가 |

가신은 단순 버프가 아니라 다음 값을 가진다.

- 충성: 배신/이탈/명령 왜곡 가능성.
- 신뢰: 플레이어와 정보 공유 깊이.
- 야망: 독립, 보상, 관직 요구.
- 기질: 신중, 과감, 명예, 실리, 복수심.
- 전문성: 전쟁, 내정, 외교, 보급, 첩보.
- 편견: 출신, 관계, 최근 피해, 직책, 성격 기반 판단 가중치.

### 5.3 어전회의와 편견

어전회의는 "정답 추천 UI"가 아니다. 서로 다른 이해관계와 정보 수준을 가진 인물들이 같은 의제에 대해 다르게 해석하는 장치다.

회의 흐름:

1. 의제가 생성된다. 예: 선전포고, 휴전, 수도 이전, 봉토 회수, 대규모 원정.
2. 참석자가 구성된다. 군주, 수뇌, 관련 태수, 가신, 봉신 대표.
3. 각 참석자가 의견을 낸다. 찬성/반대/보류와 confidence를 가진다.
4. 편견 요인이 공개된다. 예: "군수관: 보급 부족 -35", "호위: 군주 위험 -20".
5. 플레이어 군주라면 직접 결정한다. NPC 군주라면 ruler AI가 점수 합산으로 결정한다.
6. 결정은 명령 큐나 정책으로 변환된다.

UI 목표는 "누가 맞는지"보다 "왜 저렇게 말하는지"를 보여주는 것이다.

### 5.4 도독부와 봉건제

v2 국가는 단일한 자원 덩어리가 아니다. 국가 안에는 봉토, 군단, 문벌, 속령, 개인 세력이 존재한다.

플레이어에게 보이는 대표 명칭은 **도독부**로 둔다. 다만 내부 모델명은 `subfaction`을 유지한다. 도독부는 "국가 안에서 중심 도시와 병력, 재정, 자율권을 가진 준독립 군정 단위"이고, 봉토나 문벌 같은 다른 하위 집단까지 모두 흡수할 수 있는 상위 모델이 `subfaction`이다.

핵심 개념:

| 개념 | 설명 |
|---|---|
| 도독부 | 한 국가 내부의 준독립 군정 집단. leader, 중심 도시, 자율성, 병력, 자원 배분율을 가진다. |
| 봉토 | 도시 또는 도시 묶음을 장수/도독부에게 맡긴 단위. 세금, 징병, 건설 우선순위가 분리된다. |
| 봉신 계약 | 주군과 봉신 사이의 조공, 원군, 외교권, 독립권, 배반 조건. |
| 중앙 권위 | 군주의 명령이 지방에 얼마나 빠르고 정확히 전달되는지 결정한다. |
| 자율성 | 봉신이 중앙 명령을 지연, 축소, 왜곡, 거부할 수 있는 정도. |

게임 효과:

- 군주는 모든 도시를 직접 클릭하지 않는다. 태수와 봉신에게 위임해야 한다.
- 강한 봉신은 전쟁을 도와주지만, 너무 강하면 중앙을 위협한다.
- 낮은 충성의 도독부는 원군을 늦게 보내거나 독자 휴전을 시도한다.
- 봉토 회수는 단기적으로 중앙 권한을 높이지만 반란 위험을 만든다.

### 5.5 병력 소속과 예비군

전투 격자에는 "장수당 유닛 1개, 칸당 유닛 1개"만 올라온다. 따라서 예비군은 전장 유닛이 아니라 **병력 풀**이다. 이 풀에서 장수 유닛을 보충하거나, 도시 수비 NPC 유닛을 생성하거나, 도독부 원군을 동원한다.

| 병력 풀 | 소속 | 전장 반영 |
|---|---|---|
| 중앙 예비군 | 국가 직할. 군주/수뇌가 배정한다. | 장수 유닛 보충, 중앙 원군, 수도 방어 증원. |
| 도독부 예비군 | 도독부/봉토 소속. 도독 또는 봉신이 통제한다. | 원군 수락/지연/축소의 실제 자원. |
| 도시 예비군 | 도시 소속. 태수와 도시 시설이 관리한다. | 도시 수비 NPC 유닛, 공성전 보충, 치안 회복. |
| 장수 사병 | 장수 개인 소속. 추종/봉신의 독자 전력. | 해당 장수의 전투 유닛 HP/병력으로 반영. |

도시수비군은 장수 없는 NPC다. 평상시에는 `city_reserve`로 존재하고, 공격을 받으면 `GARRISON_UNIT`으로 전장에 올라온다. 장수 유닛과 달리 퇴각 판단, 사기, 충원은 도시 정책과 시설, 태수 AI가 담당한다.

중앙 예비군은 "어디에나 즉시 나타나는 병력"이 아니다. 보급로와 이동 시간이 있어야 하고, 도독부 자율성이 높으면 중앙이 지방 예비군을 직접 빼내기 어렵다. 이 제약이 봉건제의 핵심 긴장이다.

## 6. 핵심 게임 루프

### 6.1 1분 루프

1. 현재 도시/부대/장수 상태 확인.
2. 다음 장수 턴 명령 입력.
3. 가신 제안 또는 경고 확인.
4. 필요한 경우 전투/내정/이동 명령 수정.
5. 실시간 로그와 정세 변화를 관찰.

### 6.2 하루 루프

1. 전선 상황 확인.
2. 가신/추종/봉신에게 임무 배정.
3. 보급과 도시 건설 방향 조정.
4. 전쟁 replay 확인.
5. 회의실/어전회의에서 결정.

### 6.3 시즌 루프

1. 세력 확장 또는 독립 목표 설정.
2. 봉토 배분과 도독부 관리.
3. 외교 관계 재편.
4. 황제/왕/공 등 칭호와 정통성 경쟁.
5. 통일, 분열, 반란, 새 기수로 이어지는 장기 서사.

## 7. MVP 범위

처음부터 전체를 만들면 실패한다. v2 MVP는 "살아 있는 작은 전쟁과 작은 조정"을 목표로 한다.

### 7.1 MVP 월드

- 도시 20개.
- 세력 3개.
- 장수 50명.
- 플레이어 1명 + 추종 1명 + 가신 1명.
- 도독부 1개.
- 봉토 1개.
- 전쟁 replay가 남는 공격 1종.

### 7.2 MVP에서 반드시 보여줘야 하는 장면

1. 플레이어가 참모 가신에게 전쟁 제안을 받는다.
2. 어전회의에서 군수관은 반대하고, 참모는 찬성한다.
3. 플레이어가 공격을 승인한다.
4. 도독부/봉신이 원군을 보낼지 결정한다.
5. 전쟁이 접근, 요격, 공성, 전후 처리 replay로 남는다.
6. 결과에 따라 가신 신뢰, 봉신 충성, 도시 민심이 변한다.

## 8. 시스템 설계 초안

### 8.1 시간

`상순/중순/하순`은 v2에서 새로 넣는 시간 표현이다. 레거시 PHP의 byte 패러티를 고치는 항목이 아니라, samnet 공개 표면과 삼모 문법을 흡수해 v2 월드 날짜를 더 읽기 쉽게 만드는 제품 개념이다. v2에서는 두 개의 cadence를 분리한다.

| 레이어 | 목적 |
|---|---|
| simulation tick | 서버가 큐, 지연 효과, 실시간 이벤트를 평가하는 짧은 내부 틱 |
| general turn | 장수가 명령 1개를 실행할 수 있는 개인별 주기 |
| game date | 모든 유저가 보는 세계 날짜. 1개월 3순 |

명령 실행 주기와 날짜 표현을 분리해야 전투 replay, 가신 제안, 봉신 지연 같은 긴 사건을 자연스럽게 표현할 수 있다.

### 8.2 데이터 모델 초안

초기 테이블 후보:

- `battle_replays`
- `battle_replay_phases`
- `battle_participants`
- `general_followers`
- `general_retainers`
- `retainer_interactions`
- `retainer_proposals`
- `retainer_assignments`
- `court_councils`
- `council_opinions`
- `bias_profiles`
- `subfactions`
- `fiefs`
- `feudal_contracts`
- `subfaction_orders`
- `force_pools`
- `city_garrisons`
- `battle_units`
- `battle_unit_orders`

이 테이블들은 바로 모두 구현하지 않는다. 먼저 replay schema, retainer proposal, fief contract의 최소 열만 만든다.

### 7.3 결정성

v2의 모든 자동 판단은 replay 가능해야 한다.

- RNG seed는 사건 단위로 기록한다.
- 가신 제안은 근거 score를 JSON으로 남긴다.
- 회의 의견은 bias factor를 남긴다.
- 전쟁 replay는 phase별 입력/결과를 남긴다.

나중에 UI가 좋아져도 "왜 이런 결과가 나왔는지"를 서버 로그와 replay로 재구성할 수 있어야 한다.

## 9. UI 기획

### 9.1 첫 화면

랜딩이 아니라 바로 게임 상태를 보여준다.

- 현재 날짜: `218년 12월 중순`.
- 지도: 3D가 기본, 모바일/저사양은 2D.
- 최근 정세.
- 최근 전쟁 replay.
- 내 장수 카드.
- 다음 턴 명령.
- 가신 제안.

### 9.2 전쟁 화면

전쟁은 결과 텍스트 한 줄이 아니라 timeline이다.

- 1단계: 출병 명령과 동원 병력.
- 2단계: 접근 경로와 정찰 정보.
- 3단계: 요격 여부.
- 4단계: 야전/공성/시가전 phase.
- 5단계: 피해, 전공, 포로, 창고, 민심 변화.

### 9.3 가신 화면

가신 UI는 캐릭터 카드 + 관계 + 현재 임무 + 제안함으로 구성한다.

- 카드: 이름, 유형, 충성, 신뢰, 야망, 기질.
- 상호작용: 칭찬, 포상, 질책, 상담, 임무부여, 해임.
- 제안함: 근거, 예상 효과, 반대 의견, 기한.
- 기록: 지난 제안이 맞았는지 틀렸는지.

### 9.4 어전회의 화면

회의는 카드형 찬반 UI가 아니라 "논쟁 표"가 좋다.

| 인물 | 입장 | 확신 | 주요 근거 | 숨은 편향 |
|---|---|---|---|---|
| 참모 | 찬성 | 72 | 적 요격 공백 | 전공 욕구 |
| 군수관 | 반대 | 81 | 보급 2순 부족 | 손실 회피 |
| 사신 | 보류 | 58 | 휴전 가능성 | 외교 선호 |

플레이어는 승인, 보류, 수정안, 거부 중 하나를 선택한다.

## 10. 구현 로드맵

### Phase V2-0 — 문서와 증거 고정

목표: v2가 감으로 커지지 않게 근거와 비목표를 고정한다.

Deliverables:

- myosam 37페이지를 위키 페이지로 컴파일.
- samnet 공개 화면 feature snapshot 작성.
- v2 ERD 초안 작성.
- v1 패러티와 v2 확장 브랜치 분리 원칙 문서화.

Exit:

- `docs/wiki/pages/refs/myosam-help-corpus.md` 갱신.
- v2 schema spike 문서 존재.

### Phase V2-1 — 전쟁 replay spine

목표: 수치가 단순해도 전쟁이 단계별 replay로 남게 한다.

Deliverables:

- `battle_replays`, `battle_replay_phases` schema.
- 하나의 공격 명령이 replay를 생성.
- phase: `approach`, `encounter`, `field`, `siege`, `aftermath`.
- UI에서 replay timeline read-only 렌더.

Exit:

- 같은 seed로 같은 replay JSON 생성.
- 전쟁 결과 로그와 replay가 연결됨.

### Phase V2-2 — 가신 1명 vertical slice

목표: 참모 가신이 제안하고, 플레이어가 승인/거부한다.

Deliverables:

- `general_retainers`, `retainer_proposals`, `retainer_interactions`.
- 참모 가신 1명 자동 생성 또는 영입.
- 전쟁/내정/외교 제안 중 1종 생성.
- 제안 승인 시 실제 명령 큐 또는 정책으로 연결.

Exit:

- 가신 제안 근거 score가 저장됨.
- 승인/거부가 신뢰/충성에 영향을 줌.

### Phase V2-3 — 어전회의

목표: 하나의 의제를 여러 인물이 편향을 가지고 논쟁한다.

Deliverables:

- `court_councils`, `council_opinions`, `bias_profiles`.
- 선전포고 의제 1종.
- 참모/군수관/사신 의견 생성.
- 플레이어 결정 또는 NPC ruler AI 결정.

Exit:

- 같은 월드 상태와 seed에서 같은 의견/결정 재현.
- UI에서 편향과 근거가 보임.

### Phase V2-4 — 봉토와 도독부

목표: 세력 안에 중앙과 지방의 긴장을 만든다.

Deliverables:

- `subfactions`, `fiefs`, `feudal_contracts`.
- 도시 1개를 봉토로 부여.
- 봉신이 세금/징병 일부를 중앙에 납부.
- 중앙 원군 명령을 수락/지연/축소 중 하나로 처리.

Exit:

- 봉신 충성/자율성이 명령 지연에 영향을 줌.
- 봉토 회수 또는 보상 상호작용이 가능.

### Phase V2-5 — 동적 전쟁 첫 완성

목표: 전쟁 replay와 가신/봉신/회의가 한 흐름에서 만난다.

Scenario:

1. 참모가 적 요격 공백을 제안.
2. 어전회의에서 군수관이 보급 부족으로 반대.
3. 플레이어가 공격 승인.
4. 봉신이 원군을 늦게 보냄.
5. 전투 replay에서 접근 지연과 공성 손실이 발생.
6. 전후에 참모 신뢰와 봉신 충성이 변함.

Exit:

- 이 흐름이 테스트 fixture와 UI 수동 QA로 재현됨.

## 11. 우선순위

1. replay schema.
2. 가신 proposal schema.
3. court council schema.
4. fief/feudal contract schema.
5. UI timeline.
6. 3D 지도.

3D 지도는 멋있지만 핵심 재미의 원인은 아니다. 먼저 "세계가 사건을 기억하고 NPC가 의견을 낸다"를 만들어야 한다.

## 12. 비목표

- samnet/myosam 화면 또는 자산을 그대로 복제하지 않는다.
- v1 패러티 goldens를 v2 편의에 맞춰 바꾸지 않는다.
- 런타임 LLM으로 가신을 말하게 하지 않는다.
- 처음부터 전체 삼국지 지도를 만들지 않는다.
- 첫 MVP에서 모든 병종/건물/관직을 구현하지 않는다.

## 13. 첫 번째 실행 과제

바로 다음 작업은 코딩이 아니라 schema spike다.

1. `docs/superpowers/specs/2026-06-28-v2-domain-schema-spike.md` 작성.
2. 전쟁 replay, 가신 proposal, 어전회의, 봉건 계약 ERD를 확정.
3. 각 시스템별 "첫 vertical slice" 테스트 시나리오 1개씩 작성.
4. 그 다음에 `battle_replays`부터 migration을 시작한다.

이 순서를 지키면 v2가 "좋은 아이디어 잔뜩"으로 퍼지지 않고, 실제로 플레이 가능한 첫 장면까지 갈 수 있다.
