## 1. 재는 법

城마다 `lon/lat` 을 han-tiles 축으로 투영한다(`materialize_frontier_counties.project_cell` 과 같은 식, 칸 색인은 내림). 이것이 **실제 칸**이다. 좌표계는 han-tiles `col/row` 하나만 쓴다(HanCityConst x/y 는 쓰지 않는다 — 축마다 배율이 다르다, `build_han_world.py:590`).

| 지표 | 뜻 |
|---|---|
| `nearestCell` | 실제 칸 → 제 省에서 가장 가까운 칸. 0 = 城이 제 땅 안 |
| `centroidOffset` | 실제 칸 → 제 省 무게중심 |
| `seedOffset` | 실제 칸 → `cities[].col,row`(씨앗). 씨앗은 省 기하가 아니다 — 따로 잰다 |
| `centroidOverRadius` | 무게중심 밀림 ÷ 같은 넓이 원의 반지름 (이웃 대비 상대 척도) |

이슈 제목의 「10–17칸」은 무게중심 기준에 가깝다(鄴 11.5 · 安邑 10.7 · 始平(會稽) 17.9). `nearestCell` 로는 鄴 7.8 · 始平(右扶風) 6.0 · 安邑 5.4 · 元氏 3.6 이다. 둘 다 적는다.

### 지형: 실제 칸 vs 省 칸

- 실제 칸이 PLAIN/BASIN 인데 제 省에는 PLAIN+BASIN 이 **0칸**인 城 = **24곳, 전부 밀린 곳이다**(안 밀린 城 중에는 0건). 鄴·元氏가 여기 든다. 魏郡 4(鄴·梁期·曲梁·斥丘) · 京兆尹 4(鄭·杜·新豐·杜陵) · 河內 3(山陽·蕩陰·共) · 常山 2(元氏·房子) · 豫章 3 · 蜀郡 1(郫) · 隴西 1(襄武) · 廬江·代·江夏·中山·左馮翊·趙國 각 1.
- 安邑(실제 칸 PLATEAU)·始平 70715(MOUNTAIN)은 실제 칸 자체가 저지가 아니다 — 省을 제자리로 옮겨도 NE 폴리곤 지형 분류(#798 원장 밖)가 남는다. **이 둘은 기하 수리만으로 닫히지 않는다.** 별개 축으로 적는다.
- 밀린 494곳 중 실제 칸과 씨앗 칸의 지형이 다른 경우 상위: PLAIN→MOUNTAIN 38 · RIVER→PLAIN 16 · MOUNTAIN→PLAIN 8 · PLAIN→RIVER 7.
- PLAIN+BASIN 0칸 省(城 있는 것)은 전체 178곳. 그중 위 24곳만 이 결함 탓이고 나머지는 실제 산지·고원·사막이거나 지형 분류 문제다.

## 3. 어느 단계가 옮겼나 (코드 + git 이력 실측)

같은 계측을 과거 커밋의 han-tiles 에 돌렸다(城 있는 省 998 기준):

| 커밋 | 날짜 | 실제 칸 ∈ 제 省 | seedOffset p90 | 鄴 씨앗 |
|---|---|---|---|---|
| `d8fcc07d` (직전) | 08-30 | **964 / 998** | 0.0 | (410,200) |
| `a1162a0e` feat(map): regularize playable province geometry | 08-31 | **414 / 998** | 0.0 | (410,200) |
| `f98cb089` feat(scenario): audit commandery ownership gaps | 09-01 | 516 / 998 | **13.0** | (403,193) |
| `f6c65515` 이후 ~ HEAD | | 516→637 / 1,131 | 12.8 | (403,193) |

두 단계다.

1. **`a1162a0e` — owner 가 城에서 떨어져 나갔다.** `world_province_geometry.rebalance_province_areas` 가 「순서 의존 fallback merge」를 `province_quality.balanced_parent_labels`(郡 안 등넓이 분할)로 바꿨다. 縣을 덩어리에 짝짓는 비용이 `np.max(...)`(덩어리의 가장 먼 칸까지 거리)의 병목 매칭이라, 縣이 몰린 郡에서는 縣이 먼 덩어리를 받는다. 이 시점에 씨앗은 아직 실제 위치에 있었다 — 즉 **城 아이콘은 제자리, 땅만 딴 곳**이었다(964 → 414).
2. **`f98cb089` — 씨앗을 땅 쪽으로 끌고 갔다.** `rebalance_han_tiles.adapt_historical_city_seeds`(이 커밋에서 신설, 129줄)가 郡을 다시 등넓이로 나눠 병목 매칭한 뒤 `city["row"], city["col"]` 을 배정받은 덩어리의 가장 가까운 칸으로 덮어쓴다. `lon/lat` 은 그대로 둔다. 鄴이 (410,200) → (403,193) 으로, 평원에서 太行 쪽 MOUNTAIN 칸으로 간 것이 이 줄이다. `geometryBasis: HISTORICAL_SEAT_ADAPTED` 1,046省 중 481이 밀려 있다(STRATEGIC_SITE_LOCAL_CARVE 73 중 10, SOURCE_ATTESTED… 4 중 3).

`f6c65515` 는 그 뒤 郡 인접을 옮겨진 씨앗에 맞췄을 뿐이다. 이후 단계(조각 판정·劇 이전·재결속·변경 51縣·거점 분할·접기·저지 지형)는 이 바탕 위에 델타로 쌓였고 밀림을 만들지 않았다(516 → 637 로 오히려 늘었다).

버그가 아니다. `province_quality` 의 넓이 균형 정책과 지리 충실도의 맞바꿈이고, 사용자가 2026-09-17 에 뒤집은 것이 이 정책이다.

## 4. 수리안 — 국소 델타 단계, 전체 재생성 금지

`han-tiles.json` 은 판정 8건이 얹힌 정본이라 `build_tile_grid.py`/`rebalance_han_tiles.py` 로 다시 굽지 않는다. gitignored 원본(terrain-grid·han-places)도 쓰지 않는다. 수리는 **커밋본을 입력으로 받아 郡 단위 칸 델타를 내는 새 사슬 단계 ★ `partition_counties_by_location`** 이다(spec §3·§4). 「국소」의 단위는 省이 아니라 郡이다 — 한 郡 안 縣 경계는 서로 맞물려 있어 省 하나만 옮길 수 없다(鄴을 옮기면 內黃이 밀린다).

불변: `parentOwner`(郡 경계), 郡·縣·城 id, `lon/lat`, terrain, 앞 네 단계의 원장과 지문.
바뀜: `owner`, `provinceRecords`(城 없는 省의 id·수), `cities[].col,row`, `adjacency`, `_meta.counts`.

### 단계

- **S0 계측·게이트 (이 PR 이 절반)** — `measure_province_seat_offset.py` 를 기준선으로 둔다(637/651/1,106 고정 테스트 포함). 남은 것: Q1 게이트를 `--check` 로 배선, 씨앗 충돌 원장 `county-seed-collisions-v1` 초안(같은 칸 14칸·28城), spec 브랜치를 main 에 올린다.
- **S1 분할기 (scratch 산출, han-tiles 무변경)** — spec 규칙 0–7. 郡 마스크 안 8-이웃 10/14 다익스트라 최근접 배정, `min_area` 8 미만 보충, `max_area` 620 초과 縣의 縣 안 재분할, 대리 治所 17관할 씨앗 유지. 산출은 scratch 디렉터리. 이 계측 도구로 before/after 를 낸다.
- **S1.5 건식 실행 — 사용자 확인 중단점.** scratch 산출 위에서 carve·fold·lowland `--prepare`, 영토 단절 감사·조각 판정·부모 재조정·귀속·소유·보급선을 돌려 죽는 도구·재심사 행 수·`DONOR_TOO_SMALL` 수·바뀌는 connections 수를 전수로 센다. 변경 광역 省 입도(居延 28 → 약 11)도 여기서 확인받는다.
- **S2 ★ 단계 커밋** — 결정 원장 + 산출 원장(`geometry.stages` 입출력 지문, 입력 owner·省 행을 gz blob 으로 핀) + `peel()/reapply()/--check` + CI 단계. 앞 단계 도구·감사 도구 3개의 peel 순서에 ★ 를 끼운다. 그 뒤 거점 73 분할 → 접기 → 저지 지형을 새 바탕에 `--prepare` 로 다시 굽는다. 단계마다 `--check` 초록이어야 다음으로 간다.
- **S3 재심사** — 영토 단절 원장 119행(componentKey·cellCount 전부 바뀜, 자동 승계 금지), 접기 `territoryAdjudications` 4행, 시나리오 DIRECT id 큐레이션 7행, 郡 보급선 74개 재측정(기준선: scenario_1020 절단 102).
- **S4 핀 사슬 재생성** — 아래 §5 순서.
- **S5 문서·릴리스** — ADR-LITE-059(1133 README 의 「경계가 바뀌면 새 식별자」 문언 개정 — 리졸버가 city id 집합으로 고르므로 새 식별자는 불가능, 제자리 재핀), 운영 리셋 절차, 독립 교차 비평 cleared, PR. **월드 리셋 필수**(省 id·인덱스가 바뀐다).

### 이 수리로 안 닫히는 것 (별개 이슈로 남긴다)
