# 오픈삼국 v2 출시 구현 계획

> 작성일: 2026-06-29
> 상태: execution-plan
> 기준: `docs/superpowers/plans/2026-06-28-opensamguk-v2-game-design-plan.md`, `docs/superpowers/research/2026-06-27-v2-samnet-myosam-gap-design.md`, samnet 매뉴얼 전체 5페이지, myosam 도움말 37페이지

## 1. 제품 기준

v2는 v1 패러티를 지우는 재작성판이 아니다. v1의 운영 가능한 로그인, 로비, 지도, 장수, 국가, 도시, 예약턴, 상/중/하순, 로그 표면을 유지한 채, 다음 네 가지를 출시 차별점으로 얹는다.

1. 현재 조작 대상 중심 UI.
2. 가신/추종/부곡을 포함한 다중 주체 커맨드.
3. 대규모 침공, 협공, 요격, 농성, 공성으로 이어지는 동적 전쟁.
4. 부세력, 봉토, 도독부, 중앙 명령 지연을 포함한 봉건 정치.

samnet은 현재 운영 감각과 카드/연계/전투/시야/인접 진군 매뉴얼의 모티브로 사용한다. myosam은 예약턴, 관직, 부대, 요격/농성/공성, 건설/장애물, NPC 관리의 룰 근거로 사용한다. 어느 쪽도 화면, 자산, 수치, 명칭을 그대로 복제하지 않는다.

## 2. 확인한 외부 근거

### 2.1 samnet 매뉴얼

확인 페이지:

- `https://www.samnet.kr/manuals/index.html`
- `https://www.samnet.kr/manuals/general.html`
- `https://www.samnet.kr/manuals/skill.html`
- `https://www.samnet.kr/manuals/synergy.html`
- `https://www.samnet.kr/manuals/battle.html`

확인 항목:

- 기본 매뉴얼: 게임 개요, 캐릭터/장수 카드, 인재 수색, 명령 대기열, 전투 유형, 성/내정, 거래소, 국가/관직, 지도/시야/인접 진군, 정탐, 순위, 초보 전략.
- 장수 목록: JS 데이터 기준 장수 카드 680명.
- 특기 목록: JS 데이터 기준 191개 항목. 페이지 설명의 "163종"과 데이터 수가 어긋나므로 수치 자체는 정본으로 쓰지 않는다.
- 연계 목록: JS 데이터 기준 연계 178종.
- 전투 공식: 요격전/농성전/공성전, 50라운드, 공격/방어/훈련도/병력손실/크리티컬/2연속/피해무시, 33병종, 5계열 상성, 지형, 함정, 내정/징병/정탐 공식.

v2 흡수 방향:

- 한 계정 또는 플레이어가 여러 장수/카드를 운용하는 감각을 "조작 대상"으로 흡수한다.
- 명령 대기열은 대상별 큐로 확장한다.
- 연계는 그대로 복제하지 않고 "같은 작전/같은 전장에 참여한 장수 조합 보정"으로 해석한다.
- 33병종과 세부 수치는 가져오지 않고, 병종 계열/지형/함정/요격/공성/농성 구조만 흡수한다.

### 2.2 myosam 도움말

확인 상태:

- `docs/wiki/raw/myosam-help/MANIFEST.md` 기준 37페이지 수집 완료, 실패 0.

핵심 근거:

- 예약턴 입력과 명령 큐.
- 국가 소속, 관직, 지휘부, 태수, 군주 역할.
- 도시 정보, 장수 정보, 감찰부.
- 기본 내정, 효율 내정, 건설, 시설, 장애물.
- 전쟁 기본, 효율 전쟁, 야전/요격전, 농성전, 공성전.
- 부대 사용, 집합, 동시 행동.
- NPC 행동과 제한.

v2 흡수 방향:

- "협공"이라는 단어 자체는 myosam 원문에서 직접 근거가 약하지만, 부대/집합/동시/요격/농성/공성 구조가 협공 시스템의 룰 재료다.
- NPC는 자동 장수의 근거로 쓰고, v2에서는 추종과 가신으로 나누어 확장한다.
- 관직과 지휘부는 도독부/봉토/부세력 명령권의 근거로 쓴다.

## 3. 핵심 도메인 결정

### 3.1 조작 대상

메인 화면의 기본 문맥은 맵 선택 도시가 아니라 현재 조작 대상이다.

초기 대상:

- 본인 장수 1명.

v2 확장 대상:

- 본인 장수.
- 추종 장수.
- 가신.
- 부곡 지휘 단위.
- 도독부/봉토 권한이 부여된 대리 주체.

UI 규칙:

- 현재 유저가 머무는 도시, 현재 유저가 속한 국가, 현재 유저 장수 표시는 유지한다.
- 선택 대상이 바뀌어도 "내 현재 위치/국가/본인"은 사라지지 않는다.
- 선택 대상 패널은 커맨드 예약 주체를 바꾼다.
- 맵 클릭은 탐색/정보 보기이고, 기본 상태 패널을 영구 대체하지 않는다.

### 3.2 커맨드 주체

커맨드는 사용자 계정에 직접 붙지 않고 실행 주체에 붙는다.

기본 모델:

- `command_subject_type`: `GENERAL`, `FOLLOWER`, `RETAINER`, `BUGOK`, `SUBFACTION`.
- `command_subject_id`: 대상별 id.
- `ordered_by_general_id`: 실제 명령을 내린 유저 장수.
- `execution_owner_general_id`: 실행 결과 책임 장수.
- `queue_scope`: 개인 큐, 작전 큐, 국가 큐 중 하나.

출시 1차에서는 기존 `general_turn`을 본인 장수 큐로 유지하고, 대상 선택 UI와 API 계약을 먼저 추가한다. 추종/가신/부곡 큐는 이후 별도 테이블로 확장한다.

### 3.3 부곡

장수의 병사는 단순 숫자가 아니라 `부곡`이다. 부곡은 장수 개인에게 충성하는 병력 집단이며, 장수와 떨어져 있을 수 있다.

규칙:

- 장수는 여러 부곡을 보유할 수 있다.
- 부곡은 현재 위치, 병종, 병력, 훈련도, 사기, 보급, 지휘 장수, 소속 장수를 가진다.
- 부곡은 주인 장수와 같은 도시에 있을 수도 있고, 전선/도시/봉토에 따로 주둔할 수도 있다.
- 장수가 이동해도 부곡이 자동으로 모두 따라가지 않는다. 동행, 주둔, 합류, 파견 명령으로 분리한다.
- 전투에 참가하는 실체는 장수 + 부곡 또는 부곡 단독 주둔군이다.

필수 테이블 후보:

- `general_bugok`
- `bugok_orders`
- `bugok_movements`
- `bugok_supply_state`
- `operation_bugok_assignments`

### 3.4 작전

대규모 침공과 협공은 개별 `출병` 여러 개가 우연히 같은 시점에 도착하는 것이 아니라 `작전`으로 묶는다.

작전 구성:

- 목표 도시.
- 시작 시각 또는 목표 도착 순.
- 주공, 조공, 별동대, 보급대, 예비대.
- 참여 장수, 추종 장수, 부곡, 도독부 원군.
- 경로와 집결지.
- 협공 조건: 같은 phase window에 같은 전장 또는 인접 전장에 도달.

작전 결과:

- 접근.
- 정찰/은폐.
- 요격 또는 회피.
- 야전.
- 농성/공성.
- 시가전.
- 전후 처리.
- replay/log 연결.

필수 테이블 후보:

- `operations`
- `operation_participants`
- `operation_routes`
- `operation_events`
- `battle_replays`
- `battle_replay_phases`

### 3.5 역사 고증

고증은 "정확한 역사 재현 강제"가 아니라 선택 가능한 제약과 확률 보정이다.

규칙:

- 시나리오는 실제 연도와 세력, 지리, 대표 장수 배치를 가진다.
- 장수의 출신, 친소 관계, 원한, 관직 적성, 병종 선호를 기록한다.
- 비역사적 선택은 가능하되 관계, 명분, 충성, 민심 비용을 낸다.
- 연계/협공 보정은 역사적 관계를 근거로 하되 과도한 고정 보너스로 만들지 않는다.

필수 데이터 후보:

- `historical_profiles`
- `general_relationships`
- `scenario_placement_rules`
- `legitimacy_events`

## 4. 출시 구현 순서

### V2-P0: v1 운영 안정화

목표: v2 기능을 얹기 전에 현재 운영면의 모순을 닫는다.

작업:

1. 서버/컨테이너 시간대를 `Asia/Seoul`로 고정한다.
2. `ServerClock`의 UTC anchor와 KST 표기 요구를 분리하거나, v2 clock에는 명시적 zone을 둔다.
3. 로그인/로비/메인/정보/로그 전부 월과 순을 표시한다.
4. 상/중/하순으로 인해 월 이벤트가 3회 실행되는 문제를 월 경계 이벤트와 순 이벤트로 분리한다.
5. 메인 UI는 현재 장수 도시를 기본으로 보여주고, 맵 선택 도시는 보조 탐색으로 둔다.
6. 징병/모병 UI는 가능한 병과만 기본 노출하고, 전체 보기 토글을 둔다.
7. 명령 예약, 서신, 견문이 예약표에 들어가고 결과가 보이도록 e2e로 잠근다.
8. 3D foundation proof를 추가한다: 도시 3개, route 2개, terrain patch 1개, formation 4개를 같은 world coordinate로 렌더하고 picking 계약을 고정한다.
9. 임관 전후 e2e를 추가한다: 소속·봉록·현재 도시·국정 메뉴·개인 로그가 같은 임관 사건을 반영하고, 관직·부대 역할에 따라 명령 capability가 달라지는지 검증한다.
10. 명령 활성 조건을 `actor capability`, `선택 장수`, `선택 queue slot`, `server candidate set`으로 분리하고 각 거부 사유를 API 응답과 UI에 동일하게 노출한다.

검증:

- production `health`, `/game/s1`.
- 로그인 -> 게임 진입 -> 명령 예약 -> 표 반영 -> 데몬 소비 -> 결과 로그.
- `web/game` typecheck/build.
- backend command lifecycle focused tests.
- 데스크톱/모바일 canvas nonblank, picking, camera framing, context-loss recovery, FPS telemetry.
- 임관 직후와 재접속 후 모두 소속·도시·봉록·국가 채널·개인 로그가 한 사건 id를 가리키는지 확인한다.
- capability fixture는 일반 장수의 회의실/등용장/부대 창설 진입 허용, 관직 임명 거부, 부대장 전용 집합 거부를 고정한다.

### V2-P1: 조작 대상 패널과 대상별 커맨드 기반

목표: 가신/추종/부곡이 들어오기 전에도 화면과 API가 "대상별 명령"을 감당하게 한다.

작업:

1. 메인 상단에 `조작 대상` 영역을 추가한다.
2. 기본 대상은 본인 장수다.
3. 도시/국가/장수 카드를 하나의 `현재 대상 상태 패널`로 통합하고 3D picking 결과와 연결한다.
4. 커맨드 모달은 선택 대상 id/type을 포함한 내부 모델로 열린다.
5. 서버가 권한·외교·인접성·보급을 평가한 목적지 후보 API를 만들고, 3D scene과 텍스트 목록이 같은 candidate id 집합을 소비하게 한다.
6. 현재 백엔드가 지원하지 않는 대상은 비활성 상태로 노출하지 않는다.
7. 추후 가신 선택 공간은 같은 대상 selector에 흡수한다.

검증:

- 본인 장수 선택 상태에서 기존 커맨드 예약이 그대로 동작한다.
- 3D 지도에서 도시를 선택하면 inspect/focus만 바뀌고, 명령을 고른 뒤에만 그 선택을 목적지 초안으로 승격한다.
- 일반 장수, 부대장, 참모의 capability fixture에서 집합·등용·관직·전투 후보가 권한대로 달라진다.
- queue slot 미선택과 actor 권한 부족은 서로 다른 reason code를 반환하며, slot 선택만으로 권한 제한 명령이 활성화되지 않는다.
- 화면이 36턴 예약표와 함께 모바일/데스크톱에서 깨지지 않는다.

### V2-P2: 부곡 foundation

목표: 장수 병력을 분리 가능한 병력 집단으로 바꿀 준비를 한다.

작업:

1. `general_bugok` schema spike와 migration.
2. 기존 장수 병력은 기본 부곡 1개로 materialize한다.
3. 부곡 위치, 병종, 병력, 훈련도, 사기, 보급을 read API에 노출한다.
4. UI에 부곡 탭을 추가한다.
5. 명령은 아직 기존 장수 병력 값을 사용하되, read 모델은 부곡을 병행한다.

검증:

- 기존 전투/징병 결과가 깨지지 않는다.
- 장수 병력과 기본 부곡 병력이 일치한다.
- 장수와 부곡의 위치가 분리 가능한 테스트 fixture가 존재한다.

### V2-P3: 작전과 협공

목표: 떼로 침공하고, 협공하고, 원군이 지연되는 전쟁 뼈대를 만든다.

작업:

1. `operations`, `operation_participants`, `operation_routes`를 추가한다.
2. 작전 생성 UI: 목표 도시, 참여 대상, 경로, 도착 순을 선택한다.
3. 기존 `출병`은 단독 작전 1개로 감싼다.
4. 여러 장수/부곡이 같은 작전에 들어가면 협공 판정을 만든다.
5. 도착 window, 경로 충돌, 인접 도시 동시 압박을 계산한다.
6. 협공 성공/실패를 replay phase에 남긴다.
7. `operation_routes`를 3D route corridor로 표시하고 집결·교전 anchor를 전술 전장 seed에 전달한다.

검증:

- 같은 seed와 같은 작전 입력에서 같은 replay.
- 단독 출병, 2부대 협공, 원군 지연 세 fixture.
- 협공 로그가 월/순과 함께 남는다.

### V2-P4: 동적 전쟁 replay

목표: 전쟁이 결과표가 아니라 사건으로 남는다.

작업:

1. `battle_replays`, `battle_replay_phases` 추가.
2. phase: `approach`, `scout`, `intercept`, `field`, `siege`, `urban`, `aftermath`.
3. 요격/농성/공성/지형/함정/부곡 보급을 phase input으로 기록한다.
4. UI timeline을 read-only로 구현한다.
5. 기존 정세 로그와 replay를 연결한다.
6. replay가 동일 terrain/spatial snapshot을 재구성하고 정사영 지휘 카메라 keyframe을 선택적으로 재생한다.

검증:

- 전투 발생 후 replay 조회 가능.
- phase별 근거 JSON 저장.
- 월/순 로그와 replay timestamp가 일치.

### V2-P5: 가신 1명 vertical slice

목표: 참모 가신 1명이 제안하고, 플레이어가 승인/거부한다.

작업:

1. `general_retainers`, `retainer_proposals`, `retainer_interactions` 추가.
2. 본인 장수에게 참모 가신 1명 생성.
3. 가신은 전쟁/내정/외교 중 1개 제안을 rule score로 생성한다.
4. 제안은 조작 대상 패널의 가신 슬롯에 표시한다.
5. 승인 시 작전 초안 또는 커맨드 예약으로 연결한다.
6. 거부 시 신뢰/충성/냉각시간이 변한다.

검증:

- 런타임 LLM 호출 없음.
- 같은 world state와 seed에서 같은 제안.
- 승인/거부 결과가 저장되고 UI에서 보임.

### V2-P6: 어전회의와 편견

목표: 제안이 곧 정답이 아니라 논쟁의 출발점이 되게 한다.

작업:

1. `court_councils`, `council_opinions`, `bias_profiles` 추가.
2. 선전포고/대규모 침공 의제 1종.
3. 참모, 군수관, 사신, 도독부 대표 의견 생성.
4. 찬성/반대/보류, 확신, 근거, 편향을 저장한다.
5. 플레이어 결정이 작전/명령 큐로 변환된다.

검증:

- 같은 seed에서 같은 의견과 결론.
- 편향 요인이 UI에 보임.
- 결정 후 실제 작전 초안이 생성됨.

### V2-P7: 도독부, 봉토, 부세력

목표: 국가가 단일 자원 덩어리가 아니라 중앙과 지방으로 나뉜다.

작업:

1. `subfactions`, `fiefs`, `feudal_contracts` 추가.
2. 도시 1개를 봉토로 부여한다.
3. 봉토는 세금/징병/부곡 일부를 보유한다.
4. 중앙 원군 요청을 수락/지연/축소하는 룰을 만든다.
5. 봉신 충성/자율성이 작전 결과에 반영된다.

검증:

- 봉토 수입 일부가 중앙에 납부된다.
- 원군 요청 결과가 replay에 남는다.
- 봉토 회수/보상 상호작용이 가능하다.

### V2-P8: 출시 수직 슬라이스

목표: v2가 실제 플레이 가능한 한 장면으로 출시된다.

출시 시나리오:

1. 현재 장수로 접속한다.
2. 조작 대상 패널에서 본인 장수, 부곡, 가신 상태를 본다.
3. 참모 가신이 적 요격 공백을 제안한다.
4. 어전회의에서 군수관이 보급 부족으로 반대한다.
5. 플레이어가 대규모 침공 작전을 승인한다.
6. 부곡 2개와 추종 장수 1명이 작전에 편성된다.
7. 봉토 원군이 지연된다.
8. 접근, 정찰, 요격 실패, 공성, 전후 처리가 replay로 남는다.
9. 가신 신뢰, 봉신 충성, 도시 민심이 변한다.
10. 3D 전략 지도에서 선택한 route와 교전 anchor가 전술 전장과 replay에서 동일하게 보인다.

검증:

- 신규 계정 또는 known admin으로 production에서 수동 QA.
- 두 브라우저 세션에서 정세/로그 동기화.
- 전투 replay와 커맨드 결과 조회.
- 서버/컨테이너 시간 KST 표기.
- 월/순 로그 누락 없음.
- 3D 지도 로딩·도시 선택·작전 경로·전장 진입/이탈·formation 명령·replay 재생의 desktop/mobile 시각 gate.

## 6. 출시 보류 조건

- 명령 예약이 표에 반영되지 않거나 데몬 소비 결과를 볼 수 없으면 보류.
- 서신/견문 같은 커맨드 결과가 사용자에게 출력되지 않으면 보류.
- 월/순 로그가 누락되면 보류.
- 월 이벤트가 상/중/하순마다 3회 실행되면 보류.
- production에서 로그인 -> 게임 진입 -> 커맨드 예약 -> 결과 관측이 실패하면 보류.
- 가신 제안이나 회의 의견이 LLM 호출에 의존하면 보류.
- 작전/replay가 seed로 재현되지 않으면 보류.
