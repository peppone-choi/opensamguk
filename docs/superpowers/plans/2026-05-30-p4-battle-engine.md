## Resolved decisions (cited; freeze BEFORE the fan-out)

1. **`onCalcStat` value-type widening (consolidated OQ #3, Tier-0 blocker).** Current `GeneralActionModule.onCalcStat`/`onCalcOpposeStat` take a scalar `Double` (`ActionPipeline.kt:15/31`). `criticalDamageRange` is a `[min,max]` PAIR threaded through `onCalcStat` (che_필살 rewrites to `[(min+max)/2, max]`). **DECISION = ADD a parallel pair-typed hook `onCalcStatRange(general, statName, value: Pair<Double,Double>, aux): Pair<Double,Double>` (default identity) on the interface + a `GeneralActionPipeline.onCalcStatRange` fold** — do NOT widen the existing scalar signature to `Any` (would force a cast in every existing P2/P3 module and break the 1235 GREEN tests). The scalar war keys (warAvoidRatio/warCriticalRatio/warMagic*/bonusTrain/bonusAtmos/dex*/killRice/initWarPhase) keep the scalar hook; only `criticalDamageRange` uses the pair hook. Pin this in F4.
2. **`append()` is NOT ported (Unit 1).** The canonical battle path is `TriggerCaller` constructor + `merge()` (`General.php:920-934`); `append()` has a latent line-75 bucket-clobber bug, is unreachable in battle, and core2026 diverged it additive. Port constructor + merge + fire ONLY.
3. **Inner trigger map is INSERTION-ordered (`LinkedHashMap`), NEVER key-sorted (Unit 1).** Two triggers at the SAME priority (계략발동 & 계략실패, both POST+300=40300) must fire in constructor ARG order. Outer map sorted ASCENDING by int priority (`TreeMap` or sort-on-fire, stable).
4. **`uniqueID` tuple (Unit 1).** base `{priority}_{FQN}_{objID}`; `BaseWarUnitTrigger` appends `_{raiseType}` (raiseType coexistence: TYPE_ITEM=1 / TYPE_CONSUMABLE_ITEM=3 do NOT dedup against TYPE_NONE=0). PHP `objID`=`spl_object_id` is non-reproducible → use a STABLE per-unit id (`WarUnit.unitId`) + a stable class-name token; dedup keys on the `(priority, class, unit, raiseType)` tuple-string. TYPE_DEDUP_TYPE_BASE=1024.
5. **`Util::round` = half-away-from-zero (`PhpRound`); `Util::setRound` = the same half-away rounding applied in-place (the processWar() wrapper supply-rice decrement, `process_war.php:104`); damage loop clamp = `ceil()`; collapse gold/rice = `Util::toInt` truncate; reward halving = `intdiv` truncate; ConquerCity city-reset SQL `%d` int-cast (Units 3/4/5/6/7).** FIVE distinct rounding modes coexist in the war path. NEVER mix; NEVER stdlib `Math.round`/`kotlin.math.round`.
6. **PHP `arsort` tie-break for the conflict winner (consolidated OQ #4).** PHP 8.0+ made ALL sort functions (sort/asort/arsort/usort) UNCONDITIONALLY stable at every size (Stable sorting RFC; composer pins `php 8.3`) — they preserve insertion order on equal values regardless of count. (The old "≤16 = insertion sort" detail is the pre-8.0 zend_sort small-array threshold, IRRELEVANT to stability — do NOT add a non-stable secondary comparator above 16 nations.) core2026/V8 sort is also stable but JS Object re-keys integer-like keys ascending (WRONG). **DECISION = `ConflictMap` is a `LinkedHashMap<Int,Double>` sorted DESCENDING by value with insertion-order preserved on ties for ANY map size; read winner = first key. PIN against a 2-3-nation siege golden (A4/G1) before locking the comparator.**
7. **findNextCapital = PHP BFS-ring + max-pop over `CalcCityDistance`, NOT TS Euclidean (Unit 7).** Walk distance-rings outward; in the FIRST ring containing an owned city pick MAX pop. **On a pop TIE the LAST max-pop city in BFS ring-iteration order wins** — `process_war.php:833-837` does `if ($cityPop < $maxCityPop) continue; $minCity = $cityID; $maxCityPop = $cityPop;`, so on equality (`<` is false) it does NOT `continue` and OVERWRITES `$minCity` → the LAST city with the running max wins, NOT the first. (Earlier drafts said "first-max wins" — that is WRONG.)
8. **급습/선전포고 scope (consolidated OQ #13).** PHP proves these are strategic DIPLOMACY (no RNG, no processWar). **DECISION = route to P6, NOT P4.** P4 registers ONLY `che_출병` into `CommandRegistry`. **Design §11 P4 line 259 lists 거병 among the battle commands, but `che_거병` is the nation-FOUNDING command (Command/General, no processWar/WarUnit/RNG), already GREEN in P2 (`GeobyeongTest.kt` + `che_거병-fixtures.json`) — the SOLE true `processWar` caller is `che_출병` (verified). 급습/선전포고 are Command/Nation diplomacy with zero processWar → P6.** This is an intentional, verified divergence from the literal §11 line, not silent scope-cutting.
9. **WarUnitCity finishBattle wealth-decrement is DEAD CODE (Unit 5).** `isFinished` set true before the `if(isFinished||!onSiege) return` → the `killed/20` block never runs. Port faithfully as dead/unreachable; do NOT "fix" it.
