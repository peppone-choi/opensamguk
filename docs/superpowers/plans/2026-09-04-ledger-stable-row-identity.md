# 단절 원장 행에 안정 식별자를 준다

`data/curated/han/territory-disconnection-adjudications-v1.json` 의 행 id 는 위치 기반이었다.
후속 트랙(B1 재배속·G 형상수리)이 셀을 건드리는 순간 형제 행들이 서로의 조각으로 재라벨된다.
그 전에 이것부터 고친다.

## Task 1: 결함을 재현하는 실패 테스트

`componentKey` 는 `f"{unitId}#{rank}"` 였고, `rank` 는
`(-len(cells), min(cells))` 로 정렬한 목록의 인덱스다
(`tools/map/audit_territory_disconnections.py:171`). 즉 **다른 조각들의 함수**다.

합쳐진 실제 원장으로 재현했다. 鄡陽縣(41194) 을 豫章郡→鄱陽郡 으로 옮기면
(B1 이 실제로 제안하는 수정이다):

| 키 | 옮기기 전 | 옮긴 후 |
|---|---|---|
| `PARENT-0053#2` | 28셀, 鄡阳县 | 9셀, 40165 |
| `PARENT-0053#3` | 9셀, 40165 | 3셀, 41145 |
| `PARENT-0053#4` | 3셀, 41145 | (사라짐) |

건드리지도 않은 두 행의 의미가 바뀌었고, **없어진 것은 수리한 조각이 아니라 맨 끝 행**이다.
게이트는 CELL_DRIFT·MEMBER_DRIFT·NAME_DRIFT 로 빨개지지만, 사람이 그걸 보고 하는
자연스러운 수리 — 「행을 격자에 맞춘다」 — 는 40165 의 사료 근거를 41145 의 땅으로 옮긴다.
junguozhi note 캐스케이드와 같은 모양이다.

합성 픽스처(`_sibling_document`)로 같은 것을 3·2·1 셀 세 조각에 대해 못박았다.

## Task 2: 조각을 조각 자체로 식별한다

`componentKey = f"{unitId}@{col}:{row}"`, 좌표는 그 조각의 최상단·최좌측 셀
(`_anchor()`). 오직 **그 조각 자신의 셀만의 함수**다.

- 유일성은 구성상 보장된다 — 한 단위의 컴포넌트끼리는 서로소라 최소 셀을 공유할 수 없다.
  실측: 119 컴포넌트 → 119 키, 충돌 0.
- 형제가 바뀌어도 안 움직인다(위 재현 시나리오에서 재라벨 0건, 은퇴 1건 —
  그것도 **실제로 수리된 조각의 키**다).
- 내용이 바뀌면 기존 CELL_DRIFT/MEMBER_DRIFT/NAME_DRIFT 가 말한다. 식별과 내용을 분리한다.
- 사람이 확인할 수 있다 — col:row 를 지도에서 짚을 수 있다.

대안으로 셀 집합의 해시도 검토했으나 기각했다. 南郡 조각은 1,597 셀이고,
한 셀만 바뀌어도 사료 근거가 잔뜩 붙은 행이 통째로 은퇴한다. 지나치게 부서지기 쉽다.

`han-place-stable-id-adjudications-v1.json` 의 방식(CHGIS SYS_ID)은 재사용할 수 없다.
그건 *장소* 식별 문제고, 단절 조각은 사료에 대응물이 없는 순수 기하 객체다.

## Task 3: 119행 이관

이관표는 `_components()` 를 한 번 돌면서 **같은 cells 객체에서 두 키를 동시에** 계산해 만들었다.
내용으로 매칭하지 않았으므로 뒤바뀜이 구조적으로 불가능하다.

이게 중요한 이유: 게이트가 비교하는 모든 내용 필드가 동일해서
**내용으로는 구분할 수 없는 컴포넌트 쌍이 4개** 있다.

| 단위 | 縣 | 키 |
|---|---|---|
| PARENT-0116 / X046 | 古資彌凍國 (1셀) | `@643:236` · `@657:236` |
| PARENT-0165 / X052 | 末盧國 (1셀) | `@689:262` · `@693:279` |

이 4쌍에 대해서는 옛 방식의 손상이 **완전히 무성(無聲)** 이었다 — 어떤 드리프트 규칙도
못 잡는다. 이관이 이들을 올바로 옮겼음은 위 출처 검증으로 확인했다.

이관 결과: 119개 키 전부 1:1, 고아 0(양방향), 충돌 0, 산문 속 참조까지 전부 갱신.

## Task 4: 위치 기반 키가 되돌아오지 못하게

`COMPONENT_KEY` 정규식을 행 검증에 넣었다. 손으로 쓴 `PARENT-0053#2` 는 완벽하게
정상적인 문자열이라, 이 규칙이 없으면 격자 대조까지 가서 STALE_ROW 하나로 보고된다 —
**정당하게 수리되어 사라진 조각과 구분이 안 된다.** 그래서 문 앞에서 막는다.
